# 115 — Live-прототип

> Формат — см. [состав документов](documents-composition.md), документ 115.
> Экраны — [110 UI/UX](110.ui-ux.md). Прототип — [`../prototype/index.html`](../prototype/index.html).

## 1. Что это

Один файл `reports/prototype/index.html` без зависимостей и сборки. Открывается в браузере локально. Данные синтетические и согласованы с примерами историй [080](080.qa-lead-user-stories.md): например, pass rate 88,89% для прогона 40 / 5 / 3 / 2.

Прототип проверяет расположение элементов, навигацию, видимость по ролям и состояния экранов до начала разработки. Он не обращается к API и не проверяет права на сервере: в рабочей версии это делают API Reports и Superset.

## 2. Управление

| Элемент | Что делает |
| --- | --- |
| Меню в шапке | Переход между экранами; пункты, закрытые ролью, не показываются |
| «Роль» | Переключает RL-01…RL-06 и перестраивает каталог, меню и доступность детализации по [070](070.role-matrix.md) |
| «Состояние» | Показывает экран в состоянии: данные актуальны, данные устарели, загрузка, нет данных, ошибка |

## 3. Экраны

| Экран | В прототипе | Что проверить |
| --- | --- | --- |
| SCR-01 Каталог | Карточки R-01…R-11 по группам, контур, «Мои представления» | У RL-04 только его отчёты; у RL-06 каталога нет |
| SCR-02 Отчёт | Каждый из R-01…R-11 со своими данными: параметры, переключатель «Таблица / График», итоги, строки «не задано», перерасход и просрочка красным; у R-01 — смена разреза и детализация; у R-05, R-09, R-10, R-11 — сравнение с прошлым периодом | Смена разреза не сбрасывает параметры; у RL-04 — только свои часы; график дублируется таблицей |
| SCR-03 Детализация | Панель с крошками до дней и задач | Нажатие на сотрудника раскрывает дни |
| SCR-04 Оперативный дашборд | Плитки итерации, статусы, просроченные | Задача без исполнителя — «не задано» |
| SCR-05 План-факт | Плитки, неполный прогноз Planning System, сверочный прогноз, график | У RL-02 отклонение бюджета в часах, без денег |
| SCR-06 Качество | Pass rate, выполнение плана, defect density, reopened rate, график дефектов | Пояснение о недоступности разреза «релиз» |
| SCR-07 Куб | Срез «проект × месяц», выгрузка | Только RL-01 и RL-05 |
| SCR-08 Выгрузки | Задания во всех статусах жизненного цикла | `FAILED` — «Повторить», `EXPIRED` — «срок истёк» |
| SCR-09 Подписки | Форма и журнал доставок с пропущенным получателем | Права получателя проверяются при доставке |
| SCR-10 Актуальность | Потоки с лагом и порогом; у RL-06 — журнал пакетов и ручной запуск | В состоянии «данные устарели» поток Task Tracker — `STALE` |
| SCR-11 Уведомления | Готовность выгрузки, пропуск получателя | Переход к выгрузке |

## 4. Сценарии проверки

1. **Участник видит только себя.** Роль RL-04 → каталог → R-01 → в таблице одна строка; меню без «Куба» и «План-факта».
2. **Устаревшие данные.** Состояние «Данные устарели» → R-01: жёлтая строка с временем актуальности над результатом → «Актуальность»: Task Tracker в `STALE`.
3. **Drill-down.** RL-01 → R-01 → нажать на сотрудника → панель детализации по дням → «Итог» возвращает обратно.
4. **Неполный прогноз.** RL-01 → «План-факт»: плитка прогноза с пометкой `PARTIAL` и пояснение; RL-02 → бюджет в часах.
5. **Состояния.** Для любого экрана переключить «Загрузка», «Нет данных», «Ошибка».
6. **Таблица и график.** RL-03 → R-05 → «График»: открытые и закрытые по неделям → «Сравнить с прошлым периодом» → пояснение сравнения.
7. **Зависимость от договорённости.** R-09: под таблицей — пояснение, что разрез «релиз» недоступен (Q-REP-08).

Проверка прототипа: все экраны для шести ролей, пяти состояний и обоих режимов отрисовываются без ошибок — прогон скриптом с подменой DOM, 2 640 отрисовок.

## 5. Ограничения

- Графики упрощены: в рабочей версии их строит Superset или библиотека графиков веб-интерфейса.
- Параметры формы не меняют синтетические данные.
- Встраивание дашбордов Superset в веб-интерфейс Reports показано как обычные экраны.
