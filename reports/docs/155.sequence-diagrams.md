## SD-01. Приём события и применение к витрине

Связи: UC-13, US-EX-02, US-QA-01.

```mermaid
sequenceDiagram
    participant QA as QA System
    participant K as Kafka
    participant C as Потребитель событий
    participant DB as БД Reports
    QA->>K: DefectChanged, ключ defectId
    K->>C: Доставка, группа reports-qa-ingest
    C->>C: Проверка по схеме издателя
    alt схема не прошла
        C->>DB: Журнал ошибок события
        C->>K: Фиксация смещения
    else схема прошла
        C->>DB: BEGIN и INSERT processed_event ON CONFLICT DO NOTHING
        alt eventId уже есть
            DB-->>C: 0 строк
            C->>DB: COMMIT без изменений
        else новое событие
            C->>DB: UPDATE ops.defect, если ревизия новее
            C->>DB: INSERT fact_defect_transition, is_reopen для REOPENED
            C->>DB: UPDATE etl.freshness
            C->>DB: COMMIT
        end
        C->>K: Фиксация смещения
    end
    Note over C,DB: Ошибка БД три раза подряд — событие в журнал ошибок, поток продолжается, сверка SD-09 исправит
```

## SD-02. Пакетная загрузка Task Tracker

Связи: UC-10, US-EX-01, DEC-TT-06.

```mermaid
sequenceDiagram
    participant CJ as CronJob
    participant E as Задание ETL
    participant KC as Keycloak
    participant TT as Task Tracker
    participant DB as БД Reports
    participant CU as Cube
    CJ->>E: Запуск раз в час
    E->>DB: Создать пакет STARTED, прочитать checkpoint
    alt пакет потока уже идёт
        DB-->>E: Нарушение уникальности
        E-->>CJ: Выход без работы
    end
    E->>KC: Токен client credentials
    KC-->>E: access token
    loop Потоки work-items, time-logs, iterations, statuses, history
        loop Страницы по 500
            E->>TT: GET /api/v1/reports/поток?periodFrom=checkpoint&page=N
            alt 200
                TT-->>E: Страница
                E->>DB: INSERT в stg
            else 429 или 5xx или тайм-аут 10 с
                E->>TT: Повтор через 2, 4, 8 с
            else 401 или 403
                E->>DB: Пакет FAILED, причина доступа
            end
        end
    end
    E->>DB: Проверка числа строк и уникальности ID в stg
    alt проверка не прошла
        E->>DB: Пакет REJECTED, checkpoint прежний
    else проверка прошла
        E->>DB: Одна транзакция: upsert stg в dwh и ops, пакет LOADED, новый checkpoint, freshness
        E->>CU: Обновить предагрегации затронутых периодов
    end
```

## SD-03. Загрузка партии Planning System

Связи: UC-11, US-EX-03, D-05.

```mermaid
sequenceDiagram
    participant E as Задание ETL
    participant PS as Planning System
    participant DB as БД Reports
    E->>PS: POST /api/v1/exports, область Reports
    PS-->>E: 202 batchId
    loop Опрос каждые 15 с, не дольше 10 минут
        E->>PS: GET /api/v1/exports/batchId
        PS-->>E: Статус и manifest
    end
    alt партия не READY за 10 минут
        E->>DB: Пакет FAILED, повтор в следующем окне
    else READY
        loop Страницы партии
            E->>PS: GET /api/v1/exports/batchId/rows?page=N
            alt обрыв сети
                E->>PS: Повтор той же страницы, партия неизменяема
            end
            PS-->>E: Строки
            E->>DB: INSERT в stg
        end
        E->>DB: Сверка числа строк с manifest
        alt не совпало
            E->>DB: Пакет REJECTED
        else совпало
            E->>DB: Транзакция: факты плана с planVersionId, dataAsOf, quality, пакет LOADED
        end
    end
```

## SD-04. Наполнение размерности сотрудников

Связи: UC-12, US-EX-04, US-CS-10 Reference Manager.

```mermaid
sequenceDiagram
    participant E as Задание ETL
    participant RM as Reference Manager
    participant DB as БД Reports
    loop Пока next_page_token не пустой
        E->>RM: GET /v1/employees?show_deleted=true&page_size=200&page_token=T
        RM-->>E: employees и next_page_token
        E->>DB: INSERT в stg.employee
    end
    E->>DB: Сравнить stg с текущими версиями dim_employee
    loop Каждый изменившийся сотрудник
        E->>DB: Закрыть версию: valid_to, is_current false
        E->>DB: Вставить новую версию
    end
    loop Каждый удалённый сотрудник
        E->>DB: Закрыть версию, is_active false
    end
    E->>DB: Пересчитать app.user_scope, обновить freshness
    Note over E,RM: Источник недоступен после повторов — версии не меняются, поток становится STALE после 1 ч
```

## SD-05. Построение снимков и обновление куба

Связи: UC-15, ADR-008.

```mermaid
sequenceDiagram
    participant CJ as CronJob 02:00
    participant E as Задание ETL
    participant DB as БД Reports
    participant CU as Cube
    CJ->>E: Запуск снимка за вчерашний день
    E->>DB: Проверка: все потоки загружены после полуночи
    alt есть поток STALE
        E->>DB: Снимок строится, у даты пометка неполноты
    end
    E->>DB: INSERT fact_work_item_daily из ops.work_item на дату
    E->>DB: INSERT fact_defect_daily из ops.defect на дату
    E->>CU: Обновить предагрегации за дату и текущий месяц
    CU->>DB: Агрегирующие запросы к реплике
    CU-->>E: Готово
    E->>DB: freshness аналитического контура
```

## SD-06. Формирование отчёта по запросу

Связи: UC-01, US-MB-01, FR-SEC-02.

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant W as Веб-интерфейс
    participant A as Сервис отчётов
    participant KC as Keycloak
    participant CU as Cube
    participant R as Read-replica
    U->>W: Параметры R-01
    W->>A: POST /api/v1/reports/R-01/query, Bearer
    A->>KC: JWKS, кэш 10 минут
    alt токен недействителен
        A-->>W: 401
    end
    A->>R: Область данных пользователя из app.user_scope
    alt нет роли или проект вне области
        A-->>W: 403
    else параметры недопустимы
        A-->>W: 422 INVALID_PARAMETER
    else разрешено
        alt аналитический контур
            A->>CU: Запрос мер с фильтром области, тайм-аут 10 с
            CU-->>A: Строки
        else оперативный контур
            A->>R: SQL к ops с фильтром области
            R-->>A: Строки
        end
        alt строк больше 10 000
            A-->>W: 422 RESULT_TOO_LARGE
        else
            A->>R: freshness потоков отчёта
            A->>A: Запись аудита
            A-->>W: 200 результат и dataAsOf
        end
    end
    W-->>U: Таблица, график, строка актуальности
```

## SD-07. Асинхронная выгрузка

Связи: UC-08, US-AN-02, ADR-010.

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant A as Сервис отчётов
    participant DB as БД Reports
    participant WK as Воркер выгрузок
    participant CU as Cube
    participant M as MinIO
    participant K as Kafka
    U->>A: POST /api/v1/exports
    A->>A: Права и оценка объёма
    alt до 10 000 строк
        A->>CU: Данные
        A->>M: PutObject exports/exportId
        A-->>U: 201 COMPLETED
    else больше
        A->>DB: export_job QUEUED
        A-->>U: 202 QUEUED
        WK->>DB: Захват задания SELECT FOR UPDATE SKIP LOCKED, RUNNING
        WK->>CU: Данные порциями
        alt ошибка или больше 100 000 строк
            WK->>DB: FAILED, причина
        else успех
            WK->>M: PutObject, контрольная сумма
            WK->>DB: COMPLETED, expires_at, уведомление
            WK->>K: ReportExportReady
            WK->>DB: DELIVERED
        end
    end
    U->>A: GET /api/v1/exports/exportId/file
    A->>A: Проверка владельца и прав
    alt истёк срок
        A-->>U: 410
    else
        A->>M: GetObject
        A-->>U: 200 файл
    end
    Note over WK,DB: Воркер упал в RUNNING — через 15 минут задание возвращается в QUEUED
```

## SD-08. Регламентная рассылка

Связи: UC-06, US-PM-04, FR-SCH-02.

```mermaid
sequenceDiagram
    participant S as Планировщик
    participant DB as БД Reports
    participant A as Сервис отчётов
    participant K as Kafka
    S->>DB: Подписки ACTIVE с next_run_at в прошлом
    loop Каждая подписка
        S->>A: Проверка прав владельца на отчёт
        alt владелец потерял права
            S->>DB: Подписка PAUSED, уведомление владельцу
        else права есть
            S->>A: Сформировать отчёт от имени владельца
            alt ошибка
                S->>DB: Повтор через 15 минут, не более 3 раз, затем уведомление владельцу
            else успех
                S->>DB: report_snapshot
                loop Каждый получатель
                    S->>A: Права получателя на отчёт и область
                    alt прав нет
                        S->>DB: Получатель пропущен, уведомление владельцу
                    else права есть
                        S->>DB: Уведомление получателю
                        S->>K: ScheduledReportReady
                    end
                end
                S->>DB: next_run_at по расписанию
            end
        end
    end
```

## SD-09. Периодическая сверка с источником

Связи: UC-14, US-AD-01, FR-DAT-04.

```mermaid
sequenceDiagram
    participant CJ as CronJob 03:00
    participant E as Задание ETL
    participant SRC as Источник
    participant DB as БД Reports
    CJ->>E: Сверка источника за окно 30 дней
    E->>DB: Начать сверку
    loop Страницы источника
        E->>SRC: Список ID и ревизий за окно
        SRC-->>E: Страница
    end
    E->>DB: Сравнение с dwh: недостающие и лишние
    alt расхождение больше 1% записей
        E->>DB: Сверка FAILED, предупреждение администратору
    else
        E->>SRC: Догрузка недостающих записей
        E->>DB: Загрузка, лишние помечены удалёнными
        E->>DB: Сверка COMPLETED: missing, extra, fixed
    end
    Note over E,SRC: Источник недоступен — сверка FAILED, повтор в следующую ночь, отчёты работают на имеющихся данных
```
