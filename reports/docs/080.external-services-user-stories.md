## US-EX-01 — Загрузить факт Task Tracker пакетом

Как задание ETL Reports (S-07), я хочу постранично читать задачи, трудозатраты, итерации и историю Task Tracker с checkpoint, чтобы DWH отставал не больше чем на час.

- **UC:** [UC-10](060.use-cases.md#uc-10-загрузить-данные-task-tracker). **Эпик:** E-02.
- GWT-1: **Given** checkpoint `2026-10-05T10:00:00Z`, **When** задание запускается в 11:00, **Then** оно читает `/api/v1/reports/time-logs` с периодом от checkpoint, страницами по 500 до последней.
- GWT-2: **Given** третья страница вернула `503` три раза подряд, **When** задание завершает пакет, **Then** пакет `FAILED`, DWH не изменён, checkpoint прежний.
- GWT-3: **Given** токен без роли `reports-service`, **When** задание вызывает эндпоинт, **Then** трекер возвращает `403`, пакет `FAILED` с причиной «нет доступа».

## US-EX-02 — Применять события без двойного учёта

Как потребитель событий Reports (S-08), я хочу отбрасывать повторно доставленные события по `eventId`, чтобы часы и дефекты не учитывались дважды.

- **UC:** [UC-13](060.use-cases.md#uc-13-загрузить-данные-qa-system). **Эпик:** E-05.
- GWT-1: **Given** `DefectChanged` с `eventId` X уже обработан, **When** он приходит снова, **Then** витрина не меняется, смещение фиксируется.
- GWT-2: **Given** трекер прислал для одного изменения `WorkItemFieldsChanged` и `TimeLogged`, **When** события применяются, **Then** часы берутся только из `TimeLogged`.

## US-EX-03 — Загрузить партию Planning System

Как задание ETL Reports, я хочу создать неизменяемую партию экспорта и прочитать её по manifest, чтобы план и прогноз в DWH были согласованы между собой.

- **UC:** [UC-11](060.use-cases.md#uc-11-загрузить-данные-planning-system). **Эпик:** E-03.
- GWT-1: **Given** партия `READY` с manifest на 4 200 строк, **When** задание прочитало все страницы, **Then** загружено ровно 4 200 строк, иначе пакет `REJECTED`.
- GWT-2: **Given** сеть оборвалась на второй странице, **When** задание повторяет чтение, **Then** получает те же строки: партия неизменяема.

## US-EX-04 — Загрузить справочники

Как задание ETL Reports, я хочу раз в час выгружать сотрудников и подразделения с удалёнными, чтобы размерности отражали изменения с историей.

- **UC:** [UC-12](060.use-cases.md#uc-12-загрузить-справочники-reference-manager). **Эпик:** E-04.
- GWT-1: **Given** сотрудник перешёл в другое подразделение, **When** задание загрузило `employees`, **Then** старая версия в `dim_employee` закрыта датой загрузки, создана новая.
- GWT-2: **Given** сотрудник удалён (`DELETED`), **When** задание загрузило данные, **Then** версия закрыта, история трудозатрат за прошлые периоды сохранена.

## US-EX-05 — Показать показатели итерации в трекере

Как страница итерации Task Tracker (S-10), я хочу получить карточку показателей итерации от Reports, чтобы пользователь видел качество итерации без перехода в Reports.

- **UC:** [UC-17](060.use-cases.md#uc-17-встроить-отчёт-в-интерфейс-task-tracker). **Эпик:** E-08. **Статус:** предложение, у трекера не заявлено.
- GWT-1: **Given** клиент с ролью `reports-embed` и токен пользователя с RL-02, **When** он запрашивает `GET /api/v1/embed/iterations/{iterationId}`, **Then** получает M-06, M-14, M-16, M-17 и `dataAsOf`.

## US-EX-06 — Узнать о готовности выгрузки

Как Notification Service (S-12), я хочу получать событие о готовности выгрузки, чтобы доставить уведомление по внешнему каналу.

- **Эпик:** E-11. **Статус:** зависит от Q-REP-13.
- GWT-1: **Given** задание выгрузки перешло в `COMPLETED`, **When** создано уведомление, **Then** в `dev.reports.delivery.v1` опубликовано `ReportExportReady` без содержимого отчёта, только идентификаторы и ссылка на API Reports.
