# 075 — NFR (Non-Functional Requirements)

> Формат — см. [состав документов](documents-composition.md), документ 075.
> Источник — [vision, раздел 7](vision.md#7-нефункциональные-требования). NFR-01…20 — из vision 0.3; NFR-15…20 добавлены по замечаниям от 01.10.2026, NFR-04 уточнён по способу обмена. Решения — [145](145.architecture-decisions.md), проверки T — [095](095.requirements-check.md).

Значения — предложение команды Reports. Пороги, которые зависят от соседей, помечены договорённостью Q-REP из [020](020.system-context.md#6-открытые-договорённости).

## 2. Актуальность данных

NFR-04 в vision обещал 5 минут «по событиям», но события Task Tracker пока только предложены (K-02). Поэтому лаг задан по каждому источнику и способу обмена.

| ID | Источник и способ | Контур | Лаг, не более | Почему так |
| --- | --- | --- | --- | --- |
| NFR-04.1 | Task Tracker, Kafka (после DEC-TT-02) | Оперативный | 5 мин | Отправка после commit через outbox, обработка потребителем |
| NFR-04.2 | Task Tracker, опрос REST (сейчас) | Оперативный | 15 мин | Опрос раз в 5 минут по `updatedSince`, чтение страниц и загрузка |
| NFR-04.3 | QA System, Kafka | Оперативный | 2 мин | QA публикует не позже 30 с после изменения |
| NFR-04.4 | Planning System, оперативная проекция | Оперативный | 5 мин | Кэш проекции 5 минут; сигнал `PlanActivated` сбрасывает кэш |
| NFR-04.5 | Reference Manager, `List` | Оба | 1 ч | Владелец гарантирует перечитывание не реже раза в час, событий нет |
| NFR-15 | Все источники | Аналитический (DWH) | 1 ч | Инкрементальное задание ETL раз в час (NFR-16) |

Если лаг потока превышает порог, поток переходит в `STALE`, и отчёты показывают предупреждение (FR-DAT-06).

| ID | Требование | Значение | Обоснование |
| --- | --- | --- | --- |
| NFR-16 | Периодичность ETL | Инкрементальная загрузка каждого источника — раз в час; периодический снимок и полная сверка — раз в сутки в 02:00 по часовому поясу стенда; внеочередная загрузка Planning System — по событию `PlanActivated` | Раз в сутки не выполняет NFR-15 (DWH ≤ 1 ч). Только по событию нельзя: у Reference Manager событий нет, у Task Tracker они не согласованы. Час — компромисс между лагом и нагрузкой NFR-20 |

## 4. Спецификация показателей

Каждый показатель считается только здесь описанным способом и только в семантическом слое ([ADR-013](145.architecture-decisions.md)); отчёты и дашборды на него ссылаются (FR-CALC-01). Пустое значение выводится категорией «не задано» и не превращается в ноль (FR-CALC-06).

| --- | --- | --- | --- | --- | --- |
| M-01 | Фактические часы | Сумма `hours` записей трудозатрат с датой записи в периоде, без удалённых | Часы, 2 знака | Запись без проекта — «не задано» | R-01, R-06, R-11 |

| M-03 | Остаток | Значение Task Tracker без пересчёта (FR-CALC-02); может быть отрицательным | Часы | Нет оценки — «не задано» | R-06 |

**Сопоставление периодов (FR-RPT-11).** Сравнивается период той же длины, непосредственно предшествующий выбранному; для итерации — предыдущая завершённая итерация того же проекта. Недели — ISO, начало — понедельник. Если в одном из периодов нет данных, разница не считается, показывается «нет данных для сравнения».

**Категории статусов.** Статусы Task Tracker и QA System сводятся в категории «бэклог», «в работе», «завершена», «архив» по таблице `dim_status` ([120](120.data-model.md)). Для трекера сопоставление берётся из `/reports/statuses`, для дефектов QA: `CLOSED` — «завершена», остальные — «в работе».
