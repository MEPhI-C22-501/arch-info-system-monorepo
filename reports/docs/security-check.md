# Проверка безопасности

> Требование — технические требования к модулю (проверка по чек-листу: XSS, CSRF, инъекции) и [NFR-09](075.nfr.md). Образец — [Reference Manager](../../reference-manager/documents/security-check.md).

**Статус:** чек-лист составлен, проверка не проводилась — кода Reports в репозитории ещё нет. Отчёт заполняется на этапе 5 по каждому пункту: результат, способ проверки, дата.

## 1. Чек-лист

| № | Угроза | Мера в проекте | Как проверить | Результат |
| --- | --- | --- | --- | --- |
| S-01 | XSS в веб-интерфейсе | React экранирует вывод; `dangerouslySetInnerHTML` запрещён линтером; названия задач и проектов выводятся как текст | Задача с названием `<img src=x onerror=alert(1)>` в источнике → отчёт и выгрузка | Не проверено |
| S-02 | XSS в Superset | Markdown-виджеты с пользовательским HTML отключены; данные выводятся как текст | Тот же тест на дашборде | Не проверено |
| S-03 | Формулы в выгрузке (CSV injection) | Значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются в `.csv` и `.xlsx` | Задача с названием `=HYPERLINK(...)` → открыть выгрузку в Excel | Не проверено |
| S-04 | CSRF | API принимает только `Authorization: Bearer`, cookie-сессий нет; Superset — CSRF-токен включён | Запрос с чужого origin без токена → `401` | Не проверено |
| S-05 | SQL-инъекции | Параметры отчётов — только связанные параметры; разрезы и меры — из перечня описания отчёта, не из строки запроса | Параметр `slice = "employee; DROP TABLE"` → `422` | Не проверено |
| S-06 | Обход области данных | Область применяется на сервере в API, Cube и Superset RLS | RL-04 запрашивает чужого сотрудника → `403`; Explore без RLS недоступен | Не проверено |
| S-07 | Доступ к чужой выгрузке | Скачивание через API с проверкой владельца; предподписанных ссылок нет | Чужой `exportId` → `404` | Не проверено |
| S-08 | Подделка токена | Проверка подписи по JWKS, `iss`, `aud = reports`, срока | Токен другого клиента, истёкший, с изменённой подписью → `401` | Не проверено |
| S-09 | Секреты в репозитории и журналах | Secret Infra; `.env.example` без значений; маскирование `Authorization` в журналах | Сканер секретов в CI; поиск по журналам стенда | Не проверено |
| S-10 | Избыточные права у источников | Только чтение: `reports-service`, `qa-reports-reader`, R-01, S-06 | Попытка изменяющего вызова к источнику токеном Reports → `403` | Не проверено |
| S-11 | Персональные данные в событиях | В `dev.reports.delivery.v1` нет значений и имён, только идентификаторы | Проверка схем [140](140.event-schema.md) | Выполнено по документам |
| S-12 | Аудит | Каждое формирование и выгрузка пишутся в `app.audit_log`; UPDATE и DELETE отозваны | Попытка изменить запись аудита от пользователя приложения → отказ | Не проверено |

## 2. Отчёт

Заполняется после реализации: дата, версия образа, кто проверял, результат по S-01…S-12, найденные проблемы и ссылки на исправления.
