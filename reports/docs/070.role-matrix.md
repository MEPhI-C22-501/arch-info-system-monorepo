# 070 — RBAC (Role-Based Access Control)

> Формат — см. [состав документов](documents-composition.md), документ 070.
> Источник — [vision, FR-SEC-01…04](vision.md#64-доступ-и-аудит), [030 Actors](030.actors.md). Решение о механизме — [ADR-012](145.architecture-decisions.md).

Права проверяются на сервере Reports и в BI, а не скрытием элементов интерфейса (NFR-09). Роль даёт доступ к операции, **область данных** — к конкретным проектам и сотрудникам. Без области роль не открывает ни одной строки.

## 1. Роли

Роли — клиентские роли клиента `reports` в Keycloak (Q-REP-11).

| ID | Роль Keycloak | Актор | Область данных |
| --- | --- | --- | --- |
| RL-01 | `reports-project-manager` | H-01 Руководитель проекта | Проекты, где он руководитель по Planning System |
| RL-02 | `reports-team-lead` | H-02 Тимлид | Проекты, где назначены сотрудники его подразделения; сотрудники его подразделения по Reference Manager |
| RL-03 | `reports-qa-lead` | H-03 QA-лид | Проекты, где он назначен по Planning System |
| RL-04 | `reports-member` | H-04 Участник | Только собственные данные: `sub` = `account_user_id` сотрудника |
| RL-05 | `reports-analyst` | H-05 Аналитик и PMO | Все проекты |
| RL-06 | `reports-admin` | H-06 Администратор | Настройки, журналы, актуальность; бизнес-данные — только если выдана ещё одна роль |
| RL-07 | `reports-service` | S-07, S-08, S-09 | Внутренние операции загрузки и формирования; пользовательских операций нет |
| RL-08 | `reports-embed` | S-10 | Только чтение карточек итерации от имени пользователя из переданного токена |

Пользователю можно выдать несколько ролей; области объединяются.

## 4. Как определяется область данных

| Признак | Источник | Как применяется |
| --- | --- | --- |
| Пользователь | `sub` из токена Keycloak | Связь с сотрудником — `employees.account_user_id` Reference Manager |
| Подразделение пользователя | `org_units` Reference Manager | Для RL-02 |
| Руководитель проекта, назначения | Назначения и роли проекта Planning System | Для RL-01, RL-03 |
| Все проекты | Роль | Для RL-05 |

Область пересчитывается при каждой загрузке справочников и плана и хранится в `app.user_scope`. API Reports и BI фильтруют данные на сервере: API — условием по проектам и сотрудникам, BI — правилами на уровне строк ([ADR-012](145.architecture-decisions.md)). Если у пользователя нет связи с сотрудником, доступны только отчёты RL-05 при наличии этой роли; в остальных случаях — `403` с пояснением.
