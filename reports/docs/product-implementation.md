# Исполняемые Reports: R-01…R-11, выгрузки, подписки и аудит

Реализация находится целиком в `reports/pilots/`. Это работающий локальный
профиль, не акт приёмки реальных источников или общего окружения.

## Запуск и интерфейс

Обычный `launch.py up --build -d --wait` поднимает API и `product-jobs` вместе
с прежними PostgreSQL, ETL, Cube, Superset и Keycloak. Инициализатор секретов
добавляет недостающий `REPORTS_APP_DB_PASSWORD` только в `~/secrets.env`.

Интерфейс: [Reports](http://localhost:8081/ui/). Вход — public client
`reports-ui`, Authorization Code + PKCE S256; access token остаётся только в
памяти страницы. В браузерном storage лежат только временные state/verifier,
удаляемые после callback; код убирается из URL. Пароли и токены не сохраняются
в проекте. Выход очищает token и переходит к завершению сеанса Keycloak.

В интерфейсе доступны каталог, период, разрез, фильтры, сравнение периодов,
таблица и график, выгрузки, печатная версия, сохранённые представления,
подписки, уведомления и просмотр аудита для администратора. Пользовательские
строки выводятся через `textContent`, печать экранируется, CSP запрещает
inline script. Незавершённый период и недостающие источники помечаются явно.

Синтетический `admin` имеет **две** роли: `reports-admin` и `reports-analyst`.
Это не обход проверки: чистый admin не читает бизнес-данные. Member1/2 имеют
свою область. Superset оставлен для R-01; остальные отчёты доступны в Reports UI.

## Отчёты и семантика

| Отчёт | Реализовано |
| --- | --- |
| R-01 | Часы, проект/сотрудник/итерация/эпик/неделя/месяц, период, итоги и детализация |
| R-02 | Потребность, назначения, доступность, загрузка и дефицит; связи Planning → Tracker/сотрудник только явные |
| R-03 | Листовые задачи, план/факт/остаток, доля завершённых; трудозатраты скрыты от QA-only |
| R-04 | Незавершённые просроченные задачи, дни просрочки, отсутствие срока, позднее завершение |
| R-05 | Создание, первое закрытие, остаток с учётом переоткрытия, медиана закрытия |
| R-06 | План-факт, отрицательный остаток, перерасход, темп за настраиваемые 1…52 недели; прогноз и бюджет из Planning |
| R-07 | Последний результат кейса в прогоне, pass rate, выполнение, отдельные BLOCKED/SKIPPED |
| R-08 | Дефекты, статус/серьёзность, собственные записи для member при подтверждённом авторе |
| R-09 | Завершение, pass rate, reopened rate; методика M-16 остаётся Q-REP-12 |
| R-10 | Cycle/lead time, медиана и p85, throughput по ISO-неделям, средний дневной WIP |
| R-11 | Отклонение оценок и медианный коэффициент только завершённых листовых задач с планом > 0 |

Один `report_engine.py` вызывают HTTP, печать, файлы и подписки. Итоги,
отношения и медианы считаются по исходным популяциям, а не суммируются из
процентов групп. При нескольких разрезах возвращаются `subtotals` по префиксам.
Сравнение берёт непосредственно предыдущий интервал той же длины; при отсутствии
данных разница не вычисляется. Для R-06 `params.velocityWeeks` по умолчанию 4.

Часы берутся из принятого DWH, планы/остатки — от владельца задач, деньги —
только из `estimatedTotalCost`, `budgetAdjustment`, `currencyCode` Planning.
Они скрыты без роли PM/analyst **и** `cost.read`; Reports не рассчитывает деньги.
M-16 возвращается null с указанием Q-REP-12; кандидат по предложенной формуле
выделен отдельно. Нет истории — нет выдуманных закрытий и cycle time. Нет
связи идентификаторов или недельного распределения потребности — null/«не задано»,
а не произвольная сумма. Наблюдаемые состояния не восстанавливают историю до
первой загрузки. Для рабочих категорий OPEN требуется явное сопоставление.

## API и владение объектами

Базовый путь `/api/v1`, Bearer RS256/JWKS, обязательные период и серверная
область. [OpenAPI](../api/openapi/v1/openapi.yaml) остаётся draft до Q-REP-04/05.

- Каталог, описание, query, drilldown и POST `reports/{reportId}/print`.
- CRUD `views`: только свои; viewId не снимает повторную проверку прав.
- POST/GET `exports`, GET задания и `/file`: только владелец.
- CRUD `subscriptions`, журнал `/deliveries`; PATCH требует `If-Match`.
- GET/PATCH `notifications`: только получатель.
- GET `audit`: только admin, пагинация и correlation ID.

Прочие административные ETL/embedding endpoints целевого OpenAPI не объявляются
реализованными этой доработкой. Роль, период, неизвестные параметры и фильтры
проверяются сервером. Изменение роли/области не требует доверия к сохранённому UI.
Старый HTTP `/pilot` также не даёт admin-only глобальную область; Cube принимает
глобальный analyst, а не admin. Старый внутренний Python helper оставлен только
для совместимости тестов первого пилота и не является публичной авторизацией.

## Выгрузки

Асинхронные задания лежат в PostgreSQL. Worker обрабатывает их транзакционно:
после сбоя незавершённая работа откатывается, частичного файла нет. Очередь
ограничена 20 ожидающими заданиями пользователя. CSV защищает опасные префиксы,
в том числе после пробелов/BOM; XLSX использует inline strings без формул и
внешних связей. Добавляются автор, параметры, время и актуальность источников.
Печатный HTML экранируется и отдаётся с отдельной CSP.

Файлы локально хранятся как BYTEA **в собственной БД Reports**, SHA-256
проверяется при скачивании; срок — 24 часа, после него 410 и очистка содержимого.
Чужой файл — 404. На каждом скачивании проверяется актуальная область и её
fingerprint; изменение прав/связей делает старый файл недоступным. Ссылок без
аутентификации и пользовательских путей файлов нет. Общий MinIO пока не подключён.

## Подписки

Пять полей cron: числа, списки, диапазоны и шаги; timezone Europe/Moscow.
Пропущенные интервалы не создают шквал догоняющих доставок. Законченный срок
переводит подписку в COMPLETED; завершённую подписку нельзя возобновить.
Обновление версии защищает от потерянной записи. Два worker сериализуются
advisory lock PostgreSQL; доставка имеет уникальный ключ subscription/runAt.

Перед каждой доставкой локальный worker **читает текущие enabled/роли из
Keycloak**. Нет связи/роли/доступности каталога — получатель пропускается;
владелец потерял право создавать подписку — подписка приостанавливается.
Для каждого получателя создаётся отдельный файл в пересечении его области и
области владельца. Уведомление готовности появляется после формирования файла.
Владелец подписки не может скачать файлы других получателей.

Keycloak admin credential используется только локальным worker для чтения
синтетического realm; API контейнер его не получает. Для общего стенда нужен
read-only service account. Без Keycloak-профиля worker использует ограниченную
по сроку директорию проверенных JWT в Reports и отказывает при её истечении.
Это не механизм бессрочного сохранения ролей или токенов.

## Области и аудит

`app.user_scope` и `app.entity_link` изменяет только оператор, не пользовательский
API. Согласованный JSON без секретов можно подать на stdin:

```bash
python reports/pilots/launch.py run --rm -T --no-deps provision python configure_product.py < approved-scopes.json
```

Ключи JSON: replaceScopesFor/scopes, links, disableSubjects/enableSubjects.
Сопоставления: planning-project, planning-employee, hr-employee,
tracker-status-category, employee-role. Нет автоматической привязки по имени
или совпавшим UUID. Изменение конфигурации тоже попадает в аудит.

API/worker подключаются ролью `reports_app`: SELECT источников своей БД,
операции своих служебных таблиц и INSERT аудита. Изменять scopes/links и
обновлять enabled principals эта роль не может. Аудит не содержит токенов,
полных ответов и исходных payload: актор, действие, report/resource ID,
хеш запроса, результат, timestamp и correlation ID. UPDATE/DELETE/TRUNCATE
блокируются правами и PostgreSQL trigger; SQLite-тесты также проверяют запрет.

## Проверка и пределы

[Unit/HTTP/PostgreSQL](../pilots/tests/test_product.py),
[публичный HTTP](../pilots/tests/test_product_http.py),
[живой стенд](../pilots/artifacts/product-verification.json),
[все проверки](../pilots/artifacts/verification.json).
`check_product.py` проходит PKCE, все отчёты, настоящую очередь, скачивание,
отзыв роли синтетического получателя и восстановление в finally.

Интерактивный предел — 10 000 групп, экспорт — 100 000, исходная популяция
одного чтения — 100 000; файл до 20 MiB. Превышение даёт RESULT_TOO_LARGE,
данные не обрезаются молча. Производительность всех новых отчётов на общем
объёме не принята; замер миллиона строк Cube относится только к R-01.
Типизированная звезда, меры Cube и локальные ops/Kafka реализованы —
[описание и проверки](star-events-implementation.md). Общие read-replica, MinIO,
внешний канал уведомлений, общая CI и мгновенный logout требуют интеграции.
