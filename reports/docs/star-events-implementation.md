# DWH, Cube и локальный событийный конвейер

Состояние локальной реализации на 2026-10-25. Изменения ограничены `reports/`.
Согласование контрактов, реальные учётные записи источников и общий стенд не
подменяются локальными тестами.

## DWH

`pilots/star.py` создаёт 16 типизированных измерений, календарь, факты трудозатрат,
задач, переходов статусов, дефектов и их переходов, результатов и прогонов тестов,
элементов плана, потребностей, назначений, доступности и прогнозов. Факты имеют
внешние ключи; неизвестный участник измерения — `-1`. Естественные идентификаторы
сохраняются для сверки и авторизации. `plan_version` хранит версии планов.

SCD2 использует полуоткрытые интервалы наблюдений. Загрузка старых данных не
создаёт вымышленную историю HR: до первого наблюдения ключ неизвестен. Нужны
явные `entity_link` и `subject_binding`; одинаковые строки ID ничего не связывают.
Изменение разрешённых соответствий повторно проецирует звезду. Исходные payload
сохраняются для воспроизводимости; API читает подготовленные таблицы звезды.
Python остаётся транспортом расчётов R-01…R-11; наличие мер Cube не означает,
что HTTP API уже выполняет запросы через Cube.

Потребность за несколько недель сохраняется один раз. Если источник не разбил
период, `week_key=-1` и `etl.star_issue=UNSPLIT_SOURCE_PERIOD`; часы по неделям
не распределяются произвольно. План и прогноз с неполными входами сохраняют
`null`, качество и сведения об источнике.

## Меры Cube

Модели находятся в `pilots/cube/model/`. Один запрос работает с одной популяцией;
несогласованные соединения фактов запрещены, чтобы не умножать суммы.

| Меры | Модель и способ запроса |
| --- | --- |
| M-01 | `TimeLogs.hours`, фильтр `loggedDate` |
| M-02…M-04 | `PlanFact`: обязательный период; часы внутри периода, план задач на конец периода, UNION независимых популяций |
| M-05, M-06 | `WorkItems.overdue`, `completionPercent`; состояние последнего наблюдения |
| M-07 | `TimeLogs.velocity`: обязательное окно ровно 28 календарных дней, деление на четыре недели |
| M-08, M-09 | `Forecasts`: последний прогноз проекта, деньги только с `cost.read` и группировкой по валюте |
| M-10, M-11 | `Resources`: сумма факта / доступность и потребность минус назначения; без известной доступности результат `null` |
| M-12, M-13 | `Defects` и `DefectFlow`: создание, первое закрытие, остаток и отдельная популяция переходов; обязательны соответствующие временные фильтры |
| M-14, M-15 | `TestResults`, `TestRuns`: последний результат кейса в прогоне, отношения сумм |
| M-16 | `Quality.defectDensity=null` до Q-REP-12; `candidateDefectDensity` явно неутверждённый кандидат |
| M-17 | `DefectFlow`: уникальные переоткрытые / уникальные закрытые дефекты выбранного периода |
| M-18 | `WorkItems`: медиана и интерполированный p85 cycle/lead, фильтр `completedAt` |
| M-19 | `WorkItems.throughput` по `completedAt`; `StatusFlow.averageWip` по дням, включая дни с нулём; будущие дни исключены |
| M-20 | `WorkItems`: взвешенная ошибка и медиана факт/план завершённых задач с положительным планом |

`WorkItems.overrun` — дополнительный показатель за жизненный цикл задачи;
для M-04 за выбранный период используется `PlanFact.overrun`. Доступность HR
не приписывается произвольному проекту: без однозначной связи проектный M-10
может быть неизвестен. Денежные показатели разных валют не суммируются вместе.

`cube/access.js` добавляет серверную область проекта/сотрудника, проверяет
отключённого пользователя и роль. Admin сам по себе не даёт бизнес-доступа.
Участник ограничен разрешёнными моделями и своими строками. Общий SQL-пользователь
Superset видит только `TimeLogs`; новые модели доступны через проверенный JWT.
Роль БД Cube читает только подготовленные views, без исходных HR и ACL-таблиц.

## События и эксплуатация

Локальный Compose запускает приватный Kafka 3.9.1 без опубликованного порта,
инициализацию топиков и `events`. Клиент — confluent-kafka 2.11.1.
Схемы читаются из файлов владельцев через read-only mounts. Для Planning
`dev.planning.signals.v1` — локальное имя; общий топик и ACL не объявляются
согласованными. Общие TLS/SASL и сервисные учётные записи остаются у Infra.

`events.py` проверяет оболочку, версию, payload, ключ и маршрут агрегата.
Проекция `ops`, звезда, hash/eventId и checkpoint фиксируются одной транзакцией
PostgreSQL; broker commit выполняется после неё. Повтор после падения безопасен.
Поле имеет часы изменения: старое событие или REST без более свежего `updatedAt`
не перезаписывает новое. Часы M-01 записывает только `TimeLogged`; общий снимок
`actualHours` обновляет атрибут задачи, но не добавляет часы в журнал повторно.
Hard delete сохраняет историю и помечает удаление.

Три ошибки одного offset создают долговечный DLQ в БД; в broker DLQ уходят только
ссылка, причина и digest. Невалидная оболочка сохраняется hash-only. Разрешённый
payload хранится приватно для `event_runner.py --replay TOPIC PARTITION OFFSET`.
Коллизия eventId с другим телом не заменяет исходное событие. Смещение не
двигается назад. После завершения прогона новые результаты QA не применяются;
история переходов дефектов сохраняется отдельно. Сигнал Planning создаёт запрос
перечитать источник, без выдуманных часов. Демо-профиль выполняет перечитывание
синтетического источника; для реального источника используется `run_etl.py`.

`event_outbox.py` формирует события по существующим схемам Reports в транзакции
выгрузки. Публикация помечается успешной после подтверждения Kafka; при падении
возможен повтор с тем же eventId. Ссылка `/snapshots/{id}` открывает UI, выполняет
обычный вход и защищённое скачивание снимка получателя. TTL файла — 24 часа.

`maintenance.py` выполняется после 02:00 Europe/Moscow один раз за местный день:
фиксирует наблюдаемый снимок с watermarks и статусом OBSERVED/STALE, сверяет
локальные проекции. REST-загрузка отдельно сверяет множество ID с ответом
источника; отсутствие строки не превращается автоматически в удаление.
Пропущенные дни регистрируются. Из сохранённого суточного среза можно восстановить
только частичное историческое наблюдение с соответствующей отметкой, а не точное
состояние в пропущенные 02:00. История до первого наблюдения требует источника.

Успешно опубликованные outbox и старые сверки очищаются через 90 дней;
неотправленные сообщения, нерешённый DLQ, ledger и бизнес-история автоматически
не удаляются. Сроки общего хранения и резервные копии требуют общей политики.

## Проверки

- `check_postgres.py`: весь набор тестов на отдельном PostgreSQL, включая FK,
  SCD2, откат транзакций, повторы, запоздавшие события, QA, Planning и снимки.
- `check_semantics.py`: настоящие запросы Cube ко всем семействам мер и отказы
  для недопустимых ролей; [протокол](../pilots/artifacts/semantic-verification.json).
- `record_events.py`: настоящий Kafka и отдельная тестовая БД, падение после
  commit БД до commit Kafka, DLQ и outbox; [протокол](../pilots/artifacts/event-verification.json).
- `check_cube.py`: миллион строк, предагрегация и доступ участника; это замер
  трудозатрат, а не нагрузочная приёмка всех отчётов.
- `check_clean.py`: запуск с чистыми тестовыми томами, реальные Keycloak,
  Superset, API, роли и доставка; исходные тома сохраняются и стенд восстанавливается.

Итог полного прогона и хеши исходников — [verification.json](../pilots/artifacts/verification.json).
