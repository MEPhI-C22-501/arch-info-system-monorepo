# 080 — User Stories: внешние сервисы

> Формат — см. [`../documents-composition.md`](../documents-composition.md#080--user-stories-080actor-user-storiesmd).
> Источник — [`../vision.md`](../vision.md). Дополнительный файл сверх формата (акторы —
> внешние системы, а не люди), поскольку у Task Tracker есть два API-потребителя с собственными
> историями. Роль — [070 RBAC](070.role-matrix.md), use cases — [060](../block-b-domain-analysis/060.use-cases.md).

**US-T1.** Как сервис тестирования, я хочу создать задачу типа «Ошибка» через API по результатам тестового прогона, чтобы дефект автоматически попал в бэклог без ручного переноса.
- GWT-1: Дано валидные данные дефекта и уникальный внешний ID, Когда я вызываю API создания ошибки, Тогда создаётся задача, а серьёзность конвертируется в приоритет.
- GWT-2: Дано я повторяю запрос с тем же внешним ID, Когда вызываю API снова, Тогда дубликат не создаётся, возвращается ссылка на существующую задачу.
*(→ UC-16)*

**US-R1.** Как сервис отчётности, я хочу получить данные о задачах, итерациях и трудозатратах за период, чтобы построить отчёты без прямого доступа к базе Task Tracker.
- GWT-1: Дано у меня есть валидный сервисный токен, Когда я запрашиваю данные с фильтром по периоду и проекту, Тогда получаю постраничный ответ со стабильными идентификаторами.
- GWT-2: Дано токен не имеет read-only scope отчётности, Когда сервис вызывает endpoint, Тогда Task Tracker возвращает структурированный `403` с correlation ID и не раскрывает данные.
*(→ UC-17)*

**US-D1.** Как сервис справочников, я хочу отдавать постраничные коллекции сотрудников и оргструктуры, чтобы Task Tracker использовал актуальные данные без их локального редактирования.
- GWT-1: Дано Task Tracker выполняет авторизованный запрос, Когда доступна новая версия, Тогда возвращаются стабильный ID, отображаемое имя и признак активности.
- GWT-2: Дано значение стало неактивным, Когда синхронизация завершилась, Тогда оно сохраняется в старых задачах, но недоступно для новых назначений.
*(→ UC-18)*

**US-P1.** Как Planning System, я хочу публиковать версию проекта и читать фактическое выполнение, чтобы пересчитывать план-факт.
- Дано принятый пакет, Когда повторяется та же версия и JSON, Тогда дубликатов нет.
- Дано новая версия, Когда один элемент некорректен, Тогда весь пакет откатывается.
- Дано проект с задачами и фактом, Когда проект снимается с плана, Тогда данные выполнения сохраняются.
*(→ UC-20)*

**US-R2.** Как Reports, я хочу получать события и выполнять пакетную сверку по REST, чтобы обновлять витрину без двойного учёта.
- Дано повтор eventId, Когда потребитель применяет событие, Тогда повторного учёта нет.
- Дано недоступный брокер, Когда API сохраняет изменение, Тогда событие остаётся в outbox до доставки/replay.
*(→ UC-21; DEC-TT-02/06)*
