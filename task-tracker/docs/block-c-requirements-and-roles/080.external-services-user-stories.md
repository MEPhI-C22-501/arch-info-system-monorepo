# 080 — User Stories: внешние сервисы

> Формат — см. [`../documents-composition.md`](../documents-composition.md#080--user-stories-080actor-user-storiesmd).
> Источник — [`../vision.md`](../vision.md). Дополнительный файл сверх формата (акторы —
> внешние системы, а не люди), поскольку у Task Tracker есть два API-потребителя с собственными
> историями. Роль — [070 RBAC](070.role-matrix.md), use cases — [060](../block-b-domain-analysis/060.use-cases.md).

**US-T1.** As the сервис тестирования, I want создать задачу типа «Ошибка» через API по результатам тестового прогона so that дефект автоматически попал в бэклог без ручного переноса.
- GWT-1: Given валидные данные дефекта и уникальный внешний ID, When я вызываю API создания ошибки, Then создаётся задача, а серьёзность конвертируется в приоритет.
- GWT-2: Given я повторяю запрос с тем же внешним ID, When вызываю API снова, Then дубликат не создаётся, возвращается ссылка на существующую задачу.
*(→ UC-16)*

**US-R1.** As the сервис отчётности, I want получить данные о задачах, итерациях и трудозатратах за период so that построить отчёты без прямого доступа к базе Task Tracker.
- GWT-1: Given у меня есть валидный сервисный токен, When я запрашиваю данные с фильтром по периоду и проекту, Then получаю постраничный ответ со стабильными идентификаторами.
- GWT-2: Given токен не имеет read-only scope отчётности, When сервис вызывает endpoint, Then Task Tracker возвращает структурированный `403` с correlation ID и не раскрывает данные.
*(→ UC-17)*

**US-D1.** As the сервис справочников, I want отдавать версии пользователей, команд и подразделений so that Task Tracker использовал актуальные данные без их локального редактирования.
- GWT-1: Given Task Tracker выполняет авторизованный запрос, When доступна новая версия, Then возвращаются стабильный ID, отображаемое имя и признак активности.
- GWT-2: Given значение стало неактивным, When синхронизация завершилась, Then оно сохраняется в старых задачах, но недоступно для новых назначений.
*(→ UC-18)*
