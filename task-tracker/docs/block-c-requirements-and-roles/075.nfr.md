# 075 — NFR (Non-Functional Requirements)

> Формат — см. [`../documents-composition.md`](../documents-composition.md#075--nfr-non-functional-requirements-075nfrmd).
> Источник — [`../vision.md`](../vision.md), раздел «Нефункциональные требования». Рабочие ID
> введены в [095 — Traceability Matrix](../block-d-verification/095.requirements-check.md).

| ID | Категория | Требование | Метрика / порог | Проверка |
|---|---|---|---|---|
| NFR-001 | Надёжность | Операции изменения данных сохраняют целостность или возвращают понятную ошибку | 100 % проверенных отказов завершаются согласованно или откатываются целиком | VT-NFR-01: fault-injection на каждом шаге изменяющей транзакции |
| NFR-002 | Сопровождаемость / аудит | Каждое изменение карточки, кроме удаляющего историю hard delete, фиксируется с автором/источником, датой и diff | 100 % остальных типов успешных изменений порождают запись истории; hard delete удаляет её по явному правилу | VT-NFR-02: параметризованный тест всех change-kind и отдельная проверка hard delete |
| NFR-003 | Безопасность | Авторизация контролируется на сервере по роли пользователя, не только скрытием элементов интерфейса | 100 % защищённых операций отклоняют запрос без нужного права | VT-NFR-03: матричный тест ролей и сервисных клиентов |
| NFR-004 | Надёжность | Уведомление создаётся только после успешного изменения и не должно теряться при штатной работе | Для каждого успешного изменения с исполнителем есть ровно одно ожидаемое уведомление; после отката — ни одного | VT-NFR-04: интеграционный тест commit/rollback, включая удаление элемента |
| NFR-005 | Целостность данных | Жёсткое удаление выполняется атомарно, без «повисших» ссылок | Элемент и удаляемые зависимости исчезают в одной транзакции; уведомление об удалении сохраняется с `work_item_id = null` | VT-NFR-05: проверка FK и каскадов до/после удаления |
| NFR-006 | Наблюдаемость | Интеграционные операции наблюдаемы: результат, длительность, correlation ID; секреты не пишутся в журнал | 100 % внешних вызовов имеют result/duration/correlation ID; 0 секретов в тестовой выборке журналов | VT-NFR-06: анализ журналов успешных и ошибочных вызовов |
| NFR-007 | Удобство использования | Единый формат дат/времени и согласованный часовой пояс | Один документированный формат и один настроенный часовой пояс во всех UI/API-представлениях | VT-NFR-07: контрактные и UI-проверки граничных дат |
| NFR-008 | Производительность / доступность / масштабируемость *(не определено)* | Время отклика, пропускная способность, объём данных, доступность, RPO/RTO | Порогов пока нет; требование остаётся `missing` до согласования раздела 11 системных требований | VT-NFR-08: сценарий нагрузки и восстановления определяется вместе с порогами |
| NFR-009 | Совместимость | Файлы экспорта Excel открываются и проходят обратный импорт без потери поддерживаемых данных | Успешное открытие и round-trip в двух последних стабильных версиях Microsoft Excel и актуальной стабильной LibreOffice на дату релиза | VT-NFR-09: тестовая матрица редакторов + сравнение экспорт/импорт |

Связь с архитектурными решениями — см. [145 ADR](../block-h-architecture-and-logic/145.architecture-decisions.md) (ADR-003 безопасность, ADR-005 удаление, ADR-006 кэш справочников, ADR-007 атомарность аудита и уведомлений).
