# 080 — User Stories: руководитель / планировщик

> Формат — см. [`../documents-composition.md`](../documents-composition.md#080--user-stories-080actor-user-storiesmd).
> Источник — [`../vision.md`](../vision.md). Роль — [070 RBAC](070.role-matrix.md), use cases — [060](060.use-cases.md).

**US-L1.** As a руководитель, I want видеть загрузку каждого участника при формировании итерации so that не допустить перегрузку команды.
- GWT-1: Given заданы ёмкости участников и отобраны задачи, When сумма оценок превышает ёмкость участника, Then система показывает перегрузку до запуска итерации.
- GWT-2: Given нагрузка в пределах ёмкости, When я просматриваю сводку, Then вижу свободный резерв по каждому участнику.
*(→ UC-8)*

**US-L2.** As a руководитель, I want декомпозировать крупную задачу на дочерние элементы so that контролировать выполнение по частям.
- GWT-1: Given задача открыта, When я создаю дочерний элемент, Then он появляется в иерархии и в бэклоге с собственными статусом, исполнителем и оценкой.
- GWT-2: Given попытка сделать элемент потомком самого себя, When я подтверждаю связь, Then система отклоняет операцию.
*(→ UC-4)*

**US-L3.** As a руководитель, I want сравнить базовый план итерации с фактом после её завершения so that оценить точность планирования.
- GWT-1: Given итерация была активирована с зафиксированным базовым планом, When итерация завершается, Then система сохраняет сравнение плана и факта по задачам, исполнителям и итерации в целом.
*(→ UC-10)*

**US-L4.** As a руководитель, I want видеть diff каждого изменения карточки so that понимать, что и когда изменилось.
- GWT-1: Given у карточки есть история изменений, When я открываю конкретную запись, Then вижу предыдущие и новые значения с визуальным выделением различий.
*(→ UC-11)*
