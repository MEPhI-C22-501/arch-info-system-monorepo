# 010 — Глоссарий (Ubiquitous Language)

> Назначение: единая терминология предметной области Task Tracker. Формат — см.
> [`../documents-composition.md`](../documents-composition.md#010--глоссарий-ubiquitous-language-010glossarymd).
> Источник — [`../vision.md`](../vision.md), сверено с [`../system-requirements.md`](../system-requirements.md).

Общепрограммные термины («пользователь», «роль», «CRUD») намеренно не включены — только то, что специфично для трекера задач.

| Термин | Определение | Контекст / модуль | Синонимы |
|---|---|---|---|
| Рабочий элемент | Общее название для любой единицы работы одного из пяти типов: Проект, Эпик, Задача, Ошибка, Подзадача. | Ядро домена | Item, карточка |
| Проект | Верхнеуровневая инициатива, объединяющая эпики и через них задачи общей целью. | Иерархия рабочих элементов | — |
| Эпик | Крупный блок работ внутри проекта, декомпозируется на задачи и ошибки. | Иерархия рабочих элементов | Epic |
| Задача | Самостоятельная единица плановой работы с исполнителем, сроками и трудоёмкостью. | Иерархия рабочих элементов | Task |
| Ошибка | Дефект или некорректное поведение, требующее исправления; может создаваться извне сервисом тестирования. | Иерархия рабочих элементов | Bug, дефект |
| Подзадача | Часть задачи или ошибки, выделенная для отдельного выполнения и контроля. | Иерархия рабочих элементов | Subtask |
| Бэклог | Общий упорядоченный список всех рабочих элементов, зарегистрированных в системе. | Планирование | — |
| Канбан-доска | Визуальное представление рабочих элементов в виде колонок, соответствующих статусам. | Исполнение | Kanban |
| Итерация | Ограниченный период выполнения работ с датами, состоянием и составом задач. | Планирование | Спринт |
| Базовый план итерации | Состав задач и суммарная плановая трудоёмкость, зафиксированные в момент перевода итерации в состояние «Активна». | Планирование | Baseline |
| Ёмкость участника | Доступное время участника в часах на период итерации с учётом рабочих дней, отпусков и занятости. | Планирование | Capacity |
| Плановая трудоёмкость | Оценка времени на выполнение исполнимого рабочего элемента, в часах. | Учёт трудозатрат | Estimate |
| Фактическая трудоёмкость | Сумма зарегистрированных записей времени по рабочему элементу. | Учёт трудозатрат | Actual |
| Оставшееся время | `актуальный план − факт`; рассчитывается автоматически, может быть отрицательным (перерасход). | Учёт трудозатрат | Remaining |
| Запись трудозатрат | Отдельная фиксация фактически потраченного времени: дата, часы, автор. | Учёт трудозатрат | Worklog |
| История изменений (аудит) | Хронологическая последовательность записей об изменениях карточки: автор/источник, дата, изменённые поля, старые и новые значения. | Аудит | Audit log |
| Diff-представление | Способ показа записи истории с визуальным выделением добавленных, удалённых и изменённых значений. | Аудит | — |
| Вложение | Файл, прикреплённый к рабочему элементу. | Совместная работа | Attachment |
| Уведомление | Встроенное сообщение пользователю о событии, затрагивающем назначенный ему рабочий элемент. | Совместная работа | Notification |
| Жёсткое удаление | Безвозвратное удаление элемента, комментариев, вложений, трудозатрат и истории; уведомление об удалении сохраняется без ссылки на карточку. | Управление данными | Hard delete |
| Архивирование | Перевод рабочего элемента в завершающий/архивный статус без удаления данных. | Управление данными | Soft delete |
| Обмен через Excel | Экспорт рабочих элементов в файл `.xlsx` и последующий импорт изменённого файла с проверкой структуры и отчётом о результате. | Управление данными | Excel-обмен |
| Сервис тестирования | Внешняя система, создающая рабочие элементы типа «Ошибка» через API по результатам тестовых прогонов. | Интеграции | Test management |
| Сервис отчётности | Внешняя система (подсистема `reports`), потребляющая данные Task Tracker только для чтения. | Интеграции | Reporting |
| Сервис справочников | Внешняя система, предоставляющая сведения о пользователях, командах и подразделениях. | Интеграции | Reference service |
| Внешний идентификатор дефекта | Идентификатор ошибки в системе-источнике (сервисе тестирования), используемый для дедупликации при повторных запросах. | Интеграции | External defect ID |
| Идемпотентность | Свойство операции: повторный вызов с теми же данными не создаёт дубликат и не меняет результат. | Интеграции | — |
| Корреляционный идентификатор | Сквозной ID запроса для трассировки интеграционных вызовов. | Интеграции / наблюдаемость | Correlation ID, trace ID |

## Смежные термины (после согласования с другими модулями)

- `Catalog` / `CatalogItem` (Reference Manager, см. `../../../reference-manager/README.md`) — потенциальный источник записей о пользователях/командах, но по текущему README этого модуля не подтверждён как их владелец.
- `Отчёт`, `Показатель`, `Разрез`, `Витрина отчётности` (Reports, см. `../../../reports/README.md`) — термины смежного модуля, использующего наши данные.
