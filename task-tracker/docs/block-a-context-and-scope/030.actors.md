# 030 — Акторы

| Актор | Цели и права |
|---|---|
| Участник команды | Свои задачи, статусы, трудозатраты, комментарии, файлы и уведомления |
| Руководитель / планировщик | Бэклог, операционные задачи и итерации, ёмкость, план-факт; плановые поля связанных задач ведёт Planning System |
| Администратор | Статусы, приоритеты, доступ, права, синхронизация справочников и восстановление outbox |
| Planning System | Публикует проекты/эпики и версионированные плановые рамки; читает факт и историю; роль `planning-service` |
| Управление тестированием и качеством (`qa`) | Создаёт дефекты идемпотентно, читает задачи и итерации; роль `testing-service` |
| Reports | Первичное и пакетное чтение факта, применение событий к витрине; роль `reports-service` |
| Reference Manager | Поставщик сотрудников и оргструктуры; Task Tracker инициирует постраничный опрос |
| Keycloak | OIDC/OAuth 2.0, учётные записи и JWT; HR-профили остаются в Reference Manager |
| Infra | Общие Keycloak, Kafka, MinIO, сеть, CI и локальный Kubernetes |

Сервисным клиентам не предоставляется человеческий допуск: роли разрешают только нужные интеграционные API. Внешний контекст — [020](020.system-context.md), права — [070](../block-c-requirements-and-roles/070.role-matrix.md), согласования — [162](../block-i-integration-and-deployment/162.integration-spec.md).
