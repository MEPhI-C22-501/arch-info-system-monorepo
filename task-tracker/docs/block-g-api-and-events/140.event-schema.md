# 140 — Схемы событий

Целевая проектная схема; новые интеграционные компоненты описаны для согласования и последующей реализации по плану 160.

Машиночитаемый источник — [event-schemas.json](event-schemas.json); каталог — [135](135.event-catalog.md). Версия — v1 local draft. Прежний комплект описывал внутренние события; потребители ещё не подтвердили внешний wire-contract, поэтому изменения payload не объявляются совместимыми с уже работающей внешней интеграцией.

Envelope: eventId (UUID), eventType, aggregateId, occurredAt (RFC3339 UTC), correlationId, actor и payload. Обязательность и типы заданы JSON Schema; null допускается только в nullable ссылках. Kafka key — aggregateId: UUID элемента/итерации, `directory` для кэша, UUID пакета для импорта. Для одного ключа outbox не обходит более раннее pending/DEAD событие.

| eventType | Обязательные поля payload |
|---|---|
| `WorkItemCreated` | type, title, statusId, priorityId |
| `WorkItemFieldsChanged` | changedFields, oldValues, newValues, version |
| `AssigneeChanged` | oldAssigneeId, newAssigneeId |
| `StatusChanged` | fromStatusId, toStatusId |
| `HierarchyChanged` | oldParentId, newParentId |
| `CommentChanged` | commentId, operation |
| `TimeLogged` | timeLogId, userId, hours, loggedDate |
| `AttachmentChanged` | attachmentId, operation, fileName |
| `IterationCompositionChanged` | iterationId, operation, workItemId |
| `IterationActivated` | iterationId, baselineVersion, baseline |
| `IterationCompleted` | iterationId, resultVersion, result |
| `WorkItemHardDeleted` | workItemId, title, type |
| `BugCreatedFromTesting` | externalSource, externalDefectId, workItemId |
| `DirectorySynchronized` | version, users |
| `ExcelImportCompleted` | created, updated, rejected |
| `NotificationCreated` | notificationId, recipientId, changeKind |
| `PlanApplied` | externalProjectId, version |
| `ProjectRetired` | externalProjectId, version |

Пример события:

```json
{"eventId":"11111111-1111-1111-1111-111111111111","eventType":"TimeLogged","aggregateId":"22222222-2222-2222-2222-222222222222","occurredAt":"2026-10-05T09:00:00Z","correlationId":"example-request","actor":"member","payload":{"timeLogId":"33333333-3333-3333-3333-333333333333","userId":"member","hours":2.5,"loggedDate":"2026-10-05"}}
```

Доставка at-least-once; eventId не меняется при повторе. WorkItemFieldsChanged несёт версию карточки и diff, TimeLogged — одну запись первичного факта; обработчик выбирает один источник учёта и дедуплицирует его. Внутренний NotificationCreated отделяется по eventType. Retirement не является hard delete. После утверждения контракта новые необязательные поля допускаются в v1, удаление/переименование/изменение семантики требует v2 и отдельного topic; неизвестный eventType потребитель должен сохранять в своей DLQ, не падать бесконечно.
