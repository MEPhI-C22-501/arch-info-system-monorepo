# 140 — Event Schema

> Формат — см. [`../documents-composition.md`](../documents-composition.md#140--event-schema-140event-schemamd).
> Каталог событий — [135](135.event-catalog.md).

Пример схем для двух наиболее значимых внутренних событий (JSON Schema); остальные события каталога [135](135.event-catalog.md) следуют тому же шаблону (`workItemId`, временная метка, поле-специфичная нагрузка).

```json
{
  "$id": "StatusChanged.v1",
  "type": "object",
  "required": ["workItemId", "fromStatusId", "toStatusId", "changedBy", "occurredAt"],
  "properties": {
    "workItemId": { "type": "string", "format": "uuid" },
    "fromStatusId": { "type": "string", "format": "uuid" },
    "toStatusId": { "type": "string", "format": "uuid" },
    "changedBy": { "type": "string", "description": "внешний ID пользователя или имя внешнего источника" },
    "occurredAt": { "type": "string", "format": "date-time" }
  }
}
```

```json
{
  "$id": "BugCreatedFromTesting.v1",
  "type": "object",
  "required": ["workItemId", "externalSource", "externalDefectId", "severity", "occurredAt"],
  "properties": {
    "workItemId": { "type": "string", "format": "uuid" },
    "externalSource": { "type": "string", "example": "test-management" },
    "externalDefectId": { "type": "string" },
    "severity": { "type": "string", "enum": ["low", "medium", "high", "critical"] },
    "occurredAt": { "type": "string", "format": "date-time" }
  }
}
```

**Партиционирование:** при вынесении событий во внешнюю шину — предполагаемый partition key `workItemId` (гарантирует порядок событий одного рабочего элемента). **Версионирование:** суффикс `.v1` в `$id`; обратно совместимые изменения — новые опциональные поля; несовместимые — новая версия схемы.
