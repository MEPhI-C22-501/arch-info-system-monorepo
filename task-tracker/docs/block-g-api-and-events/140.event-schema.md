# 140 — Event Schema

> Формат — см. [`../documents-composition.md`](../documents-composition.md#140--event-schema-140event-schemamd).
> Каталог событий — [135](135.event-catalog.md).

Нормативная машиночитаемая схема находится в [`event-schemas.json`](event-schemas.json). Она содержит `oneOf` и отдельный `$defs` для каждого события каталога. Ниже показана общая оболочка; таблица служит кратким индексом payload, а не заменой JSON Schema.

```json
{
  "$id": "TaskTrackerDomainEvent.v1",
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["eventId", "eventType", "aggregateId", "occurredAt", "correlationId", "actor", "payload"],
  "properties": {
    "eventId": { "type": "string", "format": "uuid" },
    "eventType": { "type": "string", "enum": ["WorkItemCreated", "WorkItemFieldsChanged", "AssigneeChanged", "StatusChanged", "HierarchyChanged", "CommentChanged", "TimeLogged", "AttachmentChanged", "IterationCompositionChanged", "IterationActivated", "IterationCompleted", "WorkItemHardDeleted", "BugCreatedFromTesting", "DirectorySynchronized", "ExcelImportCompleted", "NotificationCreated"] },
    "aggregateId": { "type": "string", "description": "UUID агрегата либо версия directory snapshot" },
    "occurredAt": { "type": "string", "format": "date-time" },
    "correlationId": { "type": "string" },
    "actor": { "type": "string", "description": "Внешний ID пользователя или сервисный источник" },
    "payload": { "type": "object", "additionalProperties": true }
  },
  "additionalProperties": false
}
```

| `eventType` | Обязательные поля `payload` | Пример смысла |
|---|---|---|
| `WorkItemCreated` | `type`, `title`, `statusId`, `priorityId` | создана задача |
| `WorkItemFieldsChanged` | `changedFields`, `oldValues`, `newValues` | изменён срок |
| `AssigneeChanged` | `oldAssigneeId`, `newAssigneeId` | переназначение |
| `StatusChanged` | `fromStatusId`, `toStatusId` | переход на проверку |
| `HierarchyChanged` | `oldParentId`, `newParentId` | перенос под другой эпик |
| `CommentChanged` | `commentId`, `operation` | `created`/`updated`/`deleted` |
| `TimeLogged` | `timeLogId`, `hours`, `loggedDate` | зарегистрировано 2.5 часа |
| `AttachmentChanged` | `attachmentId`, `operation`, `fileName` | файл добавлен/удалён |
| `IterationCompositionChanged` | `iterationId`, `operation`, `workItemId` | элемент включён/исключён |
| `IterationActivated` | `iterationId`, `baselineVersion` | baseline зафиксирован |
| `IterationCompleted` | `iterationId`, `resultVersion` | plan-fact сохранён |
| `WorkItemHardDeleted` | `workItemPublicId`, `workItemTitle`, `recipientId` | уведомление возможно без FK |
| `BugCreatedFromTesting` | `externalSource`, `externalDefectId`, `severity` | внешний дефект принят |
| `DirectorySynchronized` | `directoryVersion`, `userCount`, `teamCount`, `departmentCount` | кэш обновлён |
| `ExcelImportCompleted` | `created`, `updated`, `rejected`, `reportId` | импорт завершён |
| `NotificationCreated` | `notificationId`, `recipientId`, `changeKind` | уведомление записано |

`null` допустим для old/new ссылок только там, где связь создаётся или удаляется. Семантика, обязательность и пример каждого поля заданы таблицей; типы идентификаторов — string/UUID, счётчиков — integer ≥ 0, `hours` — number ≥ 0, дат — ISO 8601.

**Партиционирование:** не применяется, поскольку внешней шины нет. Если Kafka будет утверждена отдельным ADR, candidate partition key — `aggregateId`, чтобы сохранить порядок одного агрегата. **Версионирование:** суффикс `.v1` в `$id`; новые опциональные поля обратно совместимы, удаление/переименование поля требует `.v2`. Forward compatibility для неизвестных `eventType` не гарантируется внутри одной major-версии.
