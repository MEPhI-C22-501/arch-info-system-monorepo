# 135 — Каталог событий

Оболочка и payload — [140](140.event-schema.md), [JSON Schema](event-schemas.json). При согласовании варианта Kafka предлагается записывать события в transactional outbox вместе с изменением и отправлять после commit. Контракт внешнего потребления остаётся draft до DEC-TT-02 в [162](../block-i-integration-and-deployment/162.integration-spec.md).

Topic: `task-tracker.events.v1`; partition key: aggregateId. Подписчики бизнес-событий — Reports/Planning System после согласования; техническое NotificationCreated не следует учитывать как изменение фактических часов. Повторная доставка допустима, потребитель дедуплицирует eventId.

| Событие | Издатель | Триггер / смысл | Критичность |
|---|---|---|---|
| `WorkItemCreated` | Рабочие элементы | Успешное изменение; payload: type, title, statusId, priorityId | Высокая |
| `WorkItemFieldsChanged` | Рабочие элементы | Успешное изменение; payload: changedFields, oldValues, newValues, version | Высокая |
| `AssigneeChanged` | Рабочие элементы | Успешное изменение; payload: oldAssigneeId, newAssigneeId | Высокая |
| `StatusChanged` | Рабочие элементы | Успешное изменение; payload: fromStatusId, toStatusId | Высокая |
| `HierarchyChanged` | Рабочие элементы | Успешное изменение; payload: oldParentId, newParentId | Высокая |
| `CommentChanged` | Рабочие элементы | Успешное изменение; payload: commentId, operation | Высокая |
| `TimeLogged` | Рабочие элементы | Успешное изменение; payload: timeLogId, userId, hours, loggedDate | Высокая |
| `AttachmentChanged` | Рабочие элементы | Успешное изменение; payload: attachmentId, operation, fileName | Высокая |
| `IterationCompositionChanged` | Итерации | Успешное изменение; payload: iterationId, operation, workItemId | Высокая |
| `IterationActivated` | Итерации | Успешное изменение; payload: iterationId, baselineVersion, baseline | Критичная |
| `IterationCompleted` | Итерации | Успешное изменение; payload: iterationId, resultVersion, result | Критичная |
| `WorkItemHardDeleted` | Рабочие элементы | Успешное изменение; payload: workItemId, title, type | Критичная |
| `BugCreatedFromTesting` | Интеграция | Успешное изменение; payload: externalSource, externalDefectId, workItemId | Высокая |
| `DirectorySynchronized` | Интеграция | Успешное изменение; payload: version, users | Высокая |
| `ExcelImportCompleted` | Интеграция | Успешное изменение; payload: created, updated, rejected | Высокая |
| `NotificationCreated` | Уведомления | Успешное изменение; payload: notificationId, recipientId, changeKind | Высокая |

| `ProjectRetired` | Планирование | Успешное изменение; payload: externalProjectId, version | Высокая |

Создание итерации и установка ёмкости пока внутренние шаги без отдельных событий, явно отмечены в 040. Общий WorkItemFieldsChanged и уточняющие события описывают одно изменение; нельзя суммировать часы по обоим. DEAD событие сохраняется в БД, блокирует агрегат до admin replay; копия в `.dlq` доставляется по возможности. Срок хранения и ACL топиков подтверждает Infra.
