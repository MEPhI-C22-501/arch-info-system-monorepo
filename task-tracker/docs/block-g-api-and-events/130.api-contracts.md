# 130 — Контракты API

Проектная спецификация HTTP-маршрутов: [OpenAPI 1.1.0-draft](openapi.yaml). Файл содержит 58 операций: параметры, запросы, ответы, примеры и ошибки. Новые интеграционные маршруты — draft, предлагаемый для согласования; их описание не означает наличия реализации в этом коммите.

## Аутентификация и права

Пользователи входят через Keycloak Authorization Code + PKCE. Backend проверяет подпись JWKS, issuer, audience `task-tracker`, срок действия JWT; локальный допуск и права проверяются сервером. Сервисные роли `testing-service`, `reports-service`, `planning-service` не дают пользовательский доступ. Клиентские секреты передаются только серверным клиентам.

Testing создаёт ошибки через `POST /api/v1/bugs`: уникальна пара `externalSource/externalDefectId`, первый ответ 201, повтор 200 без создания дубликата. Testing, Reports и Planning читают справочники и отчётные выгрузки. История доступна через `/reports/history`; персональные поля требуют согласованных прав потребителей (DEC-TT-02/DEC-TT-06).

## Planning

`PUT /api/v1/planning/projects/{externalId}` публикует проект, эпики и задачи одной транзакцией. `version` — возрастающее положительное число. Повтор идентичного документа возвращает `already-applied`; другой документ с той же версией и устаревшая версия дают 409. `localWorkItemId` позволяет явно привязать существующий элемент подходящего типа; привязка впоследствии неизменна.

Planning владеет названием, иерархией, исполнителем, датами и оценкой связанных задач; Task Tracker — статусом, приоритетом, описанием, итерацией и фактом. Связанные проекты и эпики доступны только для чтения. Исключение задачи из следующего документа не удаляет её. `DELETE ...?version=N` прекращает публикацию, сохраняя задачи и историю. `GET .../facts` возвращает проектную выгрузку.

Excel сохраняет эти границы: неизменённые проекты/эпики пропускаются, операционные поля связанных задач можно импортировать; изменение плановых полей отклоняет весь импорт. Версии карточек проверяются.

## Reports и события

`/reports/work-items`, `/reports/time-logs`, `/reports/history`, `/reports/iterations` используют `page/pageSize` (максимум 500), период, проект и исполнителя. Один запрос читает согласованный snapshot PostgreSQL; последовательность страниц не является общим snapshot. Для длительного ETL необходимы повторная сверка и дедупликация Kafka по `eventId`.

События записываются в outbox вместе с доменными изменениями. Доставка в `task-tracker.events.v1` — at least once, ключ `aggregateId`; порядок сохраняется внутри агрегата. После исчерпания повторов DEAD блокирует следующие события агрегата, доступен ручной replay с тем же `eventId`; DLQ — дополнительная доставка, основное состояние ошибки хранится в БД. См. [каталог](135.event-catalog.md) и [JSON Schema](event-schemas.json).

## Reference Manager и Infra

HTTP-клиент читает `/v1/employees` и `/v1/org_units` с пагинацией `page_size/next_page_token`, `show_deleted`, `order_by=name`. `account_user_id` сопоставляется с JWT sub; employee resource name хранится отдельно. Полная валидная выборка заменяет кеш атомарно; сбой сохраняет предыдущий кеш. URL, токен, enum и политика деактивации требуют DEC-TT-03.

Вложения хранятся в приватном MinIO bucket. Legacy bytea переносится с проверкой SHA-256, после удаления метаданных объект удаляется очередью. Ошибки S3 возвращают 503 без внутренних адресов и секретов.

[Спецификация интеграций и открытые соглашения](../block-i-integration-and-deployment/162.integration-spec.md) фиксирует владельцев, критерии и внешние зависимости. Draft требует согласования соседними командами до реализации.
