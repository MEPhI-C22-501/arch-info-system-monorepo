# 130 — Контракты API

Проектная спецификация HTTP-маршрутов: [OpenAPI 1.1.0-draft](openapi.yaml). Файл содержит 58 операций: параметры, запросы, ответы, примеры и ошибки. Новые интеграционные маршруты — draft, предлагаемый для согласования; их описание не означает наличия реализации в этом коммите.

## Аутентификация и права

Ответ `GET /api/v1/work-items/{id}` содержит `parentLink` с ID и названием родителя, если читатель может открыть его карточку. Блок «Иерархия» использует это поле для навигации. Для элемента без родителя и для недоступного родителя интерфейс показывает соответствующий текст без ссылки.

В `GET /api/v1/work-items/{id}/history` поля `oldValues` и `newValues` возвращаются JSON-объектами. Поле `relatedItems` содержит названия родительских и дочерних карточек, доступных читателю. В новых событиях вложений `attachmentName` сохраняет имя файла на момент изменения. Связи записываются в историю обоих участников.

Пользователи входят через Keycloak Authorization Code + PKCE. Backend проверяет подпись JWKS, issuer, audience `task-tracker`, срок действия JWT; client roles Keycloak и права проверяются сервером. Локального источника назначений ролей нет. Сервисные роли `testing-service`, `reports-service`, `planning-service` не дают пользовательский доступ. Клиентские секреты передаются только серверным клиентам.

Testing создаёт ошибки через `POST /api/v1/bugs`: уникальна пара `externalSource/externalDefectId`, первый ответ 201, повтор 200 без создания дубликата. Reports читает общие отчётные выгрузки. Planning читает факт по опубликованному проекту через свой маршрут. История доступна через `/reports/history`; персональные поля требуют согласованных прав потребителей (DEC-TT-02/DEC-TT-06).

## Planning

`PUT /api/v1/planning/projects/{externalId}` публикует проект, эпики и задачи одной транзакцией. `version` — возрастающее положительное число. Повтор идентичного документа возвращает `already-applied`; другой документ с той же версией и устаревшая версия дают 409. `localWorkItemId` позволяет явно привязать существующий элемент подходящего типа; привязка впоследствии неизменна.

Локальные проекты и эпики разрешены независимо от интеграции. Только явная привязка externalId/localWorkItemId передаёт владение плановыми полями Planning. Совпадение имён не объединяет элементы. Planning владеет названием, иерархией, исполнителем, датами и оценкой связанных задач; Task Tracker — статусом, приоритетом, описанием, итерацией и фактом. Связанные проекты и эпики доступны только для чтения. Исключение задачи из следующего документа не удаляет её. `DELETE ...?version=N` прекращает публикацию, сохраняя задачи и историю. `GET .../facts` возвращает проектную выгрузку.

Excel сохраняет эти границы: неизменённые проекты/эпики пропускаются, операционные поля связанных задач можно импортировать; изменение плановых полей отклоняет весь импорт. Версии карточек проверяются.

## Reports и события

`/reports/work-items`, `/reports/time-logs`, `/reports/history`, `/reports/iterations` используют `page/pageSize` (максимум 500), период, проект и исполнителя. Один запрос читает согласованный snapshot PostgreSQL; последовательность страниц не является общим snapshot. Для длительного ETL необходимы повторная сверка и дедупликация Kafka по `eventId`.

События записываются в outbox вместе с доменными изменениями. Доставка в `task-tracker.events.v1` — at least once, ключ `aggregateId`; порядок сохраняется внутри агрегата. После исчерпания повторов DEAD блокирует следующие события агрегата, доступен ручной replay с тем же `eventId`; DLQ — дополнительная доставка, основное состояние ошибки хранится в БД. См. [каталог](135.event-catalog.md) и [JSON Schema](event-schemas.json).

## Reference Manager и Infra

HTTP-клиент читает `/v1/employees` и `/v1/org_units` с пагинацией `pageSize`/`pageToken` (без total), фильтром удалённых `allowDeleted`. Профили читаются через `/v1/profiles`; `userId` связывает их с JWT sub. Учётная запись и кадровый статус не заменяют роли доступа. Полная валидная выборка заменяет кеш атомарно; сбой сохраняет предыдущий кеш. URL, токен, enum и политика деактивации требуют DEC-TT-03 ([подробнее](../block-i-integration-and-deployment/162.integration-spec.md#reference-manager)).

Вложения хранятся в приватном MinIO bucket. Legacy bytea переносится с проверкой SHA-256, после удаления метаданных объект удаляется очередью. Ошибки S3 возвращают 503 без внутренних адресов и секретов.

[Спецификация интеграций и открытые соглашения](../block-i-integration-and-deployment/162.integration-spec.md) фиксирует владельцев, критерии и внешние зависимости. Draft требует согласования соседними командами до реализации.

## Уточнение реализации 22.11.2026

Planning API реализован миграцией 003 и PlanningController. Снятие публикации требует версии больше текущей; повтор снятия с той же версией идемпотентен. Привязки сохраняются после retirement: автоматической передачи владения трекеру нет. Отсутствующие в следующем пакете элементы не удаляются. Проекты/эпики остаются доступными для локального создания. Серверная защита плановых полей распространяется также на bulk и Excel.

Сортировка бэклога поддерживает `dueDate`, `priority`, `status`, `type`, `assignee`, `iteration`, `createdAt`; сортировка исполнителя использует отображаемое имя. Отчётные GET-запросы используют REPEATABLE READ в пределах одного запроса.
