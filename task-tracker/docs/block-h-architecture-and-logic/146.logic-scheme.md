# 146 — Logic Scheme

> Формат — см. [`../documents-composition.md`](../documents-composition.md#146--logic-scheme-146logic-schememd).
> Детализация компонентов — [150](150.component-diagram.md).

```mermaid
flowchart TB
    UI["Веб-клиент (React)"] -->|REST + токен| API["API-слой (Spring Boot)"]

    subgraph Domain["Прикладные сервисы"]
        WI["Модуль рабочих элементов"]
        IT["Модуль итераций и ёмкости"]
        COL["Модуль совместной работы: комментарии, вложения"]
        AUD["Модуль аудита"]
        NOT["Модуль уведомлений"]
        INT["Интеграционный модуль"]
    end

    API --> WI
    API --> IT
    API --> COL
    API --> NOT
    WI --> AUD
    IT --> AUD
    COL --> AUD
    AUD --> NOT

    WI --> DB[("База данных")]
    IT --> DB
    COL --> DB
    AUD --> DB
    NOT --> DB

    API -->|проверка токена| KC["Keycloak"]
    Tests["Сервис тестирования"] -->|REST, синхронно| INT
    INT --> WI
    API -->|REST, синхронно, только чтение| Reports["Сервис отчётности"]
    INT -->|REST, синхронно, по расписанию| Refs["Сервис справочников"]
```

Все внешние взаимодействия — синхронные REST-вызовы (авторизация через Keycloak на каждый запрос, вызов сервиса тестирования — входящий, вызов сервиса отчётности — исходящий ответ, синхронизация справочников — исходящий вызов по расписанию). Асинхронного обмена через шину сообщений в границах модуля на сегодня нет (см. [ADR-004](145.architecture-decisions.md)).
