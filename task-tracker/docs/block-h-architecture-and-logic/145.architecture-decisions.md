# 145 — Архитектурные решения

Предложения внешних контрактов и альтернативы — [162](../block-i-integration-and-deployment/162.integration-spec.md). Эти ADR фиксируют проектные решения; внешние контракты и выбор шины требуют согласования до реализации.

| ADR | Контекст | Решение | Последствия / требования |
|---|---|---|---|
| ADR-001 | Пять типов образуют одну иерархию | WORK_ITEM с type и parent_id | Общий CRUD и агрегации; валидация типов/циклов; NFR-001/005 |
| ADR-002 | Нужны уведомления исполнителю | Встроенные уведомления | Не нужен внешний канал; пользователь читает их в UI; NFR-004 |
| ADR-003 | Единый вход принят в проекте | Keycloak OIDC/PKCE и локальная JWT/JWKS-проверка issuer, exp, audience; серверные права | Нет своих паролей; требуется обновление ключей и контроль срока JWT; NFR-003 |
| ADR-004 | Reports ожидает изменения, bootstrap и сверку | Kafka для изменений, REST для чтения/пакетного ETL | Брокер и обработка дублей; исключение Kafka не согласовано; DEC-TT-02/06 |
| ADR-005 | Архив и hard delete имеют разный смысл | Подтверждённый hard delete только без детей и planning binding | Зависимости удаляются атомарно; snapshot уведомления и outbox сохраняются; NFR-005 |
| ADR-006 | Оргданные принадлежат Reference Manager | Постраничный опрос employees/org_units, локальный кэш | Не редактируем HR-данные; при сбое предыдущая версия; NFR-001/006 |
| ADR-007 | Изменение, аудит, уведомление и публикация не должны расходиться | Одна транзакция БД включает изменение/аудит/уведомление/outbox; Kafka после commit | At-least-once: дубли возможны между ACK Kafka и commit БД; дедупликация у потребителя; NFR-001/002/004 |
| ADR-008 | Матрица обмена требует проекты из Planning System | Planning System — предлагаемый мастер проектов/эпиков/плана, локальные проекции в трекере | Явные внешние ID и версии; существующие записи привязываются вручную; DEC-TT-01 |
| ADR-009 | Файлы должны храниться в S3 | MinIO, метаданные и SHA-256 в БД, reservation/cleanup worker | Нет общей транзакции S3+БД; повторяемая очистка и проверяемая миграция; NFR-001/005 |
| ADR-010 | Нужна воспроизводимая учебная среда | Compose для разработки, локальный Kubernetes для финального стенда | Single-node сервисы не обещают HA; thresholds/backup утверждаются с Infra; NFR-008 |

ADR-004/008 имеют статус предложений; DEC-TT-01/02/06 ожидают письменного подтверждения. Пороговые значения production/SLO не назначаются без измерения и согласования.
