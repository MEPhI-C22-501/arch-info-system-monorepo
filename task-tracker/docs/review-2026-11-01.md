## Публичные дополнения

`POST /api/v1/work-items/bulk`: `{operation: "status"|"assignee"|"iteration", value, items:[{id,version}]}`. Пустое назначение/итерация передаётся как null. Ответ `{results:[{id,success,version? ,status?,errors?}]}`. Ошибки отдельных карточек не откатывают другие. Повторять следует только ошибки, после обновления версии карточки.

`GET/POST /api/v1/work-items/{id}/links`, `DELETE .../links/{linkId}`. Создание принимает `{targetId,type}`. RELATED симметричен; BLOCKS направлен и не допускает циклов. Связи не меняют правила переходов статусов.

`GET /api/v1/admin/outbox` и `POST .../{id}/retry` доступны по access.admin. DEAD блокирует последующие события того же агрегата. Публикация at-least-once, потребитель дедуплицирует eventId. Копия DLQ в Kafka не создаётся: в общей инфраструктуре топик/ACL для неё пока не выданы. DB является источником повторной доставки.

## Настройка интеграций

Standalone: `docker compose -f compose.yaml -f compose.integrations.yaml up --build -d`.

Для общей среды передаются KAFKA_BOOTSTRAP_SERVERS, KAFKA_SECURITY_PROTOCOL, KAFKA_SASL_JAAS_CONFIG, KAFKA_SSL_TRUSTSTORE_LOCATION, KAFKA_SSL_TRUSTSTORE_PASSWORD. Не помещать настоящие секреты в git. Topic: task-tracker.events.v1. Контракт остаётся local draft до подтверждения потребителями; внутренние изменения нормализуются в WorkItemFieldsChanged, время публикуется отдельным TimeLogged.

S3_ENDPOINT включает объектное хранилище; S3_BUCKET по умолчанию arch-dev-task-tracker; S3_ACCESS_KEY/S3_SECRET_KEY — только серверу. Без S3_ENDPOINT сохраняется bytea-режим. Если объект уже перенесён, отключение S3 не возвращает его в БД: для чтения требуется восстановить доступ к бакету. Миграция удаляет bytea только после скачивания и проверки SHA-256. Удаление карточки ставит объекты в очередь через DB trigger. Незавершённые загрузки очищаются через час.

DIRECTORY_URL теперь означает корень сервиса, без /v1 и имени коллекции; DIRECTORY_TOKEN — токен reader. Переход со старого snapshot URL требует изменения конфигурации. Ошибка чтения оставляет предыдущую проекцию.

## Внешние зависимости и ограничения

- Контракт владения планом с Planning и внешний wire-contract событий не подписаны; эта ветка не подменяет решения обеих команд.
- Включение новых проверок в корневой CI и публикация образов остаются задачей общего репозитория.
- Общего сервиса рассылок и общего пакета компонентов нет; работают встроенные уведомления и локальные компоненты.
- Сквозной приём данных QA/Reports/Planning нельзя считать доказанным тестом поставщика или наличием API.
- Автоматические браузерные сценарии запускаются отдельно через `npm run test:e2e` против выделенного стенда.

## Результаты проверки ветки

- Maven test + Checkstyle: 58 тестов, без ошибок и пропусков, включая PostgreSQL, реальную отправку в Kafka и S3-совместимый сервер Moto.
- Frontend lint, 6 unit-тестов и production build проходят.
- Playwright: четыре сценария на desktop/mobile проходят с реальным Keycloak и отдельной чистой БД.
- Liquibase 001 + 002 проверены запуском Spring Boot на новой БД; рабочая демо-БД не изменялась.
- Оба Compose-файла проходят config --quiet. Runtime MinIO из образа Infra отдельно не подтверждён: его исходная сборка требует загрузки Go-зависимостей; S3-протокол проверен на Moto.
- Внешние системы-потребители и их ACL не проверялись; штатный SASL_SSL-профиль общего Kafka не заменён локальным PLAINTEXT-профилем.

Для запуска внешних протокольных тестов задайте TRACKER_KAFKA_TEST_BOOTSTRAP и TRACKER_S3_TEST_ENDPOINT (только выделенные тестовые ресурсы); без них соответствующие два теста пропускаются.
