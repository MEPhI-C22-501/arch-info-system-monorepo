# Восстановление базы Task Tracker без журнала Liquibase

Ошибка `relation "status" already exists` возникает, если таблицы Task Tracker существуют, а в `databasechangelog` нет записи о применении `001-initial`. Обычный запуск на чистой базе применяет все миграции. Для пустого демостенда можно переключиться на новый том по [инструкции запуска](../../README.md#база-без-журнала-liquibase).

## База с пользовательскими записями

1. Остановите запись в БД и снимите резервную копию `pg_dump -Fc`. Восстановите её в отдельную базу и сначала выполните процедуру на копии.
2. Для эталона создайте отдельную пустую PostgreSQL той же версии и примените [001-initial.sql](../../backend/src/main/resources/db/changelog/001-initial.sql). Сравните схему `public` старой БД и эталона с помощью `pg_dump --schema-only --schema=public --no-owner --no-privileges`. Сверьте также справочники и настройки, которые вставляет 001. При расхождении требуется установить, какие миграции реально применялись, и разбирать отличия до проставления отметок.
3. Для схемы, точно соответствующей 001, выполните команды из `task-tracker/backend/src/main/resources` с Liquibase 5.0.3. Добавьте PostgreSQL JDBC-драйвер в classpath CLI. Подключение к копии настройте через `LIQUIBASE_COMMAND_URL`, `LIQUIBASE_COMMAND_USERNAME` и `LIQUIBASE_COMMAND_PASSWORD`. Сначала проверьте сгенерированный SQL. В `databasechangelog` должны попасть только `001-initial` и `baseline-001`.

   ```sh
   liquibase changelog-sync-to-tag-sql --changelog-file=db/changelog/db.changelog-master.yaml --tag=task-tracker-001
   liquibase changelog-sync-to-tag --changelog-file=db/changelog/db.changelog-master.yaml --tag=task-tracker-001
   ```

4. Запустите текущий backend на копии. Он применит миграции 002–004. Проверьте HTTP 200 на `/actuator/health`, наличие записей в `databasechangelog` и сохранность рабочих элементов. После проверки повторите на исходной базе при остановленной записи.

Проверка `ReviewIntegrationTest.baselinePreservesDataInAnExactInitialSchemaWithoutMigrationHistory` выполняет отметку и последующие миграции на PostgreSQL, сверяет сохранность записи и итоговую схему. Миграция 004 удаляет `local_access`. Backend использует JWT для назначения ролей и таблицу `role_permission` для разрешений роли.
