# 160 — План интеграций

Решения и открытые согласования — [162](162.integration-spec.md). Вехи задают порядок, не вымышленные календарные даты.

| Веха | Результат | Веха модуля |
|---|---|---|
| И-M1 | Контекст, владельцы данных, предложения 162 | M1–M3: анализ и проектирование |
| И-M2 | Подтверждённые контракты и пороги качества | M3: фиксация контрактов до межкомандной приёмки |
| И-M3 | Контрактный стенд и интеграционные тесты | M4: реализация и локальная проверка |
| И-M4 | Совместный стенд, отказоустойчивость и восстановление | M5: сквозная проверка |
| И-M5 | Локальный Kubernetes, чистый запуск, отчёт и выпуск | M5: сдача |

| Интеграция | Тип / протокол | Порядок | Ответственные Task Tracker / контрагент | Критерий |
|---|---|---|---|---|
| Keycloak | OIDC/OAuth 2.0, JWKS | И-M1 → И-M3 | Task Tracker / Infra | Общий issuer/client, неверный JWT 401, недостаточные права 403 |
| Planning System | Входящий PUT/DELETE плана; исходящий факт через REST/Kafka | И-M2 → И-M3 → И-M4 | Task Tracker / Planning System | Подтверждены владение и wire-contract; повторы/версии/retirement проверены |
| QA | POST bugs, read-only REST | И-M2 → И-M3 | Task Tracker / QA | Дедупликация, согласованный severity mapping; проверены потребности чтения и вех |
| Reports | Kafka + REST, пакетный ETL у потребителя | И-M2 → И-M4 | Task Tracker / Reports + Infra | Bootstrap и сверка без двойного учёта; удаление и replay; формат ETL подтверждён |
| Reference Manager | Исходящий REST по коллекциям | И-M2 → И-M4 | Task Tracker / Reference Manager | account_user_id и активность подтверждены, все страницы до commit, fallback при сбое |
| MinIO | S3, приватный бакет | И-M3 → И-M4 | Task Tracker / Infra | ACL/секреты общего стенда, миграция bytea, SHA-256 и очистка после удаления |
| Kafka | Outbox, at-least-once, DLQ | И-M3 → И-M4 | Task Tracker / Infra + потребители | Топики/ACL, порядок агрегата, дубли, отказ и ручной replay |
| Kubernetes и CI | GitHub Actions, контейнеры, manifests | И-M4 → И-M5 | Task Tracker / Infra | Образы с версией, probes/PVC/маршрутизация, запуск и восстановление с нуля |

Backend/frontend, Compose, миграции, seed и контрактные проверки дорабатываются на И-M3. Этот коммит содержит документацию, а не результаты технического этапа. До И-M2 не закрываются DEC-TT-01…07; до И-M5 сохраняются фактические результаты проверок и отклонения. Публикация образов и применение manifests к чужому кластеру выполняются ответственными после выдачи доступа.
