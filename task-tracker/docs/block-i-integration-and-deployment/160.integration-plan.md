# 160 — Integration Plan

> Формат — см. [`../documents-composition.md`](../documents-composition.md#160--integration-plan-160integration-planmd).
> Сценарии интеграций — [155](155.sequence-diagrams.md).

| Интеграция | Тип / протокол | Порядок реализации | Ответственные (Task Tracker / внешняя сторона) | Критерии готовности |
|---|---|---|---|---|
| Keycloak (аутентификация) | OpenID Connect | 1 — без неё недоступны любые защищённые операции | Task Tracker: Auth Client / Infra: развёртывание Keycloak | Токен проверяется на каждом запросе; недействительный токен отклоняется |
| Сервис тестирования (входящий API создания ошибок) | REST, сервисная аутентификация | 2 | Task Tracker: Integration Service / команда сервиса тестирования | Повторный запрос с тем же внешним ID не создаёт дубликат; ошибки валидации структурированы |
| Сервис отчётности (исходящий read-only API) | REST, сервисная аутентификация, пагинация | 3 | Task Tracker: Integration Service / команда `reports` | Фильтры по периоду/проекту/итерации/типу/статусу/исполнителю работают; ответ пагинируется |
| Сервис справочников (исходящий, синхронизация) | REST, периодический опрос + ручной запуск | 3 (параллельно с отчётностью) | Task Tracker: Integration Service / владелец сервиса справочников — не подтверждён, см. `../../CLAUDE.md` | Кэш обновляется по расписанию; временная недоступность не блокирует чтение задач |
| Infra (развёртывание, CI/CD) | Docker Compose / Kubernetes | Сквозной, по мере готовности приложения | Task Tracker / команда Infra | Приложение и БД разворачиваются воспроизводимо, проходят проверки готовности |

Точные сроки и привязка к вехам курса (И-M1…И-M5) не зафиксированы в исходных документах — согласуются отдельно по графику проекта.
