# 160 — Integration Plan

> Формат — см. [`../documents-composition.md`](../documents-composition.md#160--integration-plan-160integration-planmd).
> Сценарии интеграций — [155](155.sequence-diagrams.md).

Вехи ниже — порядок интеграционных работ курсового проекта. Они не утверждают конкретного провайдера идентификации или production-оркестратор: эти решения остаются открытыми в системных требованиях.

| Интеграция | Тип / протокол | Веха и порядок | Ответственные (Task Tracker / внешняя сторона) | Критерии готовности |
|---|---|---|---|---|
| Провайдер идентификации | Защищённые токены; OIDC/Keycloak — кандидат | И-M1: согласовать модель; И-M2: подключить адаптер | Task Tracker: Auth adapter / владелец IdP + Infra | Выбран продукт и режим проверки; матрица ролей согласована; недействительный токен и недостаточное право отклоняются |
| Сервис тестирования → Task Tracker | Входящий REST API, сервисная аутентификация | И-M2: согласовать; И-M3: контрактный стенд | Task Tracker: Integration Service / команда тестирования | Повтор пары `(source, external ID)` не создаёт дубликат; 401/403/422 структурированы |
| Сервис отчётности → Task Tracker | Входящий read-only REST API, пагинация | И-M2: согласовать; И-M3: контрактный стенд | Task Tracker: Integration Service / команда `reports` | Все обязательные фильтры и данные для показателей доступны; изменяющие операции отсутствуют |
| Task Tracker → сервис справочников | Исходящий REST, периодический опрос + ручной запуск | И-M2: найти владельца; И-M3: согласовать snapshot; И-M4: отказоустойчивость | Task Tracker: Integration Service / владелец сервиса — пока не подтверждён | Кэш обновляется; timeout/retry ограничены; недоступность не блокирует чтение задач; inactive нельзя назначить заново |
| Infra | Конкретный способ развёртывания определяется отдельно | И-M1: требования; И-M4: staging; И-M5: production-readiness | Task Tracker / команда Infra | Dev и staging воспроизводимы; readiness/миграции/backup-проверка соответствуют согласованным NFR |

На И-M5 выполняются сквозные сценарии из [155](155.sequence-diagrams.md), контрактные проверки `openapi.yaml`, проверка наблюдаемости и фиксация всех оставшихся отклонений. Календарные даты зависят от общего графика курса; вехи задают обязательную последовательность.
