# Live-прототип Task Tracker

Интерактивный кликабельный макет для проверки UI/UX-гипотез до начала кодирования — документ
[`115.live-prototype.md`](../../docs/block-e-ui-ux-design/115.live-prototype.md). Экраны и
поведение соответствуют [`110.ui-ux.md`](../../docs/block-e-ui-ux-design/110.ui-ux.md).

## Как открыть

Сборка не нужна — просто откройте `index.html` в браузере (двойным кликом или
`open index.html` / `start index.html`). Все данные — моковые, хранятся в памяти вкладки;
после перезагрузки страницы сбрасываются к исходному состоянию.

## Что внутри

| Файл | Назначение |
|---|---|
| `index.html` | Разметка всех пяти экранов + оверлеи карточки и модальных окон |
| `styles.css` | Оформление (без внешних зависимостей и CDN) |
| `app.js` | Моковые данные, рендер экранов, вся интерактивность |

## Экраны

Бэклог, Канбан-доска, Итерации, Уведомления, Админ-панель — плюс карточка рабочего элемента
(диалог поверх любого экрана). Переключатель роли в сайдбаре («Участник команды» /
«Руководитель» / «Администратор») имитирует то, что в реальной системе определяется токеном
Keycloak и правами на сервере (NFR-003) — здесь это чисто фронтенд-условие для показа/скрытия
действий и пунктов меню.

## Что реально имитируется

- иерархия рабочих элементов (Проект → Эпик → Задача/Ошибка → Подзадача) с автосуммированием
  плановой/фактической/оставшейся трудоёмкости по дочерним элементам;
- канбан-доска с drag-and-drop сменой статуса, включая отклонение переноса элемента без
  исполнителя за пределы бэклога (демонстрация error-состояния из 110.ui-ux.md);
- карточка рабочего элемента: поля, вложения, трудозатраты, комментарии, история изменений с
  diff-просмотром; один рабочий элемент (`TT-7`) заведён как «созданный сервисом тестирования»,
  чтобы показать фиксацию внешнего источника;
- итерации: ёмкость участников с подсветкой перегрузки, запуск с фиксацией базового плана,
  завершение с возвратом незавершённых элементов в бэклог, план-факт для завершённой итерации;
- уведомления, отфильтрованные по текущему пользователю, с отметкой прочтения и переходом в
  карточку;
- админ-панель: управление статусами (переименование/порядок/активность/добавление),
  синхронизация со справочником с симуляцией сбоя и логом;
- экспорт в Excel — по кнопке реально скачивается CSV с текущими данными (заменяет `.xlsx: в
  проде это будет настоящий бинарный файл от бэкенда); импорт — две демо-кнопки показывают оба
  сценария из требований: успешный (создано/обновлено) и отклонённый с отчётом об ошибках, без
  частичного применения.

## Сознательные упрощения (не баг, а масштаб макета)

- Kanban показывает только исполнимые типы (Задача/Ошибка/Подзадача) — Проекты и Эпики видны в
  Бэклоге, но не выводятся отдельными карточками на доске.
- Импорт не парсит настоящий `.xlsx` — обе кнопки лишь показывают, как выглядит отчёт о
  результате (это UI-макет, а не рабочий парсер).
- Переключатель ролей не проверяет права на сервере — в реальной системе это делает бэкенд
  (см. `../../CLAUDE.md` и NFR-003), здесь это только видимость элементов интерфейса.
- Данные не сохраняются между перезагрузками страницы (нет бэкенда/БД — так и задумано для
  прототипа).

## Проверка

Прогонялся через headless Chrome (Playwright) по всем ключевым сценариям — открытие карточки,
drag-and-drop на доске, добавление трудозатрат/комментария, план-факт по завершённой итерации,
переход по клику на уведомление, экспорт, оба сценария импорта, переключение ролей со скрытием
админ-панели, синхронизация справочников — без единой ошибки в консоли браузера.
