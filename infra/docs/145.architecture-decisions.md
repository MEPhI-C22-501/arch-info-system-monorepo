# 145. Архитектурные решения

Формат каждой записи: контекст, варианты, решение, последствия, связанные требования. Статус `accepted` означает решение инфраструктуры для учебного стенда. Он не закрывает открытый межкомандный вопрос, если вопрос назван отдельно.

## ADR-001. Готовый Keycloak

Контекст: нужен вход и учётные записи без своего auth-сервиса. Варианты: собственный JWT-сервис; Keycloak. Решение: Keycloak 26.7.4, штатные страницы и Admin API. Последствия: приложения проверяют issuer, audience и свои права. Требования: FR-01, FR-02.

## ADR-002. Учётная запись начинается в справочниках

Контекст: постановка требует синхронного создания пользователя. Варианты: событие Kafka; прямой SQL; Admin API в том же запросе. Решение: справочники координируют вызов, инфраструктура даёт клиент `reference-manager-provisioner` с минимальными ролями realm-management. Последствия: частичный сбой остаётся у справочников; FR-02 не закрыт без их реализации. Вопросы 6 и 18 открыты.

## ADR-003. MinIO из зафиксированного релиза

Контекст: upstream архивирован. Варианты: плавающий образ; SeaweedFS; сборка `RELEASE.2025-10-15T17-29-55Z`. Решение: своя сборка этого релиза. Последствия: публикация в реестр ждёт namespace. Требования: FR-03, NFR-01.

## ADR-004. Отдельный бакет и ключ

Контекст: команды не должны читать чужие объекты. Варианты: общий бакет и префиксы с общим ключом; бакет и политика на команду. Решение: отдельный бакет. Межкомандный доступ — отдельная заявка, сейчас не выдан. Требования: FR-03, NFR-05.

## ADR-005. Kafka по заявке

Контекст: нужен брокер без произвольных топиков. Варианты: auto-create; создание после заявки. Решение: auto-create выключен, ACL обязателен, клиентские listener-ы SASL_SSL. Контроллер одиночного узла слушает PLAINTEXT, наружу не публикуется, а его principal `ANONYMOUS` входит в `super.users`, иначе KRaft не регистрирует брокера. Это локальное отличие: контейнер в сети `edge` теоретически может открыть порт 9093. Клиентские listener-ы остаются SASL_SSL и `ANONYMOUS` туда не пускают. Требования: FR-04.

## ADR-006. GitHub Actions и фиксированный выпуск

Контекст: нужен общий конвейер. Варианты: Jenkins; сборка на стенде при каждом deploy. Решение: проверки в GitHub Actions, образ по digest, повторная сборка при deploy не нужна. Внешний хост пока не подключён. Требования: FR-06, FR-08.

## ADR-007. minikube без обещания HA

Контекст: постановка просит локальный кластер. Варианты: только Compose; полноценный кластер; minikube с теми же образами. Решение: манифесты `infra/k8s` для minikube, StatefulSet для данных, Deployment для Keycloak и коллектора. Последствия: на машине без minikube запуск не считается выполненным. Требования: FR-07.

## ADR-008. Отдельного Core нет

Контекст: имя Core воспринималось как ещё один backend, а каталог `core/` хранил неиспользуемый шаблон базы. Варианты: сервис Core; шаблон app+db; убрать каталог. Решение: каталога `core/` нет. Каждая команда владеет своим приложением и своей базой, чужие базы не открываются. Требования: граница vision.

## ADR-009. Четыре вида интеграции

Контекст: ревью ожидало пять видов, включая каталог файлов. Варианты: оставить общий volume; считать файл видом S3. Решение: Web API, Kafka, S3, ETL. Файл между модулями — объект и manifest. Требования: FR-05.

## ADR-010. Коллектор для демонстрации

Контекст: команды ждут OTLP. Варианты: не поднимать приёмник; коллектор с debug и file exporter. Решение: `otel-collector:4317` и `:4318`, без долговременного хранилища. Вопрос 8 справочников остаётся proposed, пока команда не подтвердит адрес. Требования: NFR-04.

## ADR-011. Повтор обработки и DLQ

Контекст: QA отказалась от топика ошибок, опираясь на повтор издателя. Варианты: молчаливые retry-топики; только повтор издателя; in-process retry и DLQ потребителя. Решение для эталона: 3 попытки в том же разделе, затем DLQ, commit после записи в DLQ, replay с тем же `eventId`. Retry-топик не используется, чтобы не нарушать порядок агрегата. Для бизнес-подписчиков решение draft. Требования: FR-04, FR-05.

## ADR-012. Реплика витрины Reports

Контекст: Q-REP-01. Варианты: реплика баз источников; чтение primary; своя витрина и её read-replica. Решение инфраструктуры совпадает с предложением Reports: primary `reports-db` и `reports-db-replica`, запись на реплику запрещена. Доступ к базам источников не открывается. Толк постановки преподавателем не подтверждён, поэтому Q-REP-01 не переводится в agreed. Требования: NFR-03.

## ADR-013. Локальные секреты и seed

Контекст: стенд должен подниматься, секреты нельзя коммитить как боевые. Варианты: случайные секреты без примера; демонстрационные значения по умолчанию. Решение: значения `localdemo*` только для локального стенда, переопределяются окружением. Повторный bootstrap не удаляет пользователей. Seed витрины не пишет в базы других команд. Требования: NFR-02.

## ADR-014. Версия релиза

Контекст: `latest` не идентифицирует выпуск. Решение: манифест в `infra/releases` с digest, коммитом конфигурации и версиями контрактов. Выпуск без площадки не объявляется развёрнутым. Требования: FR-08.
