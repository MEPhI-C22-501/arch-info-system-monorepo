# 162. Спецификация способов обмена

Для каждой связи выбран один способ. Остальные варианты записаны, чтобы выбор можно было оспорить.

| Связь | Варианты | Выбор | Почему | Статус |
| --- | --- | --- | --- | --- |
| Справочники → учётная запись | Kafka, SQL, Admin REST | Admin REST в запросе справочников | нужен ответ в том же обращении; события не дают синхронного подтверждения | proposed |
| Модули → справочники | своя копия таблиц, REST | REST `/v1` | владелец данных — справочники | draft, ждёт их API |
| Task Tracker → Planning | REST-срез, события `Task*`, события `WorkItem*` | не выбран | имена и payload расходятся, см. 135 | draft |
| Task Tracker → Reports | реплика БД трекера, REST, Kafka `WorkItem*` | Kafka плюс REST-сверка, как предлагает Reports | реплика чужой БД запрещена границами | draft |
| QA → Reports | только REST, Kafka | Kafka `dev.qa.*` и REST `/api/v1/reports` | так записала QA; Reports ещё не подтвердил | draft |
| Файл между модулями | общий каталог, S3 | S3 и manifest | четыре вида интеграции, ADR-009 | accepted для механизма, заявки команд open |
| ETL Reports | чтение чужих БД, партия в свою витрину | партия в свою витрину | ADR-012 | proposed |
| Оперативное чтение Reports | primary, реплика источников, реплика своей витрины | read-replica своей витрины | Q-REP-01 не подтверждён, механизм поднят | proposed |
| Телеметрия | файлы журналов, OTLP | OTLP в коллектор | адрес proposed командам | proposed |
| Доставка стенда | SSH, self-hosted runner | не выбран | нет площадки | blocked |

Аргумент «так короче написать» не использовался. Где статус не `agreed`, реализация доступа на стенде нужна для проверки механизма и не заменяет подпись владельца.
