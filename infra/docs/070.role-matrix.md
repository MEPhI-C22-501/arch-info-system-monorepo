# 070. Матрица доступа

OIDC-токен не даёт доступ к Kafka, S3 или чужой БД. Это разные учётные записи.

## 1. Пользовательские роли

Бизнес-роли модулей остаются в их документах `070`. Инфраструктура не назначает роль по умолчанию новой учётной записи: вопрос 6 справочников открыт. Демонстрационные пользователи `member`, `lead` и `admin` создаются в Keycloak только если их ещё нет. Это не кадровые профили и не вставка в базу справочников.

Роль клиента `reference-manager` с именем `reference-hr-reader` создаётся и никому не выдаётся, пока справочники не ответят на вопрос 22.

## 2. Клиенты OIDC

Realm `arch-info-system`. Для браузерных клиентов включён Authorization Code и PKCE (`S256`). Межсервисные вызовы идут через отдельные service accounts и `client_credentials`.

| Клиент | Вид | Audience | Назначение | Статус |
| --- | --- | --- | --- | --- |
| `task-tracker` | public SPA | `task-tracker` | браузер Task Tracker | перенесено из локального realm, draft для общего стенда |
| `planning-system` | public SPA | `planning-system` | браузер Planning | draft |
| `reference-manager` | public SPA | `reference-manager` | браузер справочников | draft |
| `reports` | public SPA | `reports` | браузер Reports | draft |
| `qa-system` | public SPA | `qa-system` | браузер QA | draft |
| `reference-manager-provisioner` | service account | нет бизнес-audience | Admin API пользователей | implemented; права только `manage-users`, `view-users`, `query-users`, `view-realm` |
| `testing-client` | service account | `task-tracker` | роль клиента `testing-service` | перенесено из Task Tracker |
| `reports-client` | service account | `task-tracker`, `reports` | роль `reports-service` | перенесено из Task Tracker |
| `planning-service` | service account | `planning-system`, `reference-manager` | машинный вызов | draft, роль HR не выдана |
| `qa-ci`, `qa-executor` | service account | `qa-system` | CI и исполнитель | draft по заявке QA |
| `example-caller` | service account | `example-api` | эталон | implemented для примера |
| `example-stranger` | service account | нет `example-api` | отрицательная проверка | implemented для примера |

Redirect URI локального стенда — `localhost` портов модулей. `http://arch.local/*` добавлен как черновик для minikube и не считается согласованным адресом площадки.

Issuer для браузера: `http://localhost:8081/realms/arch-info-system`. JWKS из контейнера: `http://keycloak:8080/realms/arch-info-system/protocol/openid-connect/certs`. Это повторяет разделение Task Tracker и не является адресом общего TLS-стенда.

## 3. Kafka principals

Пароли задаются при запуске. `admin` — super user bootstrap. Остальные principals не являются super user.

| Principal | Топик | Операции | Статус контракта |
| --- | --- | --- | --- |
| `task_tracker` | `task-tracker.events.v1` | Write, Describe | топик создан по каталогу издателя, внешний контракт draft |
| `planning` | тот же | Read, группа `planning-task-tracker` | ожидание потребителя, не согласие издателя |
| `reports` | тот же | Read, группа `reports-task-tracker` | draft |
| `qa` | `dev.qa.test-run.v1`, `dev.qa.defect.v1` | Write | draft заявки QA |
| `reports` | топики QA | Read, группа `reports-qa-ingest` | draft |
| `example` | `dev.infra.examples.v1` и его `.dlq` | Read, Write | эталон инфраструктуры |

`qa` не получает запись в `task-tracker.events.v1`.

## 4. S3

У каждой команды свой ключ и политика только на свой бакет: `task-tracker` → `arch-dev-task-tracker`, `planning-system` → `arch-dev-planning-system`, `reference-manager` → `arch-dev-reference-manager`, `reports` → `arch-dev-reports`, `qa-system` → `arch-dev-qa`. Имя `qa-system` вместо `qa`: MinIO принимает access key длиной от 3 до 20 символов. Бакет `arch-dev-infra` не выдаётся приложениям. Межкомандный префикс не выдаётся, пока нет отдельной заявки. Эталон использует `arch-dev-examples`: `example-writer` пишет, `example-reader` читает, `example-stranger` имеет только `arch-dev-stranger`.

## 5. Базы данных

| База | Кто подключается | Кто не подключается |
| --- | --- | --- |
| `keycloak` | только Keycloak | приложения |
| `reports` | роль `reports`, запись только на primary | реплика отклоняет запись; другие модули не получают роль |
| базы команд | роль своего модуля из шаблона `core/templates/app-db` | остальные модули |

Доступ к кадровым данным — через API справочников и роль, которую справочники согласуют. Прямой SQL к их базе инфраструктура не открывает.
