# 078. Сценарии качества

Оценки ниже — экспертные, не измерения стенда. Измеренный результат появляется только после прогона и помечается отдельно.

Шкала ответа: 1 — неприемлемо, 3 — достаточно для учебного стенда, 5 — удобно сопровождать. Итог способа:

`S = 0.25*C + 0.20*I + 0.20*R + 0.20*O + 0.15*L`

Веса: согласованность C = 0.25, изоляция I = 0.20, восстановление R = 0.20, операционная ясность O = 0.20, задержка L = 0.15. Сумма весов = 1.

| Способ | Стимул | Условия | Ответ | Мера |
| --- | --- | --- | --- | --- |
| Web API | изменяющий вызов | тайм-аут или 503 | повтор с тем же Idempotency-Key | нет второй записи |
| Kafka | сообщение обработано, offset не подтверждён | процесс упал | повторная доставка и дедуп по `eventId` | одна запись результата |
| Kafka | повторяемая ошибка | 3 попытки с паузами 0.2/0.4/0.8 с | запись в DLQ, затем commit | исходное тело сохранено |
| S3 | чужой ключ | политика только на свой бакет | отказ Signature V4 | объект не создан |
| ETL | обрыв посередине партии | checkpoint после commit строки | продолжение с номера | нет двойного учёта |

## Экспертная матрица

| Способ | C | I | R | O | L | S |
| --- | --- | --- | --- | --- | --- | --- |
| Web API | 4 | 4 | 3 | 5 | 5 | 4.15 |
| Kafka | 3 | 4 | 4 | 3 | 3 | 3.40 |
| S3 | 4 | 5 | 3 | 4 | 4 | 4.00 |
| ETL | 4 | 4 | 4 | 3 | 2 | 3.50 |

Расчёт Web API: `0.25*4 + 0.20*4 + 0.20*3 + 0.20*5 + 0.15*5 = 1 + 0.8 + 0.6 + 1 + 0.75 = 4.15`.

Kafka получает более низкую операционную ясность: имена событий команд ещё draft. S3 получает высокую изоляцию из-за отдельной политики бакета. ETL проигрывает по задержке, потому что это партия, а не запрос. Эти числа не являются SLA и не закрывают вопрос 9 справочников.
