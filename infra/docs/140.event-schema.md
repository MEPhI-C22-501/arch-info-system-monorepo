# 140. Схемы событий

Схема payload берётся у издателя. Здесь зафиксированы общий конверт эталона, конверт DLQ и отличия, которые нельзя слить молча.

## Отличия, которые сохраняются

| Место | Поле | Тип | Что не делаем |
| --- | --- | --- | --- |
| Vision до 06.10.2026 | `event_id` | текст | не переименовываем чужие JSON |
| Task Tracker, Planning, QA, эталон | `eventId` | строка UUID | считаем каноническим написанием для новых сообщений эталона |
| QA | `schemaVersion` | integer `1` | не приводим к строке |
| Planning | `schemaVersion` | string semver | не приводим к числу |
| Task Tracker | версия в суффиксе топика и в описании v1 | не то же поле, что у QA | не объявляем единый envelope agreed |

Потребитель принимает написание издателя. Сообщение с «чужим» написанием идентификатора для этого издателя невалидно и уходит в DLQ потребителя, а не переписывается брокером.

## Эталонный конверт

Файлы:

- [../contracts/schemas/envelope.schema.json](../contracts/schemas/envelope.schema.json)
- [../contracts/schemas/dlq.schema.json](../contracts/schemas/dlq.schema.json)
- примеры в `infra/contracts/schemas/examples/`

Допустимое сообщение содержит `eventId`, `eventType`, `occurredAt`, `schemaVersion` строкой и `payload`. Недопустимое сообщение без `eventId` валидатор отклоняет.

## DLQ потребителя

Параметры эталона, они же проверяемые значения:

| Параметр | Значение |
| --- | --- |
| Попытки | 3 |
| Пауза | 0.2 с, 0.4 с, 0.8 с, внутри того же потребителя |
| Повторяемая ошибка | сбой обработки, который ещё может пройти |
| Неповторяемая ошибка | сообщение не проходит схему |
| Commit offset | после успеха или после успешной записи в DLQ |
| Если DLQ недоступен | offset не подтверждается, исходное сообщение остаётся |
| Поля DLQ | source topic, partition, offset, исходный event id, причина, счётчик попыток, исходное тело |
| Retention | 7 суток, как у топика |
| ACL | писать и читать может principal потребителя эталона `example` |
| Оператор | человек с доступом к replay-скрипту эталона |
| Replay | повторная публикация в исходный топик с тем же `eventId`; дедупликация не создаёт вторую запись |
| Порядок | отдельных retry-топиков нет, чтобы не обгонять следующее сообщение того же агрегата |

Повтор публикации издателя этим контрактом не заменяется. QA может повторять отправку и одновременно должна иметь стратегию для своей обработки. Для бизнес-подписчиков таблица остаётся предложением `draft`, пока они не примут те же числа.

Изменение общего конверта эталона делается вместе с владельцем примера. Для бизнес-событий владельцы перечислены в [135](135.event-catalog.md).
