# 146. Логическая схема связей

```mermaid
flowchart LR
    subgraph sync["Синхронные"]
        RM["Reference Manager REST"]
        KC["Keycloak"]
        TT["Task Tracker API"]
        PL["Planning API"]
        QA["QA API"]
        REP["Reports API"]
    end
    subgraph async["Асинхронные"]
        BUS["Kafka"]
    end
    subgraph batch["Пакетные"]
        S3["MinIO"]
        ETL["ETL Reports"]
        MART["Витрина Reports"]
    end
    PL -->|REST draft| RM
    QA -->|REST draft| RM
    REP -->|REST draft| RM
    RM -->|Admin API proposed| KC
    TT -->|события draft| BUS
    QA -->|события draft| BUS
    BUS -->|подписка draft| PL
    BUS -->|подписка draft| REP
    BUS -->|подписка draft| QA
    TT -->|объект по будущей заявке| S3
    QA -->|arch-dev-qa| S3
    S3 --> ETL
    TT -->|REST или событие| ETL
    ETL --> MART
    MART -->|репликация| REPLICA["Read-replica"]
```

Сплошная готовность на схеме не показана: рёбра с подписью draft не являются проверенной связью модулей. Эталонные Web API, Kafka, S3 и ETL проверяют механизм на своих ресурсах, а не эти рёбра.
