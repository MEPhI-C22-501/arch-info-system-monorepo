# 155. Диаграммы последовательностей

Участники с подписью «ещё нет» в репозитории не поставлены. Эталон показывает механизм на инфраструктурных ресурсах.

## Вход

```mermaid
sequenceDiagram
    actor User as Браузер
    participant App as Приложение
    participant KC as Keycloak
    User->>KC: Authorization Code + PKCE
    KC-->>User: code
    User->>App: code
    App->>KC: обмен code, issuer localhost:8081
    App->>KC: JWKS из сети контейнеров
    App-->>User: сессия после проверки audience
```

Проверено эталоном: service account с чужим audience получает 401. Браузерный вход Task Tracker на общем стенде остаётся проверкой команды.

## Приём сотрудника

```mermaid
sequenceDiagram
    actor Admin as Администратор справочников
    participant RM as Reference Manager
    participant DB as БД справочников
    participant KC as Keycloak
    Admin->>RM: создать профиль
    RM->>DB: PENDING и ID операции
    RM->>KC: создать отключённую запись
    alt обе стороны подтвердили
        RM->>KC: включить запись
        RM->>DB: ACTIVE
    else тайм-аут
        RM->>DB: состояние для сверки
        Note over RM,KC: повтор по тому же ID, без удаления чужой записи
    end
```

Координация на стороне Reference Manager. Инфраструктура даёт API. Сквозной сценарий не `verified`, пока нет их обработчика. Временный пароль не отправляется: вопрос 18 открыт.

## Событие и DLQ

```mermaid
sequenceDiagram
    participant Pub as Издатель эталона
    participant K as Kafka
    participant Sub as Потребитель
    participant DLQ as DLQ
    Pub->>K: eventId
    K->>Sub: доставка
    alt успех
        Sub->>Sub: запись результата
        Sub->>K: commit
    else падение после записи
        Sub--xK: commit не выполнен
        K->>Sub: та же запись
        Sub->>K: commit без второй записи
    else попытки исчерпаны
        Sub->>DLQ: исходное тело, offset, причина, attempts
        Sub->>K: commit
    else DLQ недоступен
        Sub--xK: commit не выполнен
    end
```

Это проверенный эталон, не бизнес-подписка Planning.

## S3

```mermaid
sequenceDiagram
    participant W as Writer
    participant S as MinIO
    participant R as Reader
    W->>S: объект и manifest
    R->>S: чтение и checksum
    R->>R: повтор по operationId не создаёт вторую запись
    participant X as Чужой ключ
    X--xS: PutObject в чужой бакет
```

## ETL и отчёт

```mermaid
sequenceDiagram
    participant S as MinIO
    participant E as ETL эталона
    participant DB as SQLite эталона
    S->>E: партия и manifest
    E->>DB: строка и checkpoint commit
    Note over E: обрыв продолжается с checkpoint
    E->>DB: повтор партии не удваивает строки
```

Сервер отчётов и задержка доставки из Task Tracker в витрину здесь не показаны как выполненные: витрина содержит только демонстрационные идентификаторы, реплика PostgreSQL измеряется отдельно от лага источников.
