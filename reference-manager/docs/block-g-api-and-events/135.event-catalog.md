# 135 - Event Catalog

> Формат - см. [состав документов](../../../task-tracker/docs/documents-composition.md), документ 135.
> Источник - [системные требования, INT-RM-04, INT-RM-05](../system-requirements.md#5-требования-к-интеграциям), [конституция, принцип I](../../.specify/memory/constitution.md), [Event Storming](../block-b-domain-analysis/040.event-storming.md).

## 1. Решение

Сервис не публикует и не потребляет события. Решение принято 2026-09-14 и закреплено правилами BR-RM-09 и INT-RM-05: сервис принимает только входящие вызовы, потребители перечитывают справочники по REST API и сами выбирают срок жизни кэша. Kafka и outbox исключены из проекта (ADR-003); история изменений хранится внутри сервиса как ревизии и наружу не публикуется (ADR-016).

## 4. Внутренние факты

Доменные события из [040](../block-b-domain-analysis/040.event-storming.md) (ЗаписьСоздана, ЗаписьУдалена и другие) существуют как ревизии в истории справочника и как счётчики телеметрии (NFR-RM-27). В шину сообщений они не попадают.

## 5. Несогласованные ожидания

| Кто | Ожидание | Состояние |
| --- | --- | --- |
| Planning System | Получать классификаторы событиями | Не согласовано; требуется зафиксировать чтение по API и интервал перечитывания |
| Все потребители | Инкрементальная выборка изменившихся записей | Вопрос 3 требований |

Если по итогам согласования события всё же понадобятся, решение оформляется поправкой конституции (принцип I) и новым ADR; до этого документы 135 и 140 остаются пустыми намеренно.
