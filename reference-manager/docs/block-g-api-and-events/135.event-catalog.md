# 135 - Каталог событий Reference Manager

**Блок G.** Редакция 1.0 от 2026-09-25, к ревью команды.
Основания: [Системные требования, INT-RM-04, INT-RM-05](../system-requirements.md#5-требования-к-интеграциям), [конституция, принцип I](../../.specify/memory/constitution.md), [Event Storming](../block-b-domain-analysis/040.event-storming.md).

## 1. Решение

Сервис не публикует и не потребляет события. Решение принято 2026-09-14 и закреплено правилами BR-RM-09 и INT-RM-05: сервис принимает только входящие вызовы, потребители перечитывают справочники по REST API и сами выбирают срок жизни кэша. Kafka, outbox и журнал изменений исключены из проекта (ADR-003, ADR-004 в [145](../block-h-architecture-and-logic/145.architecture-decisions.md)).

## 4. Внутренние факты

Доменные события из [040](../block-b-domain-analysis/040.event-storming.md) (ЗаписьСоздана, ЗаписьУдалена и другие) существуют только как результат транзакции и как спаны и счётчики телеметрии (NFR-RM-27). В шину сообщений они не попадают.

## 5. Несогласованные ожидания

| Кто | Ожидание | Состояние |
| --- | --- | --- |
| Planning System | Получать классификаторы событиями (их Видение, раздел 8; ТЗ 4.5) | Не согласовано; требуется зафиксировать чтение по API и интервал перечитывания |
| Все потребители | Инкрементальная выборка изменившихся записей | Вопрос 3 требований; фильтр по времени изменения исключён 2026-09-17 |

Если по итогам согласования события всё же понадобятся, решение оформляется поправкой конституции (принцип I) и новым ADR; до этого документы [135](135.event-catalog.md) и [140](140.event-schema.md) остаются пустыми намеренно.
