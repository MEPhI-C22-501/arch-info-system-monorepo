# 130 - Контракты API Reference Manager

**Блок G.** Редакция 1.0 от 2026-09-25, к ревью команды.
Основания: [Системные требования, разделы 4, 5.1, 10.2](../system-requirements.md), [модель данных](../block-f-data-model/120.data-model.md), [RBAC](../block-c-requirements-and-roles/070.role-matrix.md), спецификация `api/openapi/v1/openapi.yaml`.

## 1. Спецификация

Источник истины - OpenAPI в `api/openapi/v1/openapi.yaml` с разбиением на `paths/` и `components/`; серверные интерфейсы и модели генерируются `task generate` (oapi-codegen) в `pkg/api/v1`. Сейчас спецификация содержит только `/livez` и `/readyz`; операции справочников добавляются по мере реализации среза 1, по одной схеме записи и одному набору из пяти операций на справочник (FR-RM-37, FR-RM-38).

Расхождения с требованиями, подлежащие устранению: путь спецификации (`api/openapi.yaml` в требованиях), имена служебных точек, префикс монтирования `/v1` вместо `/api/reference-data/v1` (K-01..K-03 в [020](../block-a-context-and-scope/020.system-context.md)).

Версионирование: мажорная версия в пути (`/v1`); в её пределах только совместимые изменения - новые справочники как новые пути, новые столбцы как необязательные поля (INT-RM-03, NFR-RM-06). Версия спецификации в `info.version` следует semver: minor при добавлении справочника или столбца, patch при уточнении описаний. Несовместимое изменение выпускается как `/v2` с периодом параллельной поддержки.

## 2. Общие правила

| Правило | Значение |
| --- | --- |
| Базовый путь | `/api/reference-data/v1` (NFR-RM-09) |
| Формат | `application/json`, UTF-8; время RFC 3339 в UTC; идентификаторы UUID v7 |
| Аутентификация | Со среза 2: `Authorization: Bearer <JWT Keycloak>`; 401 при отсутствии или недействительности; 403 при недостаточной роли |
| Частичное изменение | `PATCH` с `application/merge-patch+json` (RFC 7386); неизменяемые поля отклоняются 422 (FR-RM-07) |
| Ошибки | `application/problem+json` RFC 9457: `type`, `title`, `status`, `detail`, `instance`, `request_id`, `trace_id`, `errors[]` для 422 (NFR-RM-11) |
| Заголовки ответа | `X-Request-Id`, `X-Trace-Id` всегда; `ETag` на чтении и `If-Match` на записи со среза 2 (NFR-RM-13, FR-RM-24) |
| Размеры | Тело до 1 МБ; `limit` 1..200, по умолчанию 50 (NFR-RM-15) |
| Выгрузка | `Accept: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` на операции постраничного чтения (FR-RM-40) |

## 3. Пять операций справочника

`{catalog}` - код справочника, например `currencies`. Все справочники обслуживаются одинаково (NFR-RM-40).

| Операция | Метод и путь | Роль | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| Создать запись | `POST /{catalog}` | admin | 201, тело - запись, `Location` | 400 некорректный JSON; 409 код занят; 422 поля; 413 тело велико |
| Страница записей | `GET /{catalog}` | reader | 200, страница; при `Accept` `.xlsx` - файл | 400 параметры; 413 выгрузка сверх предела; 406 неподдерживаемый `Accept` |
| Одна запись | `GET /{catalog}/{id}` | reader | 200, запись, включая DELETED | 404 нет записи или чужой арендатор |
| Частично изменить | `PATCH /{catalog}/{id}` | admin | 200, запись | 404; 409 запись удалена или возврат неудалённой; 422 неизменяемое поле или значения; 412, 428 (срез 2) |
| Удалить | `DELETE /{catalog}/{id}` | admin | 204 | 404; 409 уже удалена; 412, 428 (срез 2) |

Операций управления справочниками нет (FR-RM-38). Возврат в работу - `PATCH` с телом `{"deleted_at": null}` (FR-RM-12).

### Параметры постраничного чтения

| Параметр | Тип | Значение |
| --- | --- | --- |
| `code` | string | Точное совпадение кода; заменяет чтение по коду (FR-RM-06) |
| `q` | string | Префикс кода или вхождение в название без учёта регистра |
| `include_deleted` | boolean | По умолчанию `false`: только ACTIVE |
| `limit`, `offset` | integer | 1..200 и >= 0 |
| `sort` | string | `code`, `name`, `updated_at` с суффиксом `:asc` или `:desc`; по умолчанию `code:asc` |
| фильтры справочника | по столбцам | Описаны в OpenAPI операции конкретного справочника, например `minor_units` для `currencies` |

Ответ страницы: `{"items": [...], "limit": 50, "offset": 0, "total": 183}`.

## 4. Схемы

Общая часть записи `RecordBase`: `id`, `code`, `name`, `status` (`ACTIVE` | `DELETED`, только чтение), `version`, `created_at`, `created_by`, `updated_at`, `updated_by`, `deleted_at`, для арендаторских справочников `tenant_id`. Схема справочника `{Catalog}Record` расширяет `RecordBase` столбцами справочника; схема создания `{Catalog}Create` содержит `code`, `name` и столбцы; схема изменения `{Catalog}Patch` - `name`, столбцы и `deleted_at` только со значением `null`.

Пример `CurrencyRecord`:

```json
{
  "id": "0192f3a2-7c3e-7d1a-9f0b-2a5c1e6d8b40",
  "code": "EUR",
  "name": "Euro",
  "status": "ACTIVE",
  "numeric_code": "978",
  "minor_units": 2,
  "symbol": "EUR",
  "version": 3,
  "created_at": "2026-09-14T10:00:00Z",
  "created_by": "keycloak-sub-1",
  "updated_at": "2026-09-20T08:30:00Z",
  "updated_by": "keycloak-sub-1",
  "deleted_at": null
}
```

## 5. Примеры

### 5.1. Создание записи, успех

```http
POST /api/reference-data/v1/currencies
Content-Type: application/json
Authorization: Bearer <token>

{"code": "PLN", "name": "Polish zloty", "numeric_code": "985", "minor_units": 2, "symbol": "zl"}
```

```http

Location: /api/reference-data/v1/currencies/0192f3a2-...
X-Request-Id: 7c1d...
X-Trace-Id: 4bf92f3577b34da6a3ce929d0e0e4736
ETag: "1"

{"id": "0192f3a2-...", "code": "PLN", "name": "Polish zloty", "status": "ACTIVE", "numeric_code": "985", "minor_units": 2, "symbol": "zl", "version": 1, "created_at": "2026-09-25T09:00:00Z", "created_by": "keycloak-sub-1", "updated_at": "2026-09-25T09:00:00Z", "updated_by": "keycloak-sub-1", "deleted_at": null}
```

### 5.2. Создание записи, ошибка по полям

```http

Content-Type: application/problem+json

  "status": 422,
  "detail": "2 fields are invalid",
```

```http

{"type": "https://erp.example/problems/code-taken", "title": "Code is already used", "status": 409, "detail": "record with code PLN exists in state DELETED; restore it with PATCH {\"deleted_at\": null}", "instance": "/api/reference-data/v1/currencies", "request_id": "...", "trace_id": "..."}
```

### 5.4. Страница с фильтром и выгрузка

```http
GET /api/reference-data/v1/currencies?q=e&sort=name:asc&limit=50
Accept: application/json
```

```http
GET /api/reference-data/v1/currencies?q=e&sort=name:asc

```

```http

```

## 6. Соответствие ошибок

| Ситуация | Код | `type` |
| --- | --- | --- |
| Нет токена или недействителен (срез 2) | 401 | `unauthorized` |
| Нет роли (срез 2) | 403 | `forbidden` |
| Запись не найдена, чужой арендатор | 404 | `not-found` |
| Неподдерживаемый `Accept` | 406 | `not-acceptable` |
| Код занят, включая удалённые | 409 | `code-taken` |
| Уже удалена, не удалена, изменение удалённой | 409 | `already-deleted`, `not-deleted`, `deleted` |
| Версия не совпала, нет `If-Match` (срез 2) | 412, 428 | `version-mismatch`, `precondition-required` |
| Некорректный JSON или параметры | 400 | `bad-request` |
| Тело велико; выгрузка сверх предела | 413 | `payload-too-large`, `export-too-large` |
| Нарушены ограничения полей | 422 | `validation` |
| Неизменяемое поле в `PATCH` | 422 | `immutable-field` |
| Внутренняя ошибка | 500 | `internal` |
| База недоступна, таймаут выгрузки | 503 | `unavailable` |
