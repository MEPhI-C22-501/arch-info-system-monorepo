# 155 - Sequence-диаграммы Reference Manager

**Блок I.** Редакция 1.0 от 2026-09-25, к ревью команды.
Основания: [Use Cases](../block-b-domain-analysis/060.use-cases.md), [контракты API](../block-g-api-and-events/130.api-contracts.md), [логическая схема](../block-h-architecture-and-logic/146.logic-scheme.md).

Тайм-ауты: запрос ограничен middleware timeout (сейчас 1 с константой, K-07; для выгрузки требуется отдельный предел до 60 с по NFR-RM-43); запрос к базе ограничен контекстом запроса; экспорт телеметрии не блокирует ответ.

## SD-01 Создание записи с проверкой полей

Use Case UC-03, UC-14; истории US-AD-01, US-AD-02.

```mermaid
sequenceDiagram
    participant A as Администратор
    participant H as transport/http
    participant S as service
    participant R as repository
    participant DB as PostgreSQL
    A->>H: POST /currencies {code, name, numeric_code, minor_units}
    H->>H: разбор JSON, X-Request-Id, спан otelhttp
    H->>S: CreateRecord(catalog=currencies, input, actor)
    S->>S: проверка полей по описанию справочника
    alt поля неверны
        S-->>H: ErrValidation{fields}
        H-->>A: 422 problem+json errors[]
    else поля верны
        S->>DB: BEGIN
        S->>R: Insert(record, version=1)
        R->>DB: INSERT ... RETURNING
        alt UNIQUE(code) нарушен
            DB-->>R: unique_violation
            R-->>S: ErrCodeTaken
            S->>DB: ROLLBACK
            S-->>H: ErrCodeTaken
            H-->>A: 409 code-taken
        else сохранено
            DB-->>R: строка
            S->>DB: COMMIT
            S-->>H: record
            H-->>A: 201 Location, ETag "1"
        end
    end
```

## SD-02 Удаление и возврат в работу

Use Case UC-05, UC-06; истории US-AD-04, US-AD-05.

```mermaid
sequenceDiagram
    participant A as Администратор
    participant H as transport/http
    participant S as service
    participant DB as PostgreSQL
    A->>H: DELETE /currencies/{id} (срез 2: If-Match "3")
    H->>S: DeleteRecord(id, actor, expectedVersion)
    S->>DB: BEGIN
    S->>DB: UPDATE currencies SET deleted_at=now(), version=version+1, updated_* WHERE id=$1 AND deleted_at IS NULL [AND version=$2]
    alt 0 строк
        S->>DB: SELECT deleted_at, version WHERE id=$1
        alt записи нет
            S-->>H: ErrNotFound
            H-->>A: 404
        else уже удалена
            S-->>H: ErrAlreadyDeleted
            H-->>A: 409 already-deleted
        else версия не совпала (срез 2)
            S-->>H: ErrVersionMismatch
            H-->>A: 412 version-mismatch
        end
        S->>DB: ROLLBACK
    else 1 строка
        S->>DB: COMMIT
        H-->>A: 204
    end
    A->>H: PATCH /currencies/{id} {"deleted_at": null}
    H->>S: RestoreRecord(id, actor)
    S->>DB: UPDATE ... SET deleted_at=NULL, version=version+1 WHERE id=$1 AND deleted_at IS NOT NULL
    alt 0 строк
        H-->>A: 404 или 409 not-deleted
    else 1 строка
        H-->>A: 200 record status=ACTIVE
    end
```

## SD-03 Постраничное чтение и выгрузка `.xlsx`

Use Case UC-08, UC-09; истории US-RD-01..04.

```mermaid
sequenceDiagram
    participant C as Подсистема или читатель
    participant H as transport/http
    participant S as service
    participant X as xlsx
    participant DB as PostgreSQL
    C->>H: GET /currencies?q=e&sort=name:asc&limit=50 (Accept: application/json)
    H->>S: ListRecords(filter, page)
    S->>DB: SELECT ... WHERE deleted_at IS NULL AND (code ILIKE 'e%' OR name ILIKE '%e%') ORDER BY name LIMIT 50 OFFSET 0
    S->>DB: SELECT count(*) ... (тот же фильтр)
    DB-->>S: строки, total
    S-->>H: page
    H-->>C: 200 {items, limit, offset, total}
    C->>H: GET /currencies?q=e&sort=name:asc (Accept: .xlsx)
    H->>S: ExportRecords(filter)
    S->>DB: SELECT count(*) ...
    alt total > предел выгрузки
        S-->>H: ErrExportTooLarge
        H-->>C: 413 export-too-large
    else в пределах
        S->>X: NewWriter(columns)
        loop порции по 1000 строк
            S->>DB: SELECT ... ORDER BY name LIMIT 1000 OFFSET n
            DB-->>S: строки
            S->>X: AppendRows(строки, коды как текст)
        end
        X-->>S: файл
        H-->>C: 200 Content-Disposition attachment
    end
```

Соединение с базой возвращается в пул между порциями; при превышении предела времени формирование прерывается ответом 503 (NFR-RM-43).

## SD-04 Запрос с токеном Keycloak (срез 2)

Use Case UC-10; история US-CS-02.

```mermaid
sequenceDiagram
    participant C as Сервис-потребитель
    participant KC as Keycloak
    participant M as auth middleware
    participant J as jwks cache
    participant S as service
    C->>KC: client credentials
    KC-->>C: access token (roles: reference-reader)
    C->>M: GET /currencies/{id} Authorization: Bearer
    M->>J: ключ по kid
    alt ключ в кэше
        J-->>M: ключ
    else нет ключа
        J->>KC: GET JWKS
        KC-->>J: ключи
        J-->>M: ключ
    end
    M->>M: подпись, iss, aud, exp, nbf
    alt токен недействителен
        M-->>C: 401 unauthorized
    else действителен
        M->>S: запрос с Principal{sub, roles, tenant}
        S->>S: роль разрешает операцию?
        alt нет
            S-->>C: 403 forbidden
        else да
            S-->>C: 200 record
        end
    end
```

Ошибка загрузки JWKS при пустом кэше даёт 503 на защищённых путях; ключи обновляются не чаще раза в минуту. Источник ключей может быть заменён конфигурацией (вопрос 7).

## SD-05 Развёртывание: задание миграций и готовность

Use Case UC-12, UC-02; требования NFR-RM-21, FR-RM-31.

```mermaid
sequenceDiagram
    participant CI as CI/CD
    participant K as Kubernetes
    participant J as Job миграций
    participant DB as PostgreSQL
    participant P as Pod reference-manager
    CI->>K: новый образ, манифесты
    K->>J: запустить Job migrate up
    J->>DB: применить миграции, schema_migrations.version = N
    alt миграция не применилась
        J-->>K: exit 1
        K-->>CI: развёртывание остановлено
    else применена
        J-->>K: exit 0
        K->>P: запустить Deployment
        P->>DB: пул, ping
        K->>P: GET /ready
        P->>DB: ping; SELECT version FROM schema_migrations
        alt база недоступна или version < N
            P-->>K: 503 {ready:false, failed_dependencies}
            K->>K: трафик не подаётся, повтор через interval
        else готов
            P-->>K: 200 {ready:true}
            K->>K: трафик на Pod, старые Pod останавливаются
        end
    end
```

## SD-06 Заявка на справочник

Use Case UC-01, UC-02; истории US-RQ-01..03. Взаимодействие людей и GitHub, не сетевых компонентов.

```mermaid
sequenceDiagram
    participant T as Команда-заказчик
    participant GH as GitHub issues и PR
    participant E as Инженер справочников
    participant CI as CI
    participant K as Развёртывание
    T->>GH: issue "Заявка на справочник": код, столбцы, данные
    E->>GH: проверка по BR-RM-08, вопросы по столбцам
    alt бизнес-сущность
        E->>GH: отклонить с обоснованием, запись в раздел 9.3
        GH-->>T: закрыто
    else НСИ
        E->>GH: PR: миграция, обработчики, OpenAPI, тесты
        CI->>GH: lint, тесты, up-down-up, diff OpenAPI
        E->>GH: ревью CODEOWNERS, слияние
        GH->>K: выкладка, SD-05
        E->>GH: закрыть issue: путь и схема записи
        GH-->>T: справочник доступен
    end
```
