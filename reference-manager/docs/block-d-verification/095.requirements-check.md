## 1. Статусы и границы проверки

- **covered** - требование связано с документом, историей и спецификацией теста.
- **partial** - связи есть, но остаётся несогласованное решение, порог или расхождение с кодом; причина указана.
- **missing** - нет истории или сценария проверки.

Статусы описывают полноту документации, не состояние реализации. Все тесты имеют статус **planned**: в репозитории есть каркас сервиса, методы справочников не реализованы, `task tests` остаётся заглушкой. T-FR-NN означает выполнение всех AC перечисленных историй; T-NFR-NN - проверки из [075](../block-c-requirements-and-roles/075.nfr.md).

Отозванные идентификаторы FR-RM-01..04, 13, 15..20, 25, 26, 27 и INT-RM-07..10 в матрицу не входят и не переиспользуются.

## 6. Итоги

Статус **missing** отсутствует. Статус **partial** имеют 22 строки по четырём причинам:

1. Расхождения кода и требований K-02, K-04, K-07..K-10 ([020, раздел 6](../block-a-context-and-scope/020.system-context.md)): имена служебных точек, изменения схемы в Compose, ограничения в коде, единая учётная запись, схема readiness, спецификация не по AIP.
2. Нерешённые вопросы требований 1, 6, 7, 8, 9, 12, 13: владелец справочников задач, роли, источник ключей, транспорт OTLP, пороги, переиспользование кода методов, выгрузка через `Accept` или `:export`.
3. Отсутствие артефактов: стек фронтенда, подключение экспорта OpenTelemetry, реализация `task tests`.
4. Несогласованное ожидание Planning System о событиях (INT-RM-05).

Открытые вопросы требований не объявлены решёнными и перечислены в [160](../block-i-integration-and-deployment/160.integration-plan.md) с ответственными.
