## 1. Статусы и границы проверки

- **covered** - требование связано с документом, историей и спецификацией теста; достаточно, чтобы начать реализацию.
- **partial** - связи есть, но остаётся несогласованное решение, порог или расхождение с кодом; причина указана.
- **missing** - нет истории или сценария проверки.

Статусы описывают полноту документации, не состояние реализации. Все тесты имеют статус **planned**: в репозитории есть каркас сервиса (конфигурация, журналирование, PostgreSQL-клиент, middleware, служебные точки), но ни одна из пяти операций справочника не реализована и `task tests` остаётся заглушкой. T-FR-NN означает выполнение всех AC перечисленных историй; T-NFR-NN - проверки из [075](../block-c-requirements-and-roles/075.nfr.md).

Отозванные идентификаторы FR-RM-01..04, 13, 15..20, 27 в матрицу не входят и не переиспользуются.

## 6. Итоги

Не покрыто документами ни одно требование; статус **missing** отсутствует. Статус **partial** имеют 26 строк по пяти причинам:

1. Расхождения кода и требований K-01..K-04, K-07 ([020, раздел 6](../block-a-context-and-scope/020.system-context.md)): префикс пути, имена служебных точек, путь спецификации, сервис миграций в Compose, лимиты в коде.
2. Нерешённые вопросы требований 1, 5, 6, 7, 8, 9, 12, 13: владелец справочников задач, claim арендатора, роли, источник ключей, транспорт OTLP, пороги, способ переиспользования обработчиков, выбор выгрузки через `Accept`.
3. Отсутствие артефактов: шаблон issue заявки, прототип интерфейса, подключение OpenTelemetry SDK, реализация `task tests`.
4. Несогласованное ожидание Planning System о событиях (INT-RM-05).
5. Конституция, принцип IV, всё ещё описывает JSON Schema отклонённой модели (K-05).

Открытые вопросы 1-17 требований не объявлены решёнными и перечислены в [160](../block-i-integration-and-deployment/160.integration-plan.md) с ответственными.
