# 080 - User Stories: администратор справочников

**Блок C.** Редакция 1.0 от 2026-09-25, к ревью команды.

Актор [H-01](../block-a-context-and-scope/030.actors.md), роль [R-02](070.role-matrix.md). Формат: "Как <актор>, я хочу <функция>, чтобы <ценность>". Given / When / Then - "Дано / Когда / Тогда". Сценарии - спецификации приёмки, не результаты выполненных тестов. Приоритеты в [090](090.features-epics.md), трассировка в [095](../block-d-verification/095.requirements-check.md).

## US-AD-01 - Создать запись справочника

Как администратор справочников, я хочу создать запись с кодом, наименованием и столбцами справочника, чтобы потребители получили новое значение по стабильному ключу.

**Связи:** UC-03 ([060](../block-b-domain-analysis/060.use-cases.md)); FR-RM-05, FR-RM-14, BR-RM-03.

- **AC-1. Given** справочник `currencies` существует и кода `XYZ` в нём нет; **When** отправляю `POST /currencies` с `code`, `name`, `numeric_code`, `minor_units`; **Then** получаю 201, запись в состоянии ACTIVE с `version` 1, заполненными `id`, `created_at`, `created_by`.
- **AC-2. Given** запись с кодом `XYZ` удалена; **When** создаю запись с тем же кодом; **Then** получаю 409 и подсказку вернуть существующую запись в работу; новой записи нет.
- **AC-3. Given** справочник арендаторский (срез 2); **When** создаю запись без `tenant_id`; **Then** получаю 422 по полю `tenant_id`.

## US-AD-02 - Получить понятную ошибку по полям

Как администратор, я хочу при отклонении записи видеть, какие поля неверны и почему, чтобы исправить их с первого раза.

**Связи:** UC-14; FR-RM-35, NFR-RM-11.

- **AC-1. Given** для `minor_units` допустимы значения 0..6; **When** отправляю `minor_units: 9`; **Then** получаю 422 в формате `application/problem+json` с `errors[]`, где есть путь `minor_units` и причина, а также `request_id` и `trace_id`.
- **AC-2. Given** столбец `currency_code` справочника `countries` ссылается на `currencies`; **When** указываю несуществующий код валюты; **Then** получаю 422 по полю `currency_code`, запись не сохранена.
- **AC-3. Given** отправлено несколько неверных полей; **When** запрос отклонён; **Then** в `errors[]` перечислены все неверные поля, а не только первое.

## US-AD-03 - Исправить наименование или столбцы записи

Как администратор, я хочу частично изменить запись, чтобы поправить ошибку без пересоздания и без смены кода.

**Связи:** UC-04; FR-RM-07, FR-RM-14, FR-RM-24.

- **AC-1. Given** запись ACTIVE с `version` 3; **When** отправляю `PATCH` только с полем `name`; **Then** получаю 200, `name` изменён, остальные столбцы прежние, `version` 4, `updated_at` и `updated_by` обновлены.
- **AC-2. Given** запись существует; **When** отправляю `PATCH` с полем `code` или `id`; **Then** получаю 422 с указанием неизменяемого поля.
- **AC-3. Given** запись в состоянии DELETED; **When** отправляю `PATCH` с полем `name`; **Then** получаю 409, запись не изменена.
- **AC-4 (срез 2). Given** запись с `version` 3; **When** отправляю `PATCH` с `If-Match: "2"`; **Then** получаю 412; без заголовка `If-Match` получаю 428.

## US-AD-04 - Удалить запись, которая больше не нужна

Как администратор, я хочу удалить запись так, чтобы она исчезла из выбора, но ссылки подсистем на неё продолжали работать.

**Связи:** UC-05; FR-RM-10, FR-RM-11, BR-RM-03, BR-RM-04, BR-RM-05.

- **AC-1. Given** запись ACTIVE; **When** отправляю `DELETE /{catalog}/{id}`; **Then** получаю 204, запись в состоянии DELETED с заполненным `deleted_at`, `version` увеличен.
- **AC-2. Given** запись удалена; **When** читаю `GET /{catalog}/{id}` и `GET /{catalog}?code=<код>`; **Then** запись возвращается со `status: DELETED`; в `GET /{catalog}` без флага её нет.
- **AC-3. Given** запись удалена; **When** отправляю `DELETE` повторно; **Then** получаю 409.
- **AC-4. Given** любая запись; **When** смотрю таблицу базы данных; **Then** строка присутствует: физического удаления нет.

## US-AD-05 - Вернуть удалённую запись в работу

Как администратор, я хочу вернуть удалённую запись, чтобы исправить ошибочное удаление без нового кода.

**Связи:** UC-06; FR-RM-12, FR-RM-14.

- **AC-1. Given** запись DELETED; **When** отправляю `PATCH /{catalog}/{id}` с телом `{"deleted_at": null}`; **Then** получаю 200, `status: ACTIVE`, `deleted_at` пуст, `version` увеличен.
- **AC-2. Given** запись ACTIVE; **When** отправляю тот же запрос; **Then** получаю 409.
- **AC-3. Given** запись DELETED; **When** отправляю `PATCH` с `deleted_at` в любом непустом значении; **Then** получаю 422.

## US-AD-06 - Наполнить новый справочник по заявке

Как администратор, я хочу после появления справочника внести начальные данные из заявки, чтобы команда-заказчик могла начать интеграцию.

**Связи:** UC-02, UC-03, UC-13; FR-RM-33, INT-RM-10.

- **AC-1. Given** заявка на `units` принята, миграция применена, `/ready` отвечает 200; **When** открываю справочник в интерфейсе администрирования или вызываю `POST /units` для каждого значения; **Then** все значения из заявки сохранены со `status: ACTIVE`, заявка закрыта со ссылкой на путь и схему.
- **AC-2. Given** в начальных данных есть дубль кода; **When** вношу его; **Then** второй экземпляр отклонён кодом 409, первый сохранён.
- **AC-3 (вопрос 10). Given** справочник стандартный (ISO 4217); **When** решён способ поставки данных; **Then** данные внесены выбранным способом, а не двумя.

## US-AD-07 - Вести записи через интерфейс администрирования (срез 3)

Как администратор, я хочу работать с записями в веб-интерфейсе с формой по столбцам справочника, чтобы не составлять запросы вручную.

**Связи:** UC-13; FR-RM-28, FR-RM-29, NFR-RM-35.

- **AC-1. Given** вошёл через Keycloak с ролью `reference-admin`; **When** открываю `/admin/`; **Then** вижу список справочников из OpenAPI и перехожу к таблице записей.
- **AC-2. Given** открыта форма записи `countries`; **When** заполняю поля; **Then** поля построены по схеме записи, включая `currency_code` с проверкой, а ошибки 422 показаны у соответствующих полей.
- **AC-3. Given** выбрана запись; **When** нажимаю "Удалить" или "Вернуть в работу"; **Then** действие выполняется после подтверждения, состояние и версия в форме обновлены.

## US-AD-08 - Работать с арендаторским справочником (срез 2)

Как администратор, я хочу видеть записи всех арендаторов и создавать записи для нужного арендатора, чтобы вести справочники всей ERP.

**Связи:** UC-11; FR-RM-25, FR-RM-26.

- **AC-1. Given** справочник арендаторский; **When** читаю `GET /{catalog}` без фильтра арендатора; **Then** вижу записи всех арендаторов с полем `tenant_id`.
- **AC-2. Given** создаю запись с `tenant_id` арендатора A; **When** пользователь арендатора B читает её по `id`; **Then** он получает 404.
