# 080 - User Stories: сервис-потребитель

**Блок C.** Редакция 1.0 от 2026-09-25, к ревью команды.

Актор [S-01](../block-a-context-and-scope/030.actors.md): Core, Task Tracker, Planning System, Reports. Роль [R-01](070.role-matrix.md) по client credentials. Формат и обозначения - как в [историях администратора](080.admin-user-stories.md).

## US-CS-01 - Читать запись по стабильному идентификатору

Как сервис-потребитель, я хочу хранить у себя `id` записи и читать её по нему в любой момент, чтобы ссылки в моих документах не ломались.

**Связи:** UC-07; FR-RM-06, BR-RM-02, BR-RM-04.

- **AC-1. Given** сохранил `id` валюты; **When** читаю `GET /currencies/{id}` через год после её удаления; **Then** получаю 200 и запись со `status: DELETED`.
- **AC-2. Given** сохранил `code`; **When** читаю `GET /currencies?code=EUR`; **Then** получаю ту же запись с тем же `id`: код не переназначен другой записи.

## US-CS-02 - Читать справочник под сервисной учётной записью (срез 2)

Как сервис-потребитель, я хочу читать справочники с токеном своей сервисной учётной записи, чтобы интеграция не зависела от пользователя.

**Связи:** UC-10; FR-RM-21, FR-RM-22, FR-RM-23.

- **AC-1. Given** сервисная учётная запись имеет роль `reference-reader`; **When** читаю с её токеном; **Then** получаю 200.
- **AC-2. Given** та же учётная запись; **When** вызываю `POST` или `DELETE`; **Then** получаю 403.
- **AC-3. Given** токен просрочен или подписан чужим ключом; **When** вызываю любую операцию; **Then** получаю 401 без изменения данных.

## US-CS-03 - Не переделывать интеграцию при расширении справочников

Как сервис-потребитель, я хочу, чтобы новые справочники и столбцы появлялись совместимо, чтобы мой код продолжал работать без изменений.

**Связи:** INT-RM-03, NFR-RM-06, NFR-RM-39, NFR-RM-40.

- **AC-1. Given** интегрировался с `currencies`; **When** в `/v1` добавили справочник `units` и столбец `symbol`; **Then** мои запросы к `currencies` возвращают прежние поля плюс необязательный `symbol`; коды ответов и формат ошибок не изменились.
- **AC-2. Given** интегрировался с двумя справочниками; **When** сравниваю их операции; **Then** параметры `code`, `q`, `include_deleted`, `limit`, `offset`, `sort`, формат страницы и ошибок совпадают.

## US-CS-04 - Сослаться на конкретный вызов при ошибке

Как сервис-потребитель, я хочу получать в ошибке идентификаторы запроса и трассы, чтобы команда справочников нашла вызов в журналах.

**Связи:** INT-RM-06, NFR-RM-11, NFR-RM-13.

- **AC-1. Given** передал заголовок `traceparent`; **When** получаю ответ; **Then** в нём `X-Request-Id` и `X-Trace-Id`, а трасса продолжает мою.
- **AC-2. Given** получил 500; **When** читаю тело; **Then** это `application/problem+json` с `request_id` и `trace_id` без внутренних деталей.

## US-CS-05 - Поддерживать локальную копию без событий

Как сервис-потребитель, я хочу перечитывать справочник по API с выбранным мной интервалом, чтобы иметь актуальную копию без подписки на события.

**Связи:** INT-RM-05, вопрос 3 требований.

- **AC-1. Given** кэширую `currencies` на 10 минут; **When** администратор удалил запись; **Then** в течение 10 минут я могу показать её как действующую, а после перечитывания она приходит со `status: DELETED` только при `include_deleted=true` или по `id`.
- **AC-2. Given** мне нужна выборка только изменившихся записей; **When** обращаюсь к команде справочников; **Then** потребность фиксируется в вопросе 3, механизм не обещан.
