# 080 - User Stories: читатель

**Блок C.** Редакция 1.0 от 2026-09-25, к ревью команды.

Актор [H-02](../block-a-context-and-scope/030.actors.md), роль [R-01](070.role-matrix.md). Читатель работает через интерфейс своей подсистемы или запрашивает выгрузку. Формат и обозначения - как в [историях администратора](080.admin-user-stories.md).

## US-RD-01 - Выбрать значение справочника

Как читатель, я хочу видеть в форме своей подсистемы только действующие значения справочника, чтобы не выбрать удалённое.

**Связи:** UC-08; FR-RM-08, FR-RM-11.

- **AC-1. Given** в `currencies` есть записи ACTIVE и DELETED; **When** подсистема запрашивает `GET /currencies?limit=50`; **Then** в ответе только ACTIVE, `total` равен их числу.
- **AC-2. Given** документ подсистемы ссылается на удалённую валюту; **When** подсистема читает её `GET /currencies/{id}`; **Then** запись возвращается со `status: DELETED`, документ отображается корректно.
- **AC-3. Given** справочник содержит 1 200 записей; **When** запрашиваю `limit=200&offset=400&sort=name:asc`; **Then** получаю 200 записей с 401-й по 600-ю в порядке названий и `total` 1 200.

## US-RD-02 - Найти запись по коду или названию

Как читатель, я хочу найти запись по точному коду или по части названия, чтобы быстро выбрать нужное значение.

**Связи:** UC-08; FR-RM-06, FR-RM-08.

- **AC-1. Given** есть запись с кодом `EUR`; **When** запрашиваю `GET /currencies?code=EUR`; **Then** получаю ровно одну запись, `total` 1.
- **AC-2. Given** есть записи `Euro` и `Eurozone unit`; **When** запрашиваю `q=eur`; **Then** получаю обе: поиск по префиксу кода и вхождению в название без учёта регистра.
- **AC-3. Given** код не существует; **When** запрашиваю `code=XXX`; **Then** получаю пустой `items[]` и `total` 0, а не 404.

## US-RD-03 - Выгрузить справочник в Excel

Как читатель, я хочу выгрузить отобранные записи в `.xlsx`, чтобы работать со справочником вне системы.

**Связи:** UC-09; FR-RM-40, FR-RM-41, FR-RM-42, NFR-RM-44, NFR-RM-45.

- **AC-1. Given** отобрал записи фильтром `q=e&sort=code:asc`; **When** запрашиваю `GET /currencies` с заголовком `Accept` для `.xlsx`; **Then** получаю файл, в котором строки соответствуют всему отбору, а не одной странице, в том же порядке.
- **AC-2. Given** файл получен; **When** открываю его в Excel; **Then** первая строка - имена столбцов, есть `id`, `code`, `status` и столбцы справочника; предупреждений о повреждении нет; `numeric_code` `036` сохранён как текст.
- **AC-3. Given** запросил выгрузку с `include_deleted=true`; **When** файл открыт; **Then** удалённые записи присутствуют со `status: DELETED` и заполненным `deleted_at`.

## US-RD-04 - Получить понятный отказ при слишком большой выгрузке

Как читатель, я хочу при превышении предела выгрузки получить понятный ответ, чтобы сузить отбор и повторить.

**Связи:** UC-09; FR-RM-43, NFR-RM-42.

- **AC-1. Given** предел выгрузки 50 000 записей и отбор даёт 60 000; **When** запрашиваю `.xlsx`; **Then** получаю 413 с сообщением о пределе и предложением сузить отбор; файл не формируется.
- **AC-2. Given** тот же отбор; **When** запрашиваю обычную страницу JSON; **Then** получаю 200: предел относится только к выгрузке.

## US-RD-05 - Работать с записями своего арендатора (срез 2)

Как читатель арендатора, я хочу видеть в арендаторском справочнике только записи своей организации, чтобы не путать чужие значения со своими.

**Связи:** UC-11; FR-RM-25, FR-RM-26.

- **AC-1. Given** токен содержит арендатора A; **When** читаю арендаторский справочник; **Then** в ответе только записи с `tenant_id` A.
- **AC-2. Given** знаю `id` записи арендатора B; **When** читаю её; **Then** получаю 404.
- **AC-3. Given** справочник системный; **When** читаю его; **Then** записи доступны независимо от арендатора.
