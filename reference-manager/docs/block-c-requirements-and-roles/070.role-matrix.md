# 070 - Роли и права доступа Reference Manager

**Блок C.** Редакция 1.1 от 2026-09-26, к ревью команды.
Основания: [Системные требования, разделы 3, 4.5, 4.9](../system-requirements.md), [акторы](../block-a-context-and-scope/030.actors.md), [конституция 2.0.0, принцип VII](../../.specify/memory/constitution.md).

Мультиарендности нет (решение 2026-09-26): права роли действуют на все справочники и все записи. Разграничение по организации или по отдельному справочнику отсутствует (BR-RM-13).

## 1. Уровни доступа

| Уровень | Обозначение | Операции API |
| --- | --- | --- |
| create | C | `POST /{catalog}` |
| read | R | `GET /{catalog}`, `GET /{catalog}/{id}`, `GET /{catalog}/{id}?version=`, `GET /{catalog}/{id}/history` |
| update | U | `PATCH /{catalog}/{id}`, включая возврат в работу `{"deleted_at": null}` |
| execute | X | Выгрузка `.xlsx`: `GET /{catalog}` с заголовком `Accept` |
| delete | D | `DELETE /{catalog}/{id}` (мягкое удаление) |

## 2. Роли

| ID | Роль | Уровни | Где определена | Кому выдаётся | Акторы |
| --- | --- | --- | --- | --- | --- |
| R-00 | Внутренняя сеть без токена | C R U X D | Срез 1: аутентификации нет, сервис недоступен снаружи (NFR-RM-30) | Всем вызывающим внутри сети стенда | Все |
| R-01 | `reference-reader` | R X | Claim ролей токена Keycloak (FR-RM-22) | Всем пользователям ERP и сервисным учётным записям подсистем | H-02, H-03, S-01 |
| R-02 | `reference-admin` | C R U X D | Claim ролей токена Keycloak (FR-RM-22) | Участникам команды справочников | H-01 |
| R-03 | Инженер справочников | репозиторий, не API | CODEOWNERS | Участникам команды справочников | H-04 |

Роли редактора нет: записи ведёт только команда справочников (решение 2026-09-15). Путь к ролям в токене (`realm_access.roles` или `resource_access.<client>.roles`) не согласован (вопрос 6 требований); рекомендация - клиентские роли клиента `reference-manager`.

## 3. Матрица прав на операции API

| Операция | Уровень | R-00 срез 1 | R-01 reader | R-02 admin |
| --- | --- | --- | --- | --- |
| `POST /{catalog}` создать запись | C | да | нет, 403 | да |
| `GET /{catalog}` страница записей, любые фильтры, `include_deleted` | R | да | да | да |
| `GET /{catalog}/{id}` запись, включая удалённую | R | да | да | да |
| `GET /{catalog}/{id}?version=N` состояние на версию | R | да | да | да |
| `GET /{catalog}/{id}/history` история записи | R | да | да | да |
| `GET /{catalog}` с `Accept` `.xlsx` выгрузка | X | да | да | да |
| `PATCH /{catalog}/{id}` изменить поля | U | да | нет, 403 | да |
| `PATCH /{catalog}/{id}` с `{"deleted_at": null}` вернуть в работу | U | да | нет, 403 | да |
| `DELETE /{catalog}/{id}` удалить | D | да | нет, 403 | да |
| `/admin/` интерфейс администрирования | - | - | вход возможен, действия C U D скрыты и отклоняются сервером | да |
| `GET /health`, `GET /ready` | - | без токена | без токена | без токена |
| `GET /metrics` по флагу конфигурации | - | внутренняя сеть | внутренняя сеть | внутренняя сеть |
| Создание, изменение, удаление справочника через API | - | операции нет (FR-RM-38) | нет | нет |
| Изменение или удаление строк истории | - | операции нет; роль БД без UPDATE и DELETE (FR-RM-45) | нет | нет |

Права проверяются в сервисном слое перед операцией по паре "роль - уровень", а не только в маршрутизаторе (FR-RM-23). Интерфейс скрывает недоступные действия, но сервер проверяет права независимо (FR-RM-28).
