# 070 - Роли и права доступа Reference Manager

**Блок C.** Редакция 1.0 от 2026-09-25, к ревью команды.
Основания: [Системные требования, разделы 3, 4.5, 4.6](../system-requirements.md), [акторы](../block-a-context-and-scope/030.actors.md), [конституция, принцип VII](../../.specify/memory/constitution.md).

## 1. Роли

| ID | Роль | Где определена | Кому выдаётся | Акторы |
| --- | --- | --- | --- | --- |
| R-00 | Внутренняя сеть без токена | Срез 1: аутентификации нет, сервис недоступен снаружи (NFR-RM-30) | Всем вызывающим внутри сети стенда | Все |
| R-01 | `reference-reader` | Claim ролей токена Keycloak (FR-RM-22) | Всем пользователям ERP и сервисным учётным записям подсистем | H-02, H-03, S-01 |
| R-02 | `reference-admin` | Claim ролей токена Keycloak (FR-RM-22) | Участникам команды справочников | H-01 |
| R-03 | Инженер справочников | CODEOWNERS репозитория, не роль API | Участникам команды справочников | H-04 |

Роли редактора нет: записи ведёт только команда справочников (решение 2026-09-15). Путь к ролям в токене (`realm_access.roles` или `resource_access.<client>.roles`) и имя claim арендатора не согласованы (вопросы 5, 6 требований).

## 2. Матрица прав на операции API

Уровни: C - создать, R - читать, U - изменить, D - удалить (мягко), X - выполнить действие. "да (свой)" означает "в пределах арендатора из токена".

| Операция | Уровень | R-00 срез 1 | R-01 reader | R-02 admin |
| --- | --- | --- | --- | --- |
| `POST /{catalog}` создать запись | C | да | нет, 403 | да |
| `GET /{catalog}` страница записей | R | да | да | да |
| `GET /{catalog}` с `include_deleted=true` | R | да | да | да |
| `GET /{catalog}` с `Accept` `.xlsx` | X | да | да | да |
| `GET /{catalog}/{id}` запись, включая удалённую | R | да | да | да |
| `PATCH /{catalog}/{id}` изменить поля | U | да | нет, 403 | да |
| `PATCH /{catalog}/{id}` с `{"deleted_at": null}` вернуть в работу | U | да | нет, 403 | да |
| `DELETE /{catalog}/{id}` удалить | D | да | нет, 403 | да |
| Записи арендаторского справочника своего арендатора | R | - | да (свой) | да |
| Записи арендаторского справочника чужого арендатора | R | - | нет, 404 | да, все арендаторы |
| Создание записи в арендаторском справочнике | C | - | нет | да, `tenant_id` указывается явно |
| `/admin/` интерфейс администрирования | X | - | вход возможен, действия записи скрыты и отклоняются сервером | да |
| `GET /health`, `GET /ready` | R | да, без токена | да, без токена | да, без токена |
| `GET /metrics` по флагу конфигурации | R | внутренняя сеть | внутренняя сеть | внутренняя сеть |
| Создание, изменение, удаление справочника через API | - | нет, операции не существует (FR-RM-38) | нет | нет |

Права проверяются в сервисном слое перед операцией, а не только в маршрутизаторе (FR-RM-23). Интерфейс скрывает недоступные действия, но сервер проверяет права независимо (FR-RM-28).

## 3. Права на уровне репозитория и инфраструктуры

| Действие | R-03 Инженер | Infra | Команда-заказчик |
| --- | --- | --- | --- |
| Подать заявку на справочник (issue) | да | - | да |
| Принять или отклонить заявку | да | - | нет |

| Применить миграции | нет, только через задание | да, задание миграций | нет |
| Изменить конфигурацию окружения, секреты | нет | да | нет |
| Прямой доступ к базе данных | нет, кроме задания миграций | нет | нет (INT-RM-01) |

## 5. Соответствие акторов и ролей

| Актор | Роль | Обоснование |
| --- | --- | --- |
| H-01 Администратор справочников | R-02 | Ведёт записи всех справочников, включая арендаторские |
| H-02 Читатель | R-01 | Читает и выгружает |
| H-03 Команда-заказчик | R-01 через свою подсистему | Прав на запись нет по решению 2026-09-15 |
| H-04 Инженер | R-03 и R-02 | Меняет код и схему, в API действует как администратор |
| S-01 Сервисы-потребители | R-01 по client credentials | Только чтение |
| S-04 Infra | без роли API | Служебные точки не требуют токена |
