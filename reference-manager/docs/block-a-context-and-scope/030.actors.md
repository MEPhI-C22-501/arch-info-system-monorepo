# 030 - Акторы Reference Manager

**Блок A.** Редакция 1.0 от 2026-09-25, к ревью команды.
Основания: [Системные требования, раздел 3](../system-requirements.md#3-пользователи-и-роли), [Видение, "Пользователи и их цели"](../vision.md), [контекст](020.system-context.md).

## 1. Люди

| ID | Актор | Должность или роль в предметной области | Действия в системе | Роль доступа |
| --- | --- | --- | --- | --- |
| H-01 | Администратор справочников | Участник команды справочников, отвечает за содержание НСИ | Создаёт записи, исправляет наименования и столбцы, удаляет ненужные записи, возвращает удалённые в работу, выгружает справочники, наполняет новый справочник по заявке; работает через интерфейс администрирования или напрямую через API | R-02 `reference-admin` |
| H-02 | Читатель | Любой сотрудник, работающий в подсистемах ERP: бухгалтер, планировщик, руководитель проекта, аналитик отчётов | Выбирает значение справочника в форме своей подсистемы, просматривает справочник, выгружает его в `.xlsx`; в сервис напрямую обращается только через интерфейсы подсистем или выгрузку | R-01 `reference-reader` |
| H-03 | Команда-заказчик | Аналитик или разработчик подсистемы ERP (Core, Task Tracker, Planning System, Reports) | Подаёт заявку на справочник как issue по шаблону: код, название, столбцы с типами и ограничениями, признак арендаторского справочника, начальные данные; уточняет состав столбцов; после закрытия заявки берёт путь и схему записи из OpenAPI и интегрирует свою подсистему | R-01 через свою подсистему; прав на запись нет |
| H-04 | Инженер команды справочников | Разработчик сервиса, владелец кода (CODEOWNERS) | Проверяет заявку на соответствие BR-RM-08, пишет миграцию с таблицей, регистрирует пять обработчиков, дополняет OpenAPI и тесты, проводит pull request | R-03 на уровне репозитория; в API - как H-01 |

H-01 и H-04 обычно одни и те же люди; разделены, потому что первый действует через API и интерфейс, второй через репозиторий.

## 2. Внешние системы

| ID | Система | Протокол и сценарий интеграции | Что делает по отношению к сервису |
| --- | --- | --- | --- |
| S-01 | Сервисы-потребители: Core, Task Tracker, Planning System, Reports | REST/JSON под `/api/reference-data/v1` с Bearer-токеном сервисной учётной записи (client credentials, роль `reference-reader`); чтение по `id`, постраничное чтение с фильтром `code=`, кэш на своей стороне | Только читают. Не создают и не изменяют записи, не подписываются на события: их нет |
| S-02 | Keycloak | OIDC; пользователи входят через Authorization Code с PKCE, сервисы получают токены по client credentials; сервис загружает открытые ключи по JWKS или получает их из конфигурации (вопрос 7) | Выдаёт токены с ролями и признаком арендатора |
| S-03 | OpenTelemetry Collector | OTLP gRPC 4317 или HTTP 4318 (вопрос 8) | Принимает трассы, метрики, журналы |
| S-04 | Infra: GitHub Actions, Kubernetes, задание миграций | Сборка образа по `reference-manager/**`, Job миграций перед Deployment, readiness и liveness по служебным точкам, сетевая политика egress | Развёртывает сервис и его базу; хранит issues заявок |

## 3. Кто чем владеет

| Актор | Создаёт | Читает | Изменяет и удаляет | Добавляет справочники |
| --- | --- | --- | --- | --- |
| H-01 Администратор | записи | всё | записи | нет, через H-04 |
| H-02 Читатель | - | записи, выгрузки | - | - |
| H-03 Команда-заказчик | заявки | записи через свою подсистему | - | инициирует заявкой |
| H-04 Инженер | миграции, обработчики, спецификацию | всё | код и схему | да, pull request |
| S-01 Потребители | - | записи по API | - | - |

Матрица прав по операциям API - в [070](../block-c-requirements-and-roles/070.role-matrix.md).
