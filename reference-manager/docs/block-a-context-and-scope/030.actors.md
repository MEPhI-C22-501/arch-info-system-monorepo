# 030 - Actors

> Формат - см. [состав документов](../../../task-tracker/docs/documents-composition.md), документ 030.
> Источник - [системные требования, раздел 3](../system-requirements.md#3-пользователи-и-роли), [видение](../vision.md), [контекст](020.system-context.md).

## 1. Люди

| ID | Актор | Должность или роль в предметной области | Действия в системе | Роль доступа |
| --- | --- | --- | --- | --- |
| H-01 | Администратор справочников | Участник команды справочников, отвечает за содержание НСИ | Создаёт записи, исправляет наименования и поля, удаляет ненужные записи, восстанавливает удалённые, читает историю, выгружает справочники, наполняет новый справочник начальными данными; работает через интерфейс администрирования или API | R-02 `reference-admin`: create, read, update, execute, delete |
| H-02 | Читатель | Сотрудник, работающий в подсистемах ERP: бухгалтер, планировщик, руководитель проекта, аналитик отчётов | Выбирает значение справочника в форме своей подсистемы, просматривает справочник и историю записи, выгружает в `.xlsx`; в сервис напрямую обращается только через интерфейсы подсистем или выгрузку | R-01 `reference-reader`: read, execute |
| H-04 | Инженер справочников | Разработчик сервиса, владелец кода | Реализует справочники из состава первой версии: хранилище, коллекцию и методы, схему в спецификации, тесты; выпускает новые версии сервиса | R-03 на уровне репозитория; в API - как H-01 |

H-01 и H-04 обычно одни и те же люди; разделены, потому что первый действует через API и интерфейс, второй через репозиторий. H-03 (команда-заказчик) отозван 2026-09-27.

## 2. Внешние системы

| ID | Система | Протокол и сценарий интеграции | Что делает по отношению к сервису |
| --- | --- | --- | --- |
| S-01 | Сервисы-потребители: Core, Task Tracker, Planning System, Reports | REST/JSON под `/v1` с Bearer-токеном сервисной учётной записи (роль `reference-reader`); `List` с фильтром, `Get` по имени, чтение истории; кэш на своей стороне | Только читают. Не создают и не изменяют записи, не подписываются на события: их нет |
| S-02 | Keycloak | OIDC; пользователи входят через Authorization Code с PKCE, сервисы получают токены по client credentials; сервис загружает открытые ключи по JWKS или получает их из конфигурации (вопрос 7) | Выдаёт токены с ролями |
| S-03 | OpenTelemetry Collector | OTLP (транспорт - вопрос 8) | Принимает трассы, метрики, журналы |
| S-04 | Infra: GitHub Actions, Kubernetes, задание изменений схемы | Сборка образа по `reference-manager/**`, Job изменений схемы перед Deployment, readiness и liveness по служебным точкам, сетевая политика egress | Развёртывает сервис и его хранилище |

## 3. Кто чем владеет

| Актор | Создаёт | Читает | Изменяет, удаляет, восстанавливает | Добавляет справочники |
| --- | --- | --- | --- | --- |
| H-01 Администратор | записи | всё, включая историю | записи | нет, через H-04 |
| H-02 Читатель | - | записи, история, выгрузки | - | - |
| H-04 Инженер | хранилище, методы, спецификацию | всё | код и схему | да, новой версией сервиса |
| S-01 Потребители | - | записи, история | - | - |

Матрица прав по операциям API - в [070](../block-c-requirements-and-roles/070.role-matrix.md).
