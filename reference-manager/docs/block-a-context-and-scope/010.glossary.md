# 010 - Глоссарий Reference Manager

**Блок A.** Редакция 1.0 от 2026-09-25, к ревью команды.
Основания: [Видение](../vision.md), [Системные требования, раздел 2](../system-requirements.md#2-термины), [конституция](../../.specify/memory/constitution.md).

## 1. Термины предметной области

| Термин | Определение | Контекст / модуль ERP | Синонимы |
| --- | --- | --- | --- |
| НСИ | Нормативно-справочная информация: данные, которые классифицируют или описывают бизнес-сущности, но сами бизнес-сущностями не являются. | Reference Manager, BR-RM-08 | Справочные данные, классификаторы, master data |
| Справочник | Именованный набор однотипных справочных значений, например валюты или страны. Хранится в отдельной таблице базы данных и обслуживается пятью обработчиками HTTP. Код справочника совпадает с именем таблицы и сегментом пути в API. | Reference Manager, BR-RM-01 | Таблица справочника, каталог |
| Запись справочника | Одно значение внутри справочника, например EUR в справочнике валют. Корневая сущность сервиса. | Reference Manager, FR-RM-05 | Элемент справочника, строка |
| Общие столбцы | Столбцы, одинаковые во всех таблицах справочников: `id`, `code`, `name`, `version`, `created_at`, `created_by`, `updated_at`, `updated_by`, `deleted_at`. | Reference Manager, FR-RM-34 | Системные поля |
| Столбцы справочника | Типизированные столбцы, которые есть только у данного справочника, например числовой код валюты. Ограничения задаются в миграции. | Reference Manager, FR-RM-35 | Атрибуты, поля справочника |
| Пять обработчиков | Операции API каждого справочника: создание записи, постраничное чтение, чтение одной записи, частичное изменение, удаление. | Reference Manager, FR-RM-37 | Пять операций, CRUD-ручки |
| Код справочника | Идентификатор справочника в нижнем регистре латиницей, например `currencies`. Равен имени таблицы и сегменту `{catalog}` пути API. | Reference Manager, FR-RM-37 | Имя справочника |
| Идентификатор записи (id) | Суррогатный ключ записи в формате UUID версии 7. Генерируется сервисом и никогда не меняется. | Reference Manager, NFR-RM-14 | UUID записи |
| Код записи (code) | Человекочитаемый ключ записи, уникальный в пределах справочника, включая удалённые записи. Задаётся при создании и не меняется. | Reference Manager, BR-RM-02, BR-RM-03 | Ключ, стабильный код |
| Состояние записи | ACTIVE или DELETED. Возвращается в поле `status`, вычисляется по значению `deleted_at` и не редактируется напрямую. | Reference Manager, FR-RM-09 | Статус записи |
| Удаление | Перевод записи в состояние DELETED: строка остаётся в таблице, получает отметку `deleted_at`, исчезает из списков по умолчанию и остаётся доступной по `id` и `code`. Физического удаления нет. | Reference Manager, FR-RM-10 | Мягкое удаление, soft delete |
| Возврат в работу | Перевод удалённой записи обратно в ACTIVE запросом `PATCH` с телом `{"deleted_at": null}`. | Reference Manager, FR-RM-12 | Восстановление, restore |
| Версия записи | Порядковый номер состояния записи. Увеличивается при каждой операции записи, включая удаление и возврат в работу. Со среза защиты API используется в заголовках `ETag` и `If-Match`. | Reference Manager, FR-RM-14, FR-RM-24 | version |
| Заявка на справочник | Обращение команды-потребителя: код и название справочника, назначение, столбцы с типами и ограничениями, признак арендаторского справочника, начальные данные. Оформляется как issue по шаблону. | Reference Manager, INT-RM-07 | Запрос на справочник |
| Команда справочников | Команда, владеющая сервисом. Принимает заявки, добавляет справочники миграцией и обработчиками, ведёт записи. | Reference Manager, CODEOWNERS | Команда Reference Manager |
| Команда-заказчик | Команда подсистемы ERP, которая подаёт заявку на справочник и после его появления читает данные по API. Прав на запись не имеет. | Core, Task Tracker, Planning System, Reports | Команда-потребитель |
| Администратор справочников | Участник команды справочников с ролью `reference-admin`. Создаёт, изменяет, удаляет записи всех справочников и возвращает их в работу. | Reference Manager, FR-RM-22 | Администратор НСИ |
| Читатель | Любой аутентифицированный пользователь или сервис ERP с ролью `reference-reader`. Читает записи и выгружает их в файл. | Все подсистемы ERP | reference-reader |
| Сервис-потребитель | Подсистема ERP, которая читает справочники по REST API под своей сервисной учётной записью и кэширует значения у себя. | Core, Task Tracker, Planning System, Reports | Потребитель, клиент API |
| Системный справочник | Справочник, записи которого общие для всех арендаторов. Таблица не содержит `tenant_id`. | Reference Manager, FR-RM-25 | Общий справочник |
| Арендаторский справочник | Справочник, записи которого разделены по арендаторам. Таблица содержит `tenant_id`, код записи уникален в пределах арендатора. | Reference Manager, FR-RM-25, FR-RM-26 | Tenant-scoped справочник |
| Арендатор | Обособленная организация, работающая в ERP. Признак арендатора передаётся в claim токена пользователя; имя claim не согласовано (вопрос 5). | Keycloak, все подсистемы | Tenant |
| Постраничное чтение | Операция `GET /{catalog}` с параметрами `limit`, `offset`, фильтрами и сортировкой. Возвращает страницу записей и общее количество. | Reference Manager, FR-RM-08 | Список записей, list |
| Фильтр по коду | Параметр точного совпадения `code=` в постраничном чтении. Заменяет отдельную операцию чтения по коду. | Reference Manager, FR-RM-06 | Чтение по коду |
| Выгрузка | Файл `.xlsx` с записями, отобранными теми же фильтрами, что и постраничное чтение. Выбирается заголовком `Accept`. | Reference Manager, FR-RM-40 | Экспорт, export |
| Схема записи | Описание полей записи справочника в спецификации OpenAPI: общие поля плюс столбцы справочника. По одной схеме на справочник. По ней строятся формы интерфейса администрирования. | Reference Manager, FR-RM-38 | Схема OpenAPI |
| Миграция справочника | SQL-миграция golang-migrate, создающая таблицу справочника с общими столбцами, столбцами справочника, ограничениями и индексами, либо добавляющая столбец. | Reference Manager, FR-RM-33, FR-RM-36 | Миграция таблицы |
| Задание миграций | Отдельный запуск `migrate` до старта новой версии приложения: цель Taskfile локально, объект Job в Kubernetes. | Infra, NFR-RM-21 | Job миграций |
| Проверка готовности | Ответ `GET /ready` кодом 200, если база данных отвечает на ping и версия схемы миграций не ниже ожидаемой. | Infra, FR-RM-31 | Readiness probe |
| Ссылка между справочниками | Столбец справочника, значение которого обязано существовать в другом справочнике. Задаётся ограничением FOREIGN KEY в миграции. | Reference Manager, FR-RM-35 | Внешний ключ |
| Идентификаторы запроса и трассы | Заголовки `X-Request-Id` и `X-Trace-Id` в каждом ответе; повторяются в теле ошибки и журналах, чтобы потребитель мог сослаться на вызов. | Reference Manager, NFR-RM-13, INT-RM-06 | request_id, trace_id |
| Ошибка по полям | Ответ кодом 422 в формате RFC 9457 со списком `errors[]`, где каждая ошибка привязана к имени поля. | Reference Manager, FR-RM-35 | Ошибка валидации |
| Стандартный классификатор | Справочник, значения которого заданы внешним стандартом: ISO 4217 (валюты), ISO 3166-1 (страны), ISO 639-1 (языки), UN/ECE Rec 20 (единицы измерения). | Reference Manager, раздел 9.2 требований | Международный справочник |

## 2. Соответствие терминам смежных модулей

| Термин смежного модуля | Модуль | Соотношение с терминами сервиса |
| --- | --- | --- |
| Мастер-данные, классификатор | Planning System | То же, что НСИ и справочник. Planning System ожидает получать классификаторы событиями; сервис событий не публикует (INT-RM-05), ожидание не согласовано. |
| Статус задачи, приоритет задачи, вид задачи | Task Tracker | Task Tracker ведёт их сам. Reports просит те же значения у сервиса. Владелец не согласован (вопрос 1 требований). Термины сервиса на них не распространяются до решения. |
| Серьёзность дефекта | Reports, Task Tracker | В Task Tracker атрибута нет. Владелец и состав не согласованы. |
| Разрез отчёта | Reports | Значения разрезов берутся из справочников сервиса по `code`, кэшируются на стороне Reports. |
| Сотрудник, проект, календарь рабочего времени | Reports, Planning System, Task Tracker | Бизнес-сущности, в сервисе не хранятся (BR-RM-08, раздел 9.3 требований). |
| Пользователь, роль, арендатор | Keycloak | Сервис не хранит пользователей; роли и арендатор приходят в токене. |

## 3. Термины, выведенные из употребления

| Термин | Причина |
| --- | --- |
| Catalog, CatalogItem, схема атрибутов, JSON Schema атрибутов | Относились к обобщённой модели хранения (одна таблица элементов с JSON-атрибутами). Модель отклонена 2026-09-17 в пользу таблицы на справочник. В конституции принцип IV ещё упоминает JSON Schema и требует поправки. |
| INACTIVE | Третье состояние записи отменено 2026-09-17. Значение, которое больше не нужно, удаляется; ссылки остаются рабочими. |
| Редактор справочников арендатора | Роли редактора нет: записи ведёт только команда справочников (решение 2026-09-15). |
| Событие изменения справочника, outbox, журнал аудита | Исключены 2026-09-14 вместе с Kafka и историей изменений. |
