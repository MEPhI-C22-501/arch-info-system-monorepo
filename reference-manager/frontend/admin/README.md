# Админ-панель на имитированных данных (шаг 1 интерфейса)

Интерфейс администрирования Reference Manager - отдельный компонент со своим образом (ADR-017). Это его первый шаг: все экраны и переходы из [110](../../documents/110.ui-ux.md) работают без сервиса. Сервис заменён имитацией в памяти страницы, которая повторяет контракт [130](../../documents/130.api-contracts.md): те же методы, параметры, поля записей и ошибки в формате `google.rpc.Status`. Второй шаг - подключение к API и вход через Keycloak.

## Как открыть

| Способ | Что сделать |
| --- | --- |
| Без сборки | Открыть `index.html` в браузере |
| Локальный стенд | `task up` из `reference-manager/`, затем `http://localhost:8081/admin/` (порт - `REFERENCE_MANAGER_UI_PORT` в `deployments/.env`) |
| Только образ интерфейса | `task build:reference-manager-ui`, образ `erp/reference-manager-ui:latest`, nginx отдаёт панель по `/admin/` и `ok` по `/healthz` |

Проверки: `task tests:frontend` запускает тесты имитации (`node --test`, Node 18 и новее, без зависимостей). `task lint:docker` проверяет Dockerfile интерфейса.

## Состав

| Файл | Назначение |

| `index.html`, `app.css` | Разметка и стили. Скрипты и стили лежат в отдельных файлах, встроенных нет: страница работает под `Content-Security-Policy` без `unsafe-inline` (замечание З-2 отчёта проверки безопасности) |
| `js/dom.js` | Построение DOM из текстовых узлов. Разметка из строк не собирается, значения записей не могут стать кодом (замечание З-1) |
| `js/catalogs.js` | Схемы справочников первой версии, группы G-1..G-3 и роли из [070](../../documents/070.role-matrix.md) |
| `js/mock-data.js` | Образцовые записи и история изменений |
| `js/filter.js` | Разбор фильтра AIP-160: сравнения, `AND`, `OR`, `NOT`, скобки, `поле:*` |
| `js/mock-api.js` | Имитация сервиса: List с фильтром, сортировкой и страницами, Get, Create, Update с `update_mask`, Delete, Undelete, ListRevisions, выгрузка, Dismiss, SyncAccount, проверка ролей, имитация Keycloak Admin REST API |
| `js/xlsx.js` | Формирование файла `.xlsx` без библиотек: текст пишется строковыми ячейками, формула из значения не получится (NFR-RM-45) |
| `js/app.js` | Экраны S-01..S-05, маршруты в фрагменте адреса, черновики форм, подтверждения |

Образ собирается из `deployments/docker/reference-manager-ui.dockerfile`, конфигурация nginx `deployments/configs/reference-manager-ui/local/reference-manager-ui.conf` в образ не входит и монтируется при запуске (см. `deployments/docker-compose.yaml`). Папка `tests/` и этот файл в образ не попадают.

## Что имитируется

Шапка страницы заменяет вход: переключатель роли задаёт токен (admin, hr-admin, reader, hr-reader, учётная запись без ролей, запрос без токена). Права проверяет имитация сервиса, а не только интерфейс: роль без нужного уровня получает PERMISSION_DENIED, запрос без токена - UNAUTHENTICATED. Полоса "Имитация сервиса" управляет доступностью Keycloak и пределом выгрузки, кнопка "Сбросить данные" возвращает образцовые записи.

| Поведение сервиса | Как воспроизведено |
| --- | --- |
| Приём сотрудника | `Create` сохраняет профиль с `account_state: PENDING`, создаёт учётную запись в имитации Keycloak и отвечает ENABLED. При выключенном Keycloak ответ UNAVAILABLE с `ACCOUNT_PENDING`, профиль остаётся PENDING |
| Повтор операции | `SyncAccount` доводит незавершённую операцию по её идентификатору, второй учётной записи с тем же логином не возникает |
| Увольнение | `Dismiss` переводит в DISMISSED, закрывает датой действующие назначение и оклад, блокирует учётную запись. Повторное увольнение - FAILED_PRECONDITION |
| Изменение ФИО или почты | `Update` передаёт изменение в учётную запись тем же обменом, при сбое состояние PENDING |
| Датированные записи | Пересечение периодов назначений и окладов одного сотрудника отклоняется ошибкой у полей дат, дата окончания раньше даты начала - ошибкой у `end_date`, идентификатор назначает имитация |
| Оргструктура | Ссылка `parent`, образующая цикл, отклоняется |
| История | Каждая операция записи добавляет ревизию с различиями, состояние на ревизию складывается из различий |
| Выгрузка | Текущий отбор уходит в файл `.xlsx`, сверх предела - отказ `EXPORT_TOO_LARGE` |
| Удаление сотрудника | До увольнения отклоняется с `EMPLOYEE_ACTIVE` (FR-RM-58) |

Два допущения, которых нет в требованиях: логин сотрудника после создания не меняется, а увольнение сотрудника с незавершённой операцией учётной записи требует сначала выполнить повтор.

## Сценарии проверки

Сценарии P-01..P-10 описаны в [115](../../documents/115.live-prototype.md). Для P-07 выключите Keycloak в полосе имитации перед созданием сотрудника, затем включите и нажмите "Повторить операцию с учётной записью" в карточке. Для P-04 уменьшите предел выгрузки до числа меньше размера отбора. Для P-10 переключайте роли reader и hr-reader на карточке сотрудника.

## Упрощения шага 1

Перечень упрощений и условия их снятия ведутся в [115](../../documents/115.live-prototype.md). На шаге 2 файл `js/mock-api.js` заменяется клиентом поверх `fetch` с теми же сигнатурами методов, переключатель роли и полоса имитации убираются, вход идёт через Keycloak.
