# Админ-панель (шаг 2 интерфейса: на API сервиса)

Интерфейс администрирования Reference Manager - отдельный компонент со своим образом (ADR-017). С 2026-10-31 панель работает на API сервиса по контракту [130](../../documents/130.api-contracts.md) (ADR-022) и входит через Keycloak: Authorization Code с PKCE, токен в памяти вкладки, роли из токена. Имитации сервиса и переключателя роли больше нет. Экраны S-01..S-05 из [110](../../documents/110.ui-ux.md).

## Как открыть

| Способ | Что сделать |
| --- | --- |
| Локальный стенд | `task up` из `reference-manager/`, затем `http://localhost:8081/admin/` (порт - `REFERENCE_MANAGER_UI_PORT` в `deployments/.env`). Данные набора `deployments/seed/demo.sql` уже загружены, учётные записи сотрудников создаёт `task demo:accounts` |
| Вход | Пользователи локального realm, пароль равен логину: `admin` (reference-admin), `hr-admin` (reference-hr-admin), `reader`, `hr-reader`, `outsider` (без ролей, экран отказа S-04) |
| Только образ интерфейса | `task build:reference-manager-ui`, образ `erp/reference-manager-ui:latest`; nginx отдаёт панель по `/admin/`, проксирует `/v1/` в сервис и отвечает `ok` по `/healthz` |

Проверки: `task tests:frontend` запускает тесты панели (`node --test`, Node 18 и новее, без зависимостей). `task lint:docker` проверяет Dockerfile интерфейса.

## Состав

| Файл | Назначение |
| --- | --- |
| `index.html`, `app.css` | Разметка и стили. Скрипты и стили лежат в отдельных файлах, встроенных нет: страница работает под `Content-Security-Policy` без `unsafe-inline` (замечание З-2 отчёта проверки безопасности) |
| `js/config.js` | Настройки среды: путь API (`/v1`), адрес Keycloak, realm, клиент. Другой стенд монтирует свою копию файла по пути `/admin/js/config.js` |
| `js/dom.js` | Построение DOM из текстовых узлов. Разметка из строк не собирается, значения записей не могут стать кодом (замечание З-1) |
| `js/auth.js` | Вход через Keycloak: PKCE S256, обмен кода на токен, обновление токена до истечения, выход. Роли читаются из `realm_access.roles` и `resource_access.reference-manager.roles` |
| `js/api.js` | Клиент API поверх `fetch`: `List` с `filter`, `order_by`, `pageSize`, `pageToken`, `allowDeleted`; `Get`, `Create`, `Update` с `updateMask`, `Delete` и `force`, `export`, ревизии, `dismiss`, `syncAccount`. Ошибки `{message, details}` с `X-Trace-Id` ответа, повтор при 429 |
| `js/catalogs.js` | Схемы справочников первой версии по [130](../../documents/130.api-contracts.md) и [120](../../documents/120.data-model.md), группы G-1..G-3 и роли из [070](../../documents/070.role-matrix.md), маска обновления, типизация тела запроса |
| `js/jsonpatch.js` | Применение операций JSON Patch ревизий: состояние записи на ревизию собирается из ревизий сервиса |
| `js/app.js` | Экраны S-01..S-05, маршруты в пути `/admin/{коллекция}/{идентификатор}`, черновики форм, подтверждения, карточка сотрудника |
| `tests/` | Тесты клиента API, входа, схем и JSON Patch |

Образ собирается из `deployments/docker/reference-manager-ui.dockerfile`, конфигурация nginx `deployments/configs/reference-manager-ui/local/reference-manager-ui.conf` в образ не входит и монтируется при запуске (см. `deployments/docker-compose.yaml`). Папка `tests/` и этот файл в образ не попадают.

## Как это работает

- **Один адрес.** Браузер ходит только на свой origin: nginx интерфейса отдаёт `/admin/` и проксирует `/v1/` в сервис, междоменных запросов к API нет (NFR-RM-35). На общем стенде то же делает маршрутизация входящих запросов. Keycloak - единственный внешний адрес, он разрешён в `connect-src` политики.
- **Вход.** Без токена страница перенаправляет в Keycloak и после возврата открывает прежний экран. Токен обновляется за 30 секунд до истечения, ответ 401 ведёт к повторному входу. "Выйти" завершает сессию и в Keycloak.
- **Права на сервере.** Панель скрывает действия по ролям (таблица в [110, раздел 4](../../documents/110.ui-ux.md)), но решает сервис: 403 показывается баннером. Учётная запись без ролей сервиса видит экран отказа S-04.
- **Справочники.** Таблица, форма, удаление (мягкое, окончательное с `force=true` для удалённой записи), выгрузка `POST /v1/{коллекция}/export` (файл отдаёт сервис), история из `GET .../revisions` с состоянием на ревизию.
- **Сотрудник (S-05).** Состояние занятости и учётной записи, действующие подразделение, должность и оклад, вкладки назначений, окладов и отсутствий с закрытием датой, "Уволить" с датой и подтверждением, "Повторить операцию с учётной записью" при PENDING. При ответе 503 (Keycloak недоступен) карточка открывается с PENDING.
- **Ссылочные поля.** Вводится идентификатор записи целевого справочника, список подсказок и подпись с наименованием берутся из `List` целевого справочника.
