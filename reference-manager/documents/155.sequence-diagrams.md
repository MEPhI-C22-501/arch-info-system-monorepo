# 155 - Sequence-диаграммы

> Формат - см. [состав документов](documents-composition.md), документ 155.
> Источник - [Use Cases](060.use-cases.md), [контракты API](130.api-contracts.md), [логическая схема](146.logic-scheme.md).

Тайм-ауты: запрос ограничен таймаутом middleware (сейчас константа, K-07; для выгрузки требуется отдельный предел до 60 с по NFR-RM-43); запрос к хранилищу ограничен контекстом запроса; экспорт телеметрии не блокирует ответ.

## SD-01 Создание записи с проверкой полей

Use Case UC-03, UC-14; истории US-AD-01, US-AD-02.

```mermaid
sequenceDiagram
    participant A as Администратор
    participant H as Маршрутизация
    participant S as Сервис записей
    participant R as Хранилище
    A->>H: POST /v1/currencies/ {code, number, name, decimals}
    H->>H: разбор запроса, спан
    H->>S: Create(currencies, поля, актор)
    S->>S: проверка полей по схеме справочника
    alt поля неверны
        S-->>H: ошибка проверки полей
        H-->>A: 400 message и details по полям
    else поля верны
        S->>R: BEGIN
        S->>S: проверка ссылок и правил справочника
        S->>R: вставить запись, получить id
        alt код занят
            R-->>S: нарушение уникальности
            S->>R: ROLLBACK
            H-->>A: 409 currency already exists
        else сохранено
            S->>R: вставить ревизию 1 (JSON Patch от пустого документа)
            S->>R: COMMIT
            H-->>A: 201 запись с id, is_deleted, revision
        end
    end
```

## SD-02 Удаление и удаление с force

Use Case UC-05; история US-AD-04.

```mermaid
sequenceDiagram
    participant A as Администратор
    participant H as Маршрутизация
    participant S as Сервис записей
    participant R as Хранилище
    A->>H: DELETE /v1/currencies/{id}
    H->>S: Delete(currencies, id, актор)
    S->>R: BEGIN
    S->>R: прочитать запись из представления
    alt записи нет или она уже удалена
        S->>R: ROLLBACK
        H-->>A: 404 currency not found
    else запись действует
        S->>R: обновить is_deleted = true
        S->>R: вставить ревизию revision + 1 (replace /is_deleted)
        alt номер ревизии занят
            S->>R: ROLLBACK
            H-->>A: 409 modified concurrently
        else ревизия вставлена
            S->>R: COMMIT
            H-->>A: 200 запись с is_deleted = true и deleted_at
        end
    end
    A->>H: DELETE /v1/currencies/{id}?force=true
    H->>S: Purge(currencies, id, актор)
    S->>R: удалить строку записи, ревизии уходят каскадом
    alt строки нет
        H-->>A: 404 currency not found
    else удалена
        H-->>A: 204
    end
```

## SD-03 Список с фильтром и выгрузка

Use Case UC-08, UC-09; истории US-RD-01..04.

```mermaid
sequenceDiagram
    participant C as Подсистема или читатель
    participant H as Маршрутизация
    participant S as Сервис записей
    participant F as Разбор filter
    participant X as Формирователь .xlsx
    participant R as Хранилище
    C->>H: GET /v1/currencies/?filter=name : "e"&order_by=name&pageSize=50
    H->>S: List(currencies, параметры)
    S->>F: разобрать filter и order_by по полям справочника, проверить pageToken
    alt неизвестное поле или чужой pageToken
        H-->>C: 400 invalid filter
    else выражение верно
        S->>R: выборка страницы плюс одна запись
        R-->>S: записи
        H-->>C: 200 currencies[] и nextPageToken
    end
    C->>H: POST /v1/currencies/export
    H->>S: Export(currencies)
    S->>R: все неудалённые записи в порядке создания
    R-->>S: записи
    S->>X: файл: заголовки, строка на запись, коды как текст, даты как даты
    X-->>S: файл в памяти
    H-->>C: 200 Content-Disposition attachment
```

Файл формируется в памяти целиком: справочники первой версии невелики, предела объёма нет (FR-RM-43 отозвано).

## SD-04 Запрос с токеном Keycloak

Use Case UC-10; история US-CS-02.

```mermaid
sequenceDiagram
    participant C as Сервис-потребитель
    participant KC as Keycloak
    participant M as Проверка токена
    participant J as Кэш ключей
    participant S as Сервис записей
    C->>KC: client credentials
    KC-->>C: access token (роль reference-reader)
    C->>M: GET /v1/currencies/5 Authorization: Bearer
    M->>J: ключ по kid
    alt ключ в кэше
        J-->>M: ключ
    else нет ключа
        J->>KC: JWKS
        KC-->>J: ключи
        J-->>M: ключ
    end
    M->>M: подпись, издатель, получатель, срок
    alt токен недействителен
        M-->>C: 401 UNAUTHENTICATED
    else действителен
        M->>S: запрос с актором и ролями
        S->>S: роль имеет уровень операции на группу справочника? (матрица 070)
        alt нет
            S-->>C: 403 PERMISSION_DENIED
        else да
            S-->>C: 200 запись
        end
    end
```

Ошибка загрузки ключей при пустом кэше даёт UNAVAILABLE на защищённых путях; ключи обновляются не чаще раза в минуту. Источник ключей может быть заменён конфигурацией (вопрос 7).

## SD-05 Развёртывание: задание изменений схемы и готовность

Use Case UC-12, UC-02; требования NFR-RM-21, FR-RM-31.

```mermaid
sequenceDiagram
    participant CI as CI/CD
    participant K as Kubernetes
    participant J as Задание изменений схемы
    participant DB as Хранилище
    participant P as Экземпляр reference-manager
    CI->>K: новый образ, манифесты
    K->>J: запустить задание
    J->>DB: применить изменения схемы, версия = N
    alt не применилось
        J-->>K: ошибка
        K-->>CI: развёртывание остановлено
    else применено
        J-->>K: успех
        K->>P: запустить Deployment
        K->>P: GET /v1/health/readyz
        P->>DB: доступность и версия схемы
        alt недоступно или версия < N
            P-->>K: 503 с перечнем проверок
            K->>K: трафик не подаётся, повтор
        else готов
            P-->>K: 200
            K->>K: трафик на экземпляр, старые экземпляры останавливаются
        end
    end
```

## SD-06 Реализация справочника

Use Case UC-02; история US-AD-06. Взаимодействие людей и репозитория, не сетевых компонентов.

```mermaid
sequenceDiagram
    participant T as Команда-потребитель
    participant E as Инженер справочников
    participant GH as Репозиторий и CI
    participant K as Развёртывание
    participant A as Администратор
    E->>T: уточнение полей и начальных данных справочника из состава первой версии
    T-->>E: поля, ограничения, данные
    E->>GH: изменение: схема записи в спецификации, хранилище, методы, тесты
    GH->>GH: линтер, тесты, сравнение спецификаций
    E->>GH: ревью CODEOWNERS, слияние
    GH->>K: новая версия, SD-05
    A->>K: наполнение записями (Create)

```

## SD-07 Чтение истории записи

Use Case UC-15; истории US-AD-08, US-RD-05, US-CS-06.

sequenceDiagram

    participant H as Маршрутизация

    participant R as Хранилище

## SD-08 Приём сотрудника: профиль и учётная запись

Use Case UC-16, UC-21; истории US-HR-01, US-HR-06. Контракт Keycloak - [130, раздел 8](130.api-contracts.md).

```mermaid
sequenceDiagram
    participant HR as HR-администратор
    participant H as Маршрутизация
    participant S as Сервис записей
    participant A as Координатор учётных записей
    participant R as Хранилище
    participant K as Keycloak Admin REST API
    HR->>H: POST /v1/employees/ {табельный номер, ФИО, логин, почта, дата приёма}
    H->>S: Create(employees, поля, актор)
    S->>S: роль hr-admin, проверка полей
    alt поля неверны или логин, почта заняты
        H-->>HR: 400 INVALID_ARGUMENT или 409 ALREADY_EXISTS
    else верны
        S->>R: BEGIN, вставить профиль: account_state PENDING, ревизия 1, COMMIT
        S->>A: выполнить операцию
        A->>K: найти учётную запись: по account_user_id, без него по логину
        alt нет ответа за тайм-аут или ошибка
            A-->>S: результат неизвестен
            H-->>HR: 503 UNAVAILABLE ACCOUNT_PENDING, имя записи
        else найдена учётная запись с другой почтой
            H-->>HR: 400 FAILED_PRECONDITION ACCOUNT_CONFLICT
        else не найдена, либо найдена с той же почтой и присвоена
            A->>K: создать отключённую учётную запись: логин, ФИО, почта, временный пароль, смена пароля, роли по умолчанию
            K-->>A: 201, идентификатор учётной записи
            A->>K: включить учётную запись, передать ФИО и почту
            K-->>A: 204
            A->>R: BEGIN, account_state ENABLED, account_user_id, ревизия 2, COMMIT
            H-->>HR: 201 запись сотрудника, account_state ENABLED
        end
    end
```

Тайм-аут каждого вызова Keycloak - 5 секунд по умолчанию (NFR-RM-47). После любого сбоя на шагах с Keycloak профиль остаётся в PENDING. Сервис не повторяет вызов сам: повтор выполняет HR-администратор (SD-10). Если учётная запись создана, но не включена, она остаётся отключённой до повтора.

## SD-09 Увольнение сотрудника

Use Case UC-17, UC-21; история US-HR-05.

```mermaid
sequenceDiagram
    participant HR as HR-администратор
    participant H as Маршрутизация
    participant S as Сервис записей
    participant A as Координатор учётных записей
    participant R as Хранилище
    participant K as Keycloak Admin REST API
    HR->>H: POST /v1/employees/1024:dismiss {dismissal_date}
    H->>S: Dismiss(1024, дата, актор)
    alt уже уволен или дата раньше приёма
        H-->>HR: 400 FAILED_PRECONDITION или INVALID_ARGUMENT
    else допустимо
        S->>R: BEGIN, employment_state DISMISSED и дата, end_date в действующих назначении и окладе, account_state PENDING с операцией DISABLE, ревизии, COMMIT
        S->>A: выполнить операцию
        A->>K: отключить учётную запись по account_user_id
        alt нет ответа за тайм-аут или ошибка
            H-->>HR: 503 UNAVAILABLE ACCOUNT_PENDING, увольнение сохранено
        else 204
            A->>R: BEGIN, account_state DISABLED, очистить операцию, ревизия UPDATED, COMMIT
            H-->>HR: 200 запись, employment_state DISMISSED, account_state DISABLED
        end
    end
```

Уже выданный токен уволенного сотрудника действует до истечения срока: блокировка закрывает новый вход и обновление токена.

## SD-10 Повтор операции с учётной записью

Use Case UC-18; история US-HR-06.

```mermaid
sequenceDiagram
    participant HR as HR-администратор
    participant S as Сервис записей
    participant A as Координатор учётных записей
    participant R as Хранилище
    participant K as Keycloak Admin REST API
    HR->>S: POST /v1/employees/1/syncAccount
    S->>R: прочитать запись: employment_state, account_state, account_user_id
    S->>A: привести учётную запись к записи
    alt account_user_id сохранён
        A->>K: прочитать учётную запись по идентификатору
    else связи нет
        A->>K: найти учётную запись по логину
        alt найдена с той же почтой
            A->>A: присвоить найденную
        else найдена с другой почтой
            S-->>HR: 400 FAILED_PRECONDITION, account_state PENDING
        else не найдена, сотрудник работает
            A->>K: создать отключённую учётную запись
        end
    end
    A->>K: включить (работает) или отключить (уволен), передать ФИО и почту
    alt нет ответа за тайм-аут или ошибка
        A->>R: account_state PENDING с ревизией, если состояние было другим
        S-->>HR: 503 UNAVAILABLE, имя записи
    else подтверждено
        A->>R: account_state ENABLED или DISABLED, account_user_id, ревизия, если что-то изменилось
        S-->>HR: 200 запись
    end
```

Повтор безопасен: создание всегда начинается с поиска существующей учётной записи, включение и отключение дают тот же результат при повторном вызове. Метод вызывается для любого сотрудника: без расхождений между записью и учётной записью он ничего не меняет и отвечает текущей записью. Отдельный идентификатор операции не хранится, нужная операция выводится из состояний записи.

## SD-11 Извлечение справочников заданием ETL

Use Case UC-08; история US-CS-10; требование INT-RM-12.

```mermaid
sequenceDiagram
    participant E as Задание ETL команды Reports
    participant KC as Keycloak
    participant H as Reference Manager
    participant W as Аналитическое хранилище Reports
    E->>KC: client credentials
    KC-->>E: токен с ролью reference-reader
    loop по каждому нужному справочнику
        loop пока в ответе есть nextPageToken
            E->>H: GET /v1/employees?allowDeleted=true&pageSize=100&pageToken=...
            alt сервис недоступен или тайм-аут
                H-->>E: ошибка
                E->>E: запуск завершён ошибкой, загрузка не выполняется
            else страница получена
                H-->>E: записи, nextPageToken
            end
        end
    end
    E->>W: загрузить преобразованные данные
```

Инициатор и владелец задания - команда Reports. Сервис в аналитическое хранилище ничего не отправляет и о нём не знает. Тайм-аут и расписание задаёт потребитель; целевой интервал запуска - не реже раза в час.
