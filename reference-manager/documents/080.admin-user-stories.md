# 080 - User Stories: администратор справочников

> Формат - см. [состав документов](documents-composition.md), документ 080.

Актор [H-01](030.actors.md), роль [R-02](070.role-matrix.md). Формат: "Как <актор>, я хочу <функция>, чтобы <ценность>". Given / When / Then - "Дано / Когда / Тогда". Сценарии - спецификации приёмки, не результаты выполненных тестов. Приоритеты в [090](090.features-epics.md), трассировка в [095](095.requirements-check.md).

## US-AD-01 - Создать запись справочника

Как администратор справочников, я хочу создать запись с идентификатором, наименованием и полями справочника, чтобы потребители получили новое значение по стабильному имени.

**Связи:** UC-03 ([060](060.use-cases.md)); FR-RM-05, FR-RM-14, BR-RM-03.

- **AC-1. Given** в `currencies` нет записи `XYZ`; **When** вызываю `Create` с идентификатором `XYZ`, `display_name`, `numeric_code`, `minor_units`; **Then** получаю запись `currencies/XYZ` в состоянии ACTIVE с `etag`.
- **AC-2. Given** запись `currencies/XYZ` удалена; **When** создаю запись с тем же идентификатором; **Then** получаю ALREADY_EXISTS с подсказкой восстановить существующую; новой записи нет.
- **AC-3. Given** запись создана; **When** читаю её историю; **Then** вижу одну ревизию CREATED с моим идентификатором, временем и всеми полями в изменениях.

## US-AD-02 - Получить понятную ошибку по полям

Как администратор, я хочу при отклонении записи видеть, какие поля неверны и почему, чтобы исправить их с первого раза.

**Связи:** UC-14; FR-RM-35, NFR-RM-11.

- **AC-1. Given** для `minor_units` допустимы значения 0..6; **When** отправляю 9; **Then** получаю INVALID_ARGUMENT с `BadRequest`, где есть поле `minor_units` и причина, и `RequestInfo` с идентификатором запроса.
- **AC-2. Given** поле `currency` справочника `countries` ссылается на `currencies`; **When** указываю несуществующее имя валюты; **Then** получаю INVALID_ARGUMENT по полю `currency`, запись не сохранена.
- **AC-3. Given** отправлено несколько неверных полей; **When** запрос отклонён; **Then** перечислены все неверные поля, а не только первое.

## US-AD-03 - Исправить наименование или поля записи

Как администратор, я хочу частично изменить запись, чтобы поправить ошибку без пересоздания и без смены имени.

**Связи:** UC-04; FR-RM-07, FR-RM-14, FR-RM-24.

- **AC-1. Given** запись ACTIVE; **When** вызываю `Update` с `update_mask: display_name`; **Then** получаю запись с новым `display_name`, прежними остальными полями и новым `etag`; в истории появилась ревизия UPDATED с одним изменением.
- **AC-2. Given** запись существует; **When** включаю в `update_mask` поле `name` или `state`; **Then** получаю INVALID_ARGUMENT с указанием поля.
- **AC-3. Given** запись DELETED; **When** вызываю `Update`; **Then** получаю FAILED_PRECONDITION, запись не изменена.
- **AC-4 (срез 2). Given** запись с текущим `etag`; **When** вызываю `Update` с устаревшим `etag`; **Then** получаю ABORTED.

## US-AD-04 - Удалить запись, которая больше не нужна

Как администратор, я хочу удалить запись так, чтобы она исчезла из выбора, но ссылки подсистем на неё продолжали работать.

**Связи:** UC-05; FR-RM-10, FR-RM-11, BR-RM-03, BR-RM-04, BR-RM-05.

- **AC-1. Given** запись ACTIVE; **When** вызываю `Delete`; **Then** получаю запись в состоянии DELETED с заполненным `delete_time` и новым `etag`; в истории ревизия DELETED.
- **AC-2. Given** запись удалена; **When** читаю её `Get`; **Then** запись возвращается со `state: DELETED`; в `List` без `show_deleted` её нет, с `show_deleted` есть.
- **AC-3. Given** запись удалена; **When** вызываю `Delete` повторно; **Then** получаю FAILED_PRECONDITION.

## US-AD-05 - Восстановить удалённую запись

Как администратор, я хочу восстановить удалённую запись, чтобы исправить ошибочное удаление без нового идентификатора.

**Связи:** UC-06; FR-RM-12, FR-RM-14.

- **AC-1. Given** запись DELETED; **When** вызываю `Undelete`; **Then** получаю запись в состоянии ACTIVE с пустым `delete_time` и новым `etag`; в истории ревизия UNDELETED.
- **AC-2. Given** запись ACTIVE; **When** вызываю `Undelete`; **Then** получаю FAILED_PRECONDITION.

## US-AD-06 - Наполнить новый справочник

Как администратор, я хочу внести начальные данные нового справочника, чтобы потребители могли начать интеграцию.

**Связи:** UC-02, UC-03, UC-13; FR-RM-33.

- **AC-1. Given** справочник `units` развёрнут и `/ready` отвечает 200; **When** вношу значения через интерфейс администрирования или `Create`; **Then** все значения сохранены со `state: ACTIVE`.
- **AC-2. Given** в начальных данных есть дубль идентификатора; **When** вношу его; **Then** второй экземпляр отклонён ALREADY_EXISTS, первый сохранён.

## US-AD-07 - Вести записи через интерфейс администрирования (срез 3)

Как администратор, я хочу работать с записями в веб-интерфейсе с формой по полям справочника, чтобы не составлять запросы вручную.

**Связи:** UC-13; FR-RM-28, FR-RM-29, NFR-RM-35.

- **AC-1. Given** вошёл через Keycloak с ролью `reference-admin`; **When** открываю `/admin/`; **Then** вижу список справочников из спецификации и перехожу к таблице записей.
- **AC-2. Given** открыта форма записи `countries`; **When** заполняю поля; **Then** поля построены по схеме записи, включая `currency` с выбором из справочника валют, а ошибки INVALID_ARGUMENT показаны у соответствующих полей.
- **AC-3. Given** выбрана запись; **When** нажимаю "Удалить" или "Восстановить"; **Then** действие выполняется после подтверждения, состояние в форме обновлено.

## US-AD-08 - Посмотреть, кто и когда изменил запись

Как администратор, я хочу видеть историю записи с ревизиями, авторами и изменениями, чтобы разбирать спорные правки без обращения к разработчикам.

**Связи:** UC-15; FR-RM-44, FR-RM-46, FR-RM-47, BR-RM-12.

- **AC-1. Given** запись создана, дважды изменена и удалена; **When** читаю её `revisions`; **Then** получаю четыре ревизии от новой к старой с действиями DELETED, UPDATED, UPDATED, CREATED, авторами, временем и списком изменений каждой.
- **AC-2. Given** ревизия UPDATED; **When** смотрю её изменения; **Then** вижу только изменённые поля с прежним и новым значением.
- **AC-3. Given** запись с тремя ревизиями; **When** запрашиваю запись в состоянии на ревизию 2; **Then** получаю запись такой, какой она была после второй операции.
- **AC-4. Given** любая роль; **When** пытаюсь изменить или удалить ревизию; **Then** такой операции нет в API, а учётная запись сервиса в хранилище её отклоняет.
