# 010 - Глоссарий (Ubiquitous Language)

> Формат - см. [состав документов](documents-composition.md), документ 010.
> Источник - [системные требования, раздел 2](system-requirements.md#2-термины), сверено с [видением](vision.md).

Общепрограммные термины (пользователь, роль, CRUD) намеренно не включены - только предметная область модуля: кадровые мастер-данные и справочники. Термины кадровой области добавлены 2026-10-02.

## 1. Кадровая область

| Термин | Определение | Контекст / модуль ERP | Синонимы |
| --- | --- | --- | --- |
| Кадровые мастер-данные | Сведения о сотрудниках, организационной структуре и должностях, общие для всех подсистем. Единственный владелец - Reference Manager. | Reference Manager, все потребители | HR-данные |
| HR-профиль | Запись справочника сотрудников: ФИО, табельный номер, логин, адрес почты, состояние занятости, связь с учётной записью. Не содержит пароля и ролей доступа. | Reference Manager, Keycloak | Профиль сотрудника, карточка сотрудника |
| Сотрудник | Человек, работающий в организации, описанный HR-профилем. Для Task Tracker и QA System - исполнитель, для Planning System - ресурс. | Reference Manager, Task Tracker, Planning System, QA System, Reports | Работник, ресурс, исполнитель |
| Табельный номер | Идентификатор записи сотрудника. Задаётся при приёме и не меняется. | Reference Manager, все потребители | Внешний идентификатор сотрудника |
| Учётная запись | Запись пользователя в Keycloak: логин, пароль, роли доступа. Создаётся и блокируется по запросу сервиса, в сервисе хранится только её идентификатор. | Keycloak, Reference Manager | Аккаунт |
| Организационная структура | Иерархия подразделений организации. | Reference Manager, Task Tracker, Planning System, QA System | Оргструктура |
| Подразделение | Узел организационной структуры: отдел или команда. Может иметь вышестоящее подразделение. | Reference Manager, Task Tracker | Отдел, команда, org unit |
| Должность | Наименование должности из справочника должностей. Сотрудник занимает должность по назначению. | Reference Manager, Planning System | Позиция |
| Датированная запись | Запись, у которой есть дата начала и дата окончания действия. Новое значение оформляется новой записью, прежняя сохраняется. | Reference Manager | Запись с периодом действия |
| Период действия | Даты, с которой и по которую действует датированная запись. Пустая дата окончания означает "действует сейчас". | Reference Manager, Planning System | Действует с даты / по дату |
| Назначение | Датированная запись о том, что сотрудник занимает должность в подразделении. Периоды назначений одного сотрудника не пересекаются. | Reference Manager, Planning System | Назначение на должность |
| Оклад | Датированная запись о размере оклада сотрудника в валюте. Данные ограниченного доступа. | Reference Manager, Planning System | Ставка |
| Отсутствие | Датированная запись о периоде, когда сотрудник не работает: отпуск, болезнь, другое. Данные ограниченного доступа. | Reference Manager, Planning System | Неявка |
| Состояние занятости | EMPLOYED (работает) или DISMISSED (уволен). Не связано с удалением записи. | Reference Manager, все потребители | employment_state |
| Состояние учётной записи | PENDING (операция с учётной записью не завершена), ENABLED (создана и включена), DISABLED (заблокирована). | Reference Manager, Keycloak | account_state |
| Приём | Создание HR-профиля, после которого сервис создаёт учётную запись в Keycloak с временным паролем. | Reference Manager, Keycloak | Найм |
| Увольнение | Перевод сотрудника в состояние DISMISSED с блокировкой учётной записи. Запись сотрудника остаётся. | Reference Manager, Keycloak | Dismiss |
| Идентификатор операции | Значение, которое сервис сохраняет до обращения к Keycloak, чтобы повтор операции не создал вторую учётную запись. | Reference Manager | Ключ повтора |
| HR-администратор | Сотрудник кадровой службы с ролью hr-admin. Принимает и увольняет сотрудников, ведёт кадровые справочники. | Reference Manager | reference-hr-admin |
| Читатель кадровых данных | Пользователь или сервис с ролью hr-reader. Читает все справочники, включая оклады и отсутствия. | Planning System | reference-hr-reader |

## 2. Справочники и записи

| Термин | Определение | Контекст / модуль ERP | Синонимы |
| --- | --- | --- | --- |
| НСИ | Нормативно-справочная информация: данные, которые классифицируют или описывают бизнес-сущности, но сами бизнес-сущностями не являются. | Reference Manager | Справочные данные, классификаторы, master data |
| Справочник | Именованный набор однотипных справочных записей, например валюты или сотрудники. В API - коллекция ресурсов со своим путём, например `/v1/countries`. | Reference Manager | Каталог, коллекция |
| Запись справочника | Одна справочная единица внутри справочника, например страна RU. В API - ресурс с именем вида `countries/RU`. | Reference Manager | Ресурс, элемент справочника |
| Имя записи | Имя ресурса: путь коллекции и идентификатор записи, например `currencies/EUR`. Стабильно, задаётся один раз. | Reference Manager, все потребители | name |
| Идентификатор записи | Последний сегмент имени, например `EUR`. Уникален в пределах справочника, включая удалённые записи, не меняется. Задаётся при создании: для стандартных классификаторов это код стандарта, для сотрудника табельный номер. Идентификатор датированной записи назначает сервис. | Reference Manager | id |
| Общие поля записи | Поля, одинаковые во всех справочниках: имя, состояние, признак версии, время удаления. Наименование есть везде, кроме датированных записей. | Reference Manager | name, display_name, state, etag, delete_time |
| Поля справочника | Типизированные поля, которые есть только у данного справочника, например числовой код валюты или число знаков дробной части. | Reference Manager | Атрибуты |
| Наименование | Человекочитаемое название записи для отображения. | Reference Manager, интерфейсы подсистем | display_name |
| Состояние записи | ACTIVE (в обороте) или DELETED (удалена). Только для чтения. | Reference Manager | state |
| Признак версии | Непрозрачное значение, которое меняется при каждой операции записи; передаётся в операции записи, чтобы не перезаписать чужое изменение. | Reference Manager | etag |
| Удаление | Перевод записи в состояние DELETED: запись остаётся, получает время удаления, исчезает из списков по умолчанию и остаётся доступной по имени. Физического удаления нет. | Reference Manager | Мягкое удаление, soft delete |
| Восстановление | Перевод удалённой записи обратно в ACTIVE. | Reference Manager | Undelete |
| Ревизия | Элемент истории изменений записи: действие, актор, время, изменённые поля с прежними и новыми значениями. Неизменяема. | Reference Manager | Revision, запись истории |
| История изменений | Ревизии записей справочника в обратном хронологическом порядке. Ведётся для каждого справочника отдельно. | Reference Manager | Журнал изменений, revisions |
| Действие ревизии | Что произошло с записью: создание, изменение, удаление, восстановление. | Reference Manager | action |
| Стандартные методы | Пять операций каждого справочника: список, чтение, создание, изменение, удаление. | Reference Manager, потребители | List, Get, Create, Update, Delete |
| Список | Метод чтения записей справочника постранично с фильтром и сортировкой. | Reference Manager, потребители | List |
| Фильтр | Выражение отбора записей списка по общим полям и полям справочника. | Reference Manager, потребители | filter |
| Показ удалённых | Признак списка, включающий записи в состоянии DELETED. | Reference Manager | show_deleted |
| Маска изменения | Перечень полей, которые меняет операция изменения; остальные поля не трогаются. | Reference Manager | update_mask |
| Выгрузка | Файл `.xlsx` с записями, отобранными теми же параметрами, что и список. | Reference Manager, Reports, администраторы | Экспорт, export |
| Схема записи | Описание полей записи справочника в спецификации API: общие поля плюс поля справочника. По одной схеме на справочник; по ней строятся формы интерфейса администрирования. | Reference Manager, потребители | Схема OpenAPI |
| Ссылка между справочниками | Поле справочника, значение которого обязано быть именем записи другого справочника. | Reference Manager | Внешняя ссылка |
| Ошибка по полям | Отказ операции с перечнем полей и причин, по которым запись отклонена. | Reference Manager, интерфейсы подсистем | Ошибка проверки |
| Группа справочников | Набор справочников с одинаковыми правами ролей: общие классификаторы, кадровые справочники, оклады и отсутствия. | Reference Manager, Keycloak | Группа доступа |
| Уровни доступа | Операции над записями: create, read, update, execute, delete. Набор уровней роли задаётся для группы справочников. | Reference Manager, Keycloak | CRUXD |
| Администратор справочников | Участник команды справочников с ролью admin. Ведёт записи общих классификаторов. | Reference Manager | reference-admin |
| Читатель | Любой аутентифицированный пользователь или сервис ERP с ролью reader. Читает классификаторы и кадровые справочники, их историю, выгружает. Оклады и отсутствия ему недоступны. | Все подсистемы ERP | reference-reader |
| Сервис-потребитель | Подсистема ERP, которая читает справочники по API под своей сервисной учётной записью и кэширует значения у себя. | Core, Task Tracker, Planning System, QA System, Reports | Потребитель, клиент API |
| Команда справочников | Команда, владеющая сервисом: определяет состав справочников, реализует их и ведёт записи классификаторов. | Reference Manager | Команда Reference Manager |
| Состав справочников | Перечень справочников первой версии: кадровые по постановке проекта, классификаторы по подтверждённой потребности команд. Новый справочник - новая версия сервиса. | Reference Manager, все потребители | Перечень справочников первой версии |
| Стандартный классификатор | Справочник, значения которого заданы внешним стандартом: ISO 4217 (валюты), ISO 3166-1 (страны). | Reference Manager, Planning System | Международный справочник |
| Проверка готовности | Ответ сервиса о том, что хранилище доступно и его схема соответствует версии сервиса. | Infra | Readiness |
