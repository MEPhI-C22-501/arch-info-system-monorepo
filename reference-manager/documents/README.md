# Reference Manager - комплект документов

Комплект по [составу документов курсового проекта](documents-composition.md), блоки A-I. Основание - [системные требования](system-requirements.md), [видение](vision.md), [конституция проекта](../.specify/memory/constitution.md) и код в `main`. Описывает проектируемую систему: в репозитории есть каркас сервиса, методы справочников, история, защита API, кадровые справочники и интерфейс ещё не реализованы.

**Редакция:** 3.0, 2026-10-02. **Статус:** к ревью команды.

Изменения 2026-10-02 по замечаниям руководителя проекта от 2026-10-01 и его ответам на вопросы команды:

- модуль приведён к постановке: сотрудники, оргструктура и должности с датированными назначениями, окладами и отсутствиями, владение HR-профилями
- учётные записи сотрудников создаются и блокируются в Keycloak по интеграции
- единый вход через Keycloak входит в первую версию
- добавлены документ 162 и отчёт проверки безопасности
- потребитель QA System, поток в аналитическое хранилище и обмен файлами описаны явно
- отказ от событий подтверждён документами потребителей, документы 135 и 140 заполнены
- справочники статусов и приоритетов задач и серьёзности дефектов сняты: их ведут Task Tracker и QA System
- интерфейс администрирования вынесен в отдельный компонент
- пакетные операции и загрузка из файла отнесены в конец работ, формат выгрузки `.xlsx` и ведение истории подтверждены

Редакция 2.0, 2026-09-27: API по принципам Google AIP, коллекция и методы на каждый справочник, история как ревизии с различиями отдельно на справочник.

## Правила чтения

- Идентификаторы требований FR-RM, INT-RM, BR-RM, NFR-RM взяты из системных требований; отозванные перечислены в их разделе 1.3 и не переиспользуются. Идентификаторы комплекта: акторы H и S, роли R, группы справочников G, UC, US, эпики E, ADR, SD, интеграции I, расхождения с кодом K.
- Срез 1 - первая версия, включая кадровые справочники, учётные записи Keycloak и проверку токена. Пометка "срез 2" относится к `etag` и сетевой политике, "срез 3" - к интерфейсу (раздел 13 требований). Пометка "вне основного объёма" означает работу в конце, если останется время.
- Документы описывают контракт и модель, а не реализацию: детали хранения приведены только там, где их требует состав документа (120), детали компонентов - в 150.
- Расхождения между требованиями и кодом собраны в [020, раздел 6](020.system-context.md); открытые вопросы требований и ответственные - в [160, раздел 3](160.integration-plan.md).
- Сервис не публикует события. Документы 135 и 140 описывают это решение и то, чем оно подтверждено.
