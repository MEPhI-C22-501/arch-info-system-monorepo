# 130 - API Contracts

> Формат - см. [состав документов](documents-composition.md), документ 130.
> Источник - [системные требования, разделы 4, 5.1, 10.2](system-requirements.md), [сущности](050.entities.md), [RBAC](070.role-matrix.md), спецификация `api/openapi/v1/openapi.yaml`.

## 1. Спецификация

Источник истины - OpenAPI в `api/openapi/v1/openapi.yaml`. Сейчас спецификация содержит только служебные точки и имеет версию `0.0.0`. Коллекции справочников, включая кадровые, добавляются по этому документу до реализации среза 1 (K-10 в [020](020.system-context.md)). На каждый справочник - своя коллекция, свои пути и своя схема записи; общие параметры и ошибки вынесены в переиспользуемые компоненты.

Версионирование: мажорная версия в пути (`/v1`); в её пределах только совместимые изменения - новые коллекции и необязательные поля (INT-RM-03, NFR-RM-06). Версия спецификации в `info.version` по semver: minor при добавлении справочника или поля, patch при уточнении описаний.

## 2. Общие правила по Google AIP

| Правило | Значение |
| --- | --- |
| Ресурсы | Коллекция на справочник (`/v1/currencies`), имя записи `currencies/EUR` (AIP-122) |
| Стандартные методы | List, Get, Create, Update, Delete (AIP-131..135); кастомные Undelete (AIP-164) и ListRevisions (AIP-162) |
| Стандартные поля | `name`, `display_name`, `state`, `etag`, `delete_time` (AIP-148); `create_time` и `update_time` в записи не возвращаются, время и автор - в ревизиях (отклонение от AIP-148, решение 2026-09-27) |
| Список | `page_size` (1..200, по умолчанию 50), `page_token`, `filter` (AIP-160), `order_by`, `show_deleted`; ответ с `next_page_token` и `total_size` (AIP-132, AIP-158) |
| Создание | Идентификатор записи в параметре `{справочник}_id`, например `currency_id` (AIP-133). Для датированных записей параметр не передаётся, идентификатор назначает сервис |
| Состояния с побочным действием | Состояния занятости и учётной записи только для чтения; переходы выполняют кастомные методы `Dismiss` и `SyncAccount` (AIP-136, AIP-216) |
| Изменение | `PATCH` с `update_mask`; поля вне маски не трогаются (AIP-134) |
| Конкурентность | `etag` в записи; в `Update`, `Delete`, `Undelete` несовпадение - ABORTED (AIP-154); срез 2 |
| Мягкое удаление | `Delete` возвращает запись со `state: DELETED`; `Undelete` - `POST {name}:undelete` (AIP-164); `purge_time` нет: записи не очищаются |
| Ревизии | `GET {name}/revisions`, обратный хронологический порядок; ревизия несёт различия, а не снимок (отклонение от AIP-162) |
| Ошибки | `google.rpc.Status` с `code`, `message`, `status`, `details[]`: `ErrorInfo`, `BadRequest`, `RequestInfo` (AIP-193) |
| Формат | `application/json`, UTF-8, время RFC 3339 UTC; заголовки ответа `X-Request-Id`, `X-Trace-Id` |
| Выгрузка | `Accept: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` на `List` (решение 2026-09-17; альтернатива `:export` - вопрос 13) |

## 3. Методы справочника

На примере `currencies`; у всех справочников набор одинаков (NFR-RM-40).

| Метод | HTTP | Роль | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| List | `GET /v1/currencies` | reader | 200: `currencies[]`, `next_page_token`, `total_size`; при `Accept` `.xlsx` - файл | INVALID_ARGUMENT (фильтр, сортировка, `page_size`); FAILED_PRECONDITION (выгрузка сверх предела) |
| Get | `GET /v1/currencies/{currency}` | reader | 200: запись, включая DELETED; с `?revision=N` - состояние на ревизию | NOT_FOUND |
| Create | `POST /v1/currencies?currency_id=PLN` | admin | 201: запись | INVALID_ARGUMENT (поля, формат идентификатора); ALREADY_EXISTS |
| Update | `PATCH /v1/currencies/{currency}` с `update_mask` | admin | 200: запись | NOT_FOUND; INVALID_ARGUMENT (поле только для чтения, значения); FAILED_PRECONDITION (запись DELETED); ABORTED (срез 2) |
| Delete | `DELETE /v1/currencies/{currency}` | admin | 200: запись со `state: DELETED` | NOT_FOUND; FAILED_PRECONDITION (уже удалена); ABORTED (срез 2) |
| Undelete | `POST /v1/currencies/{currency}:undelete` | admin | 200: запись со `state: ACTIVE` | NOT_FOUND; FAILED_PRECONDITION (не удалена); ABORTED (срез 2) |
| ListRevisions | `GET /v1/currencies/{currency}/revisions` | reader | 200: `revisions[]`, `next_page_token`, `total_size` | NOT_FOUND |
| GetRevision | `GET /v1/currencies/{currency}/revisions/{revision}` | reader | 200: ревизия | NOT_FOUND |

Операций управления справочниками нет (FR-RM-38). В таблице указана наименьшая роль для классификаторов. Права по группам справочников - в [070](070.role-matrix.md).

### Кадровые справочники

Справочники `employees`, `org_units`, `positions`, `assignments`, `salaries`, `absences` имеют тот же набор методов, что и `currencies`. Отличия:

| Справочник | Отличие |
| --- | --- |
| `employees` | `Create` создаёт учётную запись в Keycloak и отвечает 201 только после её включения. Дополнительные методы `Dismiss` и `SyncAccount`. `Delete` при включённой учётной записи отклоняется |
| `org_units` | Ссылка `parent`, образующая цикл, отклоняется |
| `assignments`, `salaries`, `absences` | Параметр идентификатора в `Create` не передаётся: идентификатор назначает сервис. Поля `display_name` нет. Пересечение периодов в `assignments` и `salaries` отклоняется |
| `salaries`, `absences` | Чтение требует роли `reference-hr-reader` или `reference-hr-admin` |

| Метод | HTTP | Роль | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| Create сотрудника | `POST /v1/employees?employee_id=1024` | hr-admin | 201: запись с `account_state: ENABLED` | INVALID_ARGUMENT (поля, занятый логин или адрес почты); ALREADY_EXISTS (табельный номер); UNAVAILABLE `ACCOUNT_PENDING` (Keycloak не подтвердил, профиль сохранён в PENDING); FAILED_PRECONDITION `ACCOUNT_CONFLICT` (логин занят чужой учётной записью) |
| Dismiss | `POST /v1/employees/{employee}:dismiss` с телом `{"dismissal_date": "2026-10-31"}` | hr-admin | 200: запись с `employment_state: DISMISSED`, `account_state: DISABLED` | NOT_FOUND; INVALID_ARGUMENT (дата раньше приёма); FAILED_PRECONDITION `ALREADY_DISMISSED`; UNAVAILABLE `ACCOUNT_PENDING` (увольнение сохранено, блокировка не подтверждена) |
| SyncAccount | `POST /v1/employees/{employee}:syncAccount` | hr-admin | 200: запись с завершённой операцией | NOT_FOUND; UNAVAILABLE `ACCOUNT_PENDING`; FAILED_PRECONDITION `ACCOUNT_CONFLICT` |
| List сотрудников | `GET /v1/employees` | reader | 200: `employees[]`, `next_page_token`, `total_size` | INVALID_ARGUMENT |
| List подразделений | `GET /v1/org_units` | reader | 200: `org_units[]`, `next_page_token`, `total_size` | INVALID_ARGUMENT |
| List назначений | `GET /v1/assignments` | reader | 200: `assignments[]`, `next_page_token`, `total_size` | INVALID_ARGUMENT |
| List окладов, отсутствий | `GET /v1/salaries`, `GET /v1/absences` | hr-reader | 200: страница записей | INVALID_ARGUMENT; PERMISSION_DENIED для reader и admin |

Фильтры кадровых справочников:

| Задача потребителя | Запрос |
| --- | --- |
| Работающие сотрудники подразделения | `GET /v1/employees?filter=employment_state = EMPLOYED AND org_unit = "org_units/dev-backend"` |
| Сотрудник по идентификатору пользователя из токена | `GET /v1/employees?filter=account_user_id = "<sub>"` |
| Подчинённые подразделения | `GET /v1/org_units?filter=parent = "org_units/dev"` |
| Только команды | `GET /v1/org_units?filter=kind = TEAM` |
| Назначение сотрудника на дату | `GET /v1/assignments?filter=employee = "employees/1024" AND start_date <= "2026-06-15" AND (end_date >= "2026-06-15" OR NOT end_date:*)`. Выражение `NOT end_date:*` отбирает записи без даты окончания |
| Отсутствия сотрудника за период | `GET /v1/absences?filter=employee = "employees/1024" AND start_date <= "2026-12-31" AND end_date >= "2026-10-01"` |
| Полная выгрузка для кэша или ETL | `GET /v1/employees?show_deleted=true&page_size=200` постранично до пустого `next_page_token` |

### Параметры List

| Параметр | Значение |
| --- | --- |
| `filter` | Выражение AIP-160 по общим полям и полям справочника: `state = ACTIVE`, `display_name:"евро"`, `minor_units = 2 AND symbol != ""`, `name = "currencies/EUR"`; неизвестное поле - INVALID_ARGUMENT |
| `order_by` | Поля через запятую с необязательным ` desc`: `display_name`, `minor_units desc`; по умолчанию `name` |
| `page_size`, `page_token` | 1..200, по умолчанию 50; токен непрозрачен и привязан к параметрам отбора |
| `show_deleted` | По умолчанию `false`: только ACTIVE |

## 4. Схемы

`CurrencyRecord`: `name` (только чтение), `display_name`, `state` (`ACTIVE` | `DELETED`, только чтение), `etag` (только чтение), `delete_time` (только чтение), поля справочника `numeric_code`, `minor_units`, `symbol`. Создание принимает тело записи без полей только для чтения и параметр `currency_id`; изменение принимает тело записи и `update_mask`.

`EmployeeRecord`: общие поля; `family_name`, `given_name`, `middle_name`, `email`, `username`, `hire_date`; только для чтения `employment_state` (`EMPLOYED` | `DISMISSED`), `dismissal_date`, `org_unit`, `position`, `account_state` (`PENDING` | `ENABLED` | `DISABLED`), `account_user_id`. Пароля в схеме нет.

`OrgUnitRecord`: общие поля; `kind` (`DEPARTMENT` | `TEAM`), `parent`. `PositionRecord`: только общие поля.

`AssignmentRecord`: `name`, `state`, `etag`, `delete_time`; `employee`, `org_unit`, `position`, `start_date`, `end_date`. `SalaryRecord`: те же общие поля; `employee`, `amount`, `currency`, `start_date`, `end_date`. `AbsenceRecord`: те же общие поля; `employee`, `kind` (`VACATION` | `SICK_LEAVE` | `OTHER`), `start_date`, `end_date`. Даты периодов - календарные даты в формате `YYYY-MM-DD` без времени.

`Revision`: `name` (`currencies/EUR/revisions/3`), `action` (`CREATED` | `UPDATED` | `DELETED` | `UNDELETED`), `create_time`, `author`, `request_id`, `changes[]` из `{field, old_value, new_value}`.

`Status` (ошибка): `code`, `message`, `status`, `details[]`.

## 6. Соответствие ошибок

| Ситуация | HTTP | `status` | `ErrorInfo.reason` |
| --- | --- | --- | --- |
| Нет токена или недействителен | 401 | UNAUTHENTICATED | `TOKEN_INVALID` |
| Нет уровня доступа на группу справочника | 403 | PERMISSION_DENIED | `LEVEL_REQUIRED` |
| Запись или ревизия не найдена | 404 | NOT_FOUND | `RECORD_NOT_FOUND` |
| Идентификатор занят, включая удалённые | 409 | ALREADY_EXISTS | `ID_TAKEN` |
| Уже удалена, не удалена, изменение удалённой | 400 | FAILED_PRECONDITION | `ALREADY_DELETED`, `NOT_DELETED`, `RECORD_DELETED` |
| Выгрузка сверх предела | 400 | FAILED_PRECONDITION | `EXPORT_TOO_LARGE` |
| Сотрудник уже уволен; удаление сотрудника с включённой учётной записью | 400 | FAILED_PRECONDITION | `ALREADY_DISMISSED`, `ACCOUNT_ENABLED` |
| Логин занят учётной записью, не связанной с профилем | 400 | FAILED_PRECONDITION | `ACCOUNT_CONFLICT` |
| Пересечение периодов, дата окончания раньше начала, цикл в иерархии | 400 | INVALID_ARGUMENT | `FIELD_VIOLATION` |
| `etag` не совпал (срез 2) | 409 | ABORTED | `ETAG_MISMATCH` |
| Неверные поля, фильтр, сортировка, маска, идентификатор | 400 | INVALID_ARGUMENT | `FIELD_VIOLATION`, `FILTER_INVALID`, `MASK_INVALID` |
| Тело велико | 400 | INVALID_ARGUMENT | `PAYLOAD_TOO_LARGE` |
| Внутренняя ошибка | 500 | INTERNAL | `INTERNAL` |
| Хранилище недоступно, таймаут выгрузки | 503 | UNAVAILABLE | `STORAGE_UNAVAILABLE`, `EXPORT_TIMEOUT` |
| Keycloak не подтвердил операцию с учётной записью | 503 | UNAVAILABLE | `ACCOUNT_PENDING` |

## 7. Служебные точки

| Путь | Состояние в коде | Ответ |
| --- | --- | --- |
| `GET /v1/livez` | есть | 200 без тела |
| `GET /v1/readyz` | есть без проверки версии схемы (K-02, K-09) | 200 или 503 с перечнем неуспешных проверок |
| `GET /metrics` | нет | Prometheus по флагу конфигурации (FR-RM-32) |

Без токена. Наружу кластера служебные точки и `/metrics` не публикуются.

## 8. Исходящий контракт: Keycloak Admin REST API

Сервис вызывает Keycloak под служебным клиентом `reference-manager-provisioner`, который создаёт и настраивает Infra ([vision Infra, раздел 3](../../infra/vision.md)). Схемы запросов публикует Keycloak, здесь перечислены используемые операции.

| Назначение | Запрос к Keycloak | Когда | Ответ и обработка |
| --- | --- | --- | --- |
| Служебный токен | `POST /realms/{realm}/protocol/openid-connect/token`, `grant_type=client_credentials` | Перед операцией, токен кэшируется до истечения срока | Ошибка - UNAVAILABLE, состояние PENDING |
| Найти учётную запись | `GET /admin/realms/{realm}/users?username={username}&exact=true` | Перед созданием и при повторе | Найдена со ссылкой на этот профиль - создание пропускается; найдена чужая - FAILED_PRECONDITION `ACCOUNT_CONFLICT` |
| Создать учётную запись | `POST /admin/realms/{realm}/users`: логин, ФИО, адрес почты, `enabled: false`, атрибут со ссылкой на `employees/{id}`, временный пароль, обязательное действие смены пароля | `Create` сотрудника, `SyncAccount` | 201 - идентификатор из заголовка `Location`; 409 - повторный поиск |
| Включить, заблокировать, изменить | `PUT /admin/realms/{realm}/users/{id}`: `enabled: true` или `false`, ФИО, адрес почты | Завершение создания; `Dismiss`; `Update` ФИО или почты | 204 - операция подтверждена |

Тайм-аут каждого вызова - из конфигурации, по умолчанию 5 секунд (NFR-RM-47). Тайм-аут и любая ошибка, кроме 409 при создании, означают неизвестный результат: сервис не повторяет вызов сам, оставляет состояние PENDING и отвечает UNAVAILABLE. Секрет клиента, временный пароль и служебный токен в журналы и ошибки не попадают (NFR-RM-48).

## 9. Методы вне основного объёма

Выполняются в конце, если останется время (FR-RM-59, FR-RM-60). В спецификацию первой версии не входят.

| Метод | HTTP | Правило |
| --- | --- | --- |
| BatchCreate, BatchUpdate, BatchDelete | `POST /v1/{справочник}:batchCreate`, `:batchUpdate`, `:batchDelete` | Несколько записей одного справочника; запрос выполняется целиком или отклоняется целиком; на каждую запись своя ревизия |
| Import | `POST /v1/{справочник}:import` с файлом `.xlsx` | Формат файла совпадает с форматом выгрузки; ошибки возвращаются по строкам и полям |
