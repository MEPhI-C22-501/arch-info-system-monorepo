# 070 - RBAC (Role-Based Access Control)

> Формат - см. [состав документов](documents-composition.md), документ 070.
> Источник - [системные требования, разделы 3 и 4.5](system-requirements.md), [акторы](030.actors.md), [конституция, принцип VII](../.specify/memory/constitution.md).

Мультиарендности нет: права роли действуют на все записи справочников своей группы (BR-RM-13). Проверка токена и ролей входит в первую версию: работы без аутентификации нет (решение 2026-10-02).

## 1. Уровни доступа

| Уровень | Обозначение | Методы |
| --- | --- | --- |
| create | C | `Create` |
| read | R | `List`, `Get`, чтение истории и состояния на ревизию |
| update | U | `Update`, `Undelete`, для сотрудников также `Dismiss` и `SyncAccount` |
| execute | X | Выгрузка `.xlsx` |
| delete | D | `Delete` (мягкое) |

## 2. Группы справочников

| Группа | Справочники | Почему отдельная |
| --- | --- | --- |
| G-1 Общие классификаторы | `currencies`, `countries`, `project_roles`, `grades` | Ведёт команда справочников |
| G-2 Кадровые справочники | `employees`, `org_units`, `positions`, `assignments` | Ведёт кадровая служба; читают все подсистемы |
| G-3 Оклады и отсутствия | `salaries`, `absences` | Данные ограниченного доступа: читают только роли кадрового контура |

## 3. Роли

| ID | Роль | G-1 | G-2 | G-3 | Где определена | Кому выдаётся | Акторы |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R-01 | `reference-reader` | R X | R X | нет | Claim ролей токена Keycloak (FR-RM-22) | Всем пользователям ERP и сервисным учётным записям подсистем | H-02, S-01 |
| R-02 | `reference-admin` | C R U X D | R X | нет | Claim ролей токена Keycloak | Участникам команды справочников | H-01 |
| R-03 | Инженер справочников | репозиторий, не API | репозиторий | репозиторий | CODEOWNERS | Участникам команды справочников | H-04 |
| R-04 | `reference-hr-admin` | R X | C R U X D | C R U X D | Claim ролей токена Keycloak | Сотрудникам кадровой службы | H-05 |
| R-05 | `reference-hr-reader` | R X | R X | R X | Claim ролей токена Keycloak | Пользователям и сервисным учётным записям, которым нужны оклады и отсутствия (вопрос 22 требований) | S-01: Planning System |

R-00 "Внутренняя сеть без токена" отозвана 2026-10-02: единый вход обязателен с первой версии. Роли редактора нет (2026-09-15). Роли R-04 и R-05 введены 2026-10-02. Путь к ролям в токене не согласован (вопрос 6 требований).

## 4. Матрица прав на операции API

Для справочника группы G-1, например `countries`.

| Операция | Уровень | R-01 reader | R-05 hr-reader | R-02 admin | R-04 hr-admin |
| --- | --- | --- | --- | --- | --- |
| `POST /v1/countries` Create | C | нет | нет | да | нет |
| `GET /v1/countries` List, любые `filter`, `order_by`, `show_deleted` | R | да | да | да | да |
| `GET /v1/countries/{id}` Get, включая DELETED и состояние на ревизию | R | да | да | да | да |
| `GET /v1/countries/{id}/revisions` история | R | да | да | да | да |
| `GET /v1/countries` с `Accept` `.xlsx` выгрузка | X | да | да | да | да |
| `PATCH /v1/countries/{id}` Update | U | нет | нет | да | нет |
| `POST /v1/countries/{id}:undelete` Undelete | U | нет | нет | да | нет |
| `DELETE /v1/countries/{id}` Delete | D | нет | нет | да | нет |

Для справочников групп G-2 и G-3.

| Операция | Уровень | R-01 reader | R-05 hr-reader | R-02 admin | R-04 hr-admin |
| --- | --- | --- | --- | --- | --- |
| Create, Update, Undelete, Delete в `employees`, `org_units`, `positions`, `assignments` | C U D | нет | нет | нет | да |
| List, Get, история, выгрузка в `employees`, `org_units`, `positions`, `assignments` | R X | да | да | да | да |
| `POST /v1/employees/{id}:dismiss` Dismiss | U | нет | нет | нет | да |
| `POST /v1/employees/{id}:syncAccount` SyncAccount | U | нет | нет | нет | да |
| Create, Update, Undelete, Delete в `salaries`, `absences` | C U D | нет | нет | нет | да |
| List, Get, история, выгрузка в `salaries`, `absences` | R X | нет | да | нет | да |

Прочее.

| Операция | Кому доступна |
| --- | --- |
| Интерфейс администрирования | Вход возможен любой роли; действия, которых роль не даёт, скрыты и отклоняются сервером |
| `GET /v1/livez`, `GET /v1/readyz` | Без токена |
| `GET /metrics` по флагу конфигурации | Только внутри кластера, наружу не публикуется |
| Создание, изменение, удаление справочника через API | Операции нет (FR-RM-38) |
| Изменение или удаление ревизий | Операции нет (FR-RM-45) |

Отказ в уровне доступа отвечает PERMISSION_DENIED. Права проверяются на сервере перед операцией по тройке "роль - группа справочника - уровень" (FR-RM-23). Интерфейс скрывает недоступные действия, но сервер проверяет права независимо (FR-RM-28). Если у пользователя несколько ролей, действует объединение их прав.

## 5. Права на уровне репозитория и инфраструктуры

| Действие | R-03 Инженер | Infra |
| --- | --- | --- |
| Реализовать справочник из состава первой версии: хранилище, методы, спецификация, тесты | да, через pull request с ревью CODEOWNERS | - |
| Применить изменения схемы хранилища | нет, только через задание | да |
| Изменить конфигурацию окружения, секреты | нет | да |
| Прямой доступ к хранилищу | нет, кроме задания изменений схемы | нет |
| Выдать служебному клиенту сервиса права на учётные записи в Keycloak | нет | да |

## 6. Права учётных записей в хранилище и в Keycloak

| Объект | Чтение | Добавление | Изменение | Удаление | Схема |
| --- | --- | --- | --- | --- | --- |
| Записи справочников (учётная запись сервиса) | да | да | да | нет (NFR-RM-16) | нет |
| История справочников (учётная запись сервиса) | да | да | нет | нет | нет |
| Учётная запись задания изменений схемы | да | да | да | да | да |

Служебный клиент сервиса в Keycloak имеет права только на создание, чтение, изменение и блокировку пользователей своего realm. Прав администрирования сервера, других realm и ролей клиентов у него нет.

## 7. Соответствие акторов и ролей

| Актор | Роль | Обоснование |
| --- | --- | --- |
| H-01 Администратор справочников | R-02 | Ведёт классификаторы, кадровые справочники читает |
| H-02 Читатель | R-01 | Читает, смотрит историю, выгружает |
| H-04 Инженер | R-03 и R-02 | Меняет код и схему, в API действует как администратор |
| H-05 HR-администратор | R-04 | Ведёт кадровые справочники, принимает и увольняет |
| S-01 Сервисы-потребители | R-01 по client credentials; Planning System - R-05 | Только чтение; оклады и отсутствия нужны планированию ресурсов |
| S-02 Keycloak | без роли API | Сервис обращается к нему, а не наоборот |
| S-04 Infra | без роли API | Служебные точки не требуют токена |
