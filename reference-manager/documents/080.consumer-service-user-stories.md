# 080 - User Stories: сервис-потребитель

> Формат - см. [состав документов](documents-composition.md), документ 080.

Актор [S-01](030.actors.md): Core, Task Tracker, Planning System, QA System, Reports. Роль [R-01](070.role-matrix.md) по client credentials. Потребителю окладов и отсутствий выдаётся [R-05](070.role-matrix.md). Формат и обозначения - как в [историях администратора](080.admin-user-stories.md).

## US-CS-01 - Читать запись по стабильному имени

Как сервис-потребитель, я хочу хранить у себя имя записи и читать её по нему в любой момент, чтобы ссылки в моих документах не ломались.

**Связи:** UC-07; FR-RM-06, BR-RM-02, BR-RM-04.

- **AC-1. Given** сохранил `currencies/EUR`; **When** вызываю `Get` через год после удаления записи; **Then** получаю запись со `state: DELETED`.
- **AC-2. Given** сохранил имя; **When** справочник расширен новыми записями и полями; **Then** `Get` по прежнему имени возвращает ту же запись.

## US-CS-02 - Читать справочник под сервисной учётной записью

Как сервис-потребитель, я хочу читать справочники с токеном своей сервисной учётной записи, чтобы интеграция не зависела от пользователя.

**Связи:** UC-10; FR-RM-21, FR-RM-22, FR-RM-23.

- **AC-1. Given** сервисная учётная запись имеет роль `reference-reader`; **When** вызываю `List` или `Get`; **Then** получаю данные.
- **AC-2. Given** та же учётная запись; **When** вызываю `Create` или `Delete`; **Then** получаю PERMISSION_DENIED.
- **AC-3. Given** токен просрочен или подписан чужим ключом; **When** вызываю любой метод; **Then** получаю UNAUTHENTICATED без изменения данных.

## US-CS-03 - Не переделывать интеграцию при расширении справочников

Как сервис-потребитель, я хочу, чтобы новые справочники и поля появлялись совместимо, чтобы мой код продолжал работать без изменений.

**Связи:** INT-RM-03, NFR-RM-06, NFR-RM-39, NFR-RM-40.

- **AC-1. Given** интегрировался с `currencies`; **When** в `/v1` добавили коллекцию `grades` и поле `symbol`; **Then** мои запросы к `currencies` возвращают прежние поля плюс необязательное `symbol`; коды ошибок и формат не изменились.
- **AC-2. Given** интегрировался с двумя справочниками; **When** сравниваю их методы; **Then** параметры `filter`, `order_by`, `page_size`, `page_token`, `show_deleted`, формат страницы и ошибок совпадают.

## US-CS-04 - Сослаться на конкретный вызов при ошибке

Как сервис-потребитель, я хочу получать в ошибке идентификаторы запроса и трассы, чтобы команда справочников нашла вызов в журналах.

**Связи:** INT-RM-06, NFR-RM-11, NFR-RM-13.

- **AC-1. Given** передал заголовок `traceparent`; **When** получаю ответ; **Then** в нём `X-Request-Id` и `X-Trace-Id`, а трасса продолжает мою.
- **AC-2. Given** получил INTERNAL; **When** читаю тело; **Then** это `google.rpc.Status` с `ErrorInfo` и `RequestInfo`, без внутренних деталей.

## US-CS-05 - Поддерживать локальную копию без событий

Как сервис-потребитель, я хочу перечитывать справочник по API с выбранным мной интервалом, чтобы иметь актуальную копию без подписки на события.

**Связи:** INT-RM-05, вопрос 3 требований.

- **AC-1. Given** кэширую `currencies` на 10 минут; **When** администратор удалил запись; **Then** после перечитывания `List` с `show_deleted` запись приходит со `state: DELETED`, а без него исчезает.
- **AC-2. Given** мне нужна выборка только изменившихся записей; **When** обращаюсь к команде справочников; **Then** потребность фиксируется в вопросе 3, механизм не обещан.

## US-CS-06 - Разобрать изменение значения по истории

Как сервис-потребитель, я хочу читать историю записи по API, чтобы объяснить пользователю, почему значение в его документе отличается от текущего.

**Связи:** UC-15; FR-RM-46, FR-RM-47.

- **AC-1. Given** сохранил имя записи; **When** читаю её `revisions`; **Then** получаю ревизии от новой к старой с действием, автором, временем и изменениями; роли `reference-reader` достаточно.
- **AC-2. Given** документ хранит номер ревизии на момент создания; **When** запрашиваю запись в состоянии на эту ревизию; **Then** получаю запись такой, какой она была тогда.

## US-CS-07 - Получить сотрудников и организационную структуру

Как сервис-потребитель (Task Tracker, QA System), я хочу читать сотрудников и подразделения из одного источника, чтобы назначать исполнителей и тестировщиков без собственной копии кадровых данных.

**Связи:** UC-08; FR-RM-48, FR-RM-49, INT-RM-01.

- **AC-1. Given** роль `reference-reader`; **When** вызываю `List` в `employees` с `filter="employment_state = EMPLOYED"`; **Then** получаю работающих сотрудников: имя записи, ФИО, подразделение, должность.
- **AC-2. Given** сотрудник уволен; **When** перечитываю `employees` с тем же фильтром; **Then** его в ответе нет, а `Get` по имени возвращает запись с `employment_state: DISMISSED`.
- **AC-3. Given** нужны команды и отделы; **When** вызываю `List` в `org_units`; **Then** получаю подразделения с видом и вышестоящим подразделением.
- **AC-4. Given** кэширую сотрудников; **When** перечитываю список с `show_deleted` не реже раза в час; **Then** кэш отражает приём, увольнение и удаление записей.

## US-CS-08 - Получить значение на дату

Как сервис-потребитель (Planning System), я хочу получить назначение, оклад и отсутствия сотрудника на нужную дату, чтобы считать потребность, доступность и бюджет по данным, действовавшим в тот период.

**Связи:** UC-08; FR-RM-51, FR-RM-52, BR-RM-16.

- **AC-1. Given** у сотрудника два периода назначений; **When** вызываю `List` в `assignments` с фильтром по сотруднику и дате; **Then** получаю одну запись, действовавшую на эту дату.
- **AC-2. Given** роль `reference-hr-reader`; **When** читаю `salaries` и `absences` сотрудника за период; **Then** получаю записи с суммой, валютой и датами.
- **AC-3. Given** роль `reference-reader`; **When** читаю `salaries`; **Then** получаю PERMISSION_DENIED.

## US-CS-09 - Сопоставить пользователя с сотрудником

Как сервис-потребитель, я хочу по идентификатору пользователя из токена найти его HR-профиль, чтобы показать ФИО, подразделение и должность.

**Связи:** UC-08; FR-RM-49, BR-RM-15.

- **AC-1. Given** в токене пользователя есть его идентификатор в Keycloak; **When** вызываю `List` в `employees` с фильтром по `account_user_id`; **Then** получаю ровно одну запись сотрудника.

## US-CS-10 - Извлечь справочники для аналитического хранилища

Как задание ETL команды Reports, я хочу по расписанию выгружать справочники целиком, чтобы строить разрезы отчётов без обращения к сервису при каждом отчёте.

**Связи:** UC-08; INT-RM-12.

- **AC-1. Given** сервисная учётная запись с ролью `reference-reader`; **When** прохожу `List` справочника постранично с `show_deleted` до пустого `next_page_token`; **Then** получаю все записи, включая удалённые, и `total_size` совпадает с числом полученных.
- **AC-2. Given** задание запускается раз в час; **When** запись изменена между запусками; **Then** следующий запуск получает её новое состояние.
- **AC-3. Given** сервис недоступен; **When** задание запускается; **Then** оно завершается ошибкой без частичной загрузки, а сервис ничего в хранилище не отправлял.
