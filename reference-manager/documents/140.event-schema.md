# 140 - Event Schema

> Формат - см. [состав документов](documents-composition.md), документ 140.
> Источник - [135 - Каталог событий](135.event-catalog.md).

## 1. Состояние

Решение согласовано: события не публикуются и не потребляются, поэтому действующих схем событий нет. Потребители перечитывают данные по API с целевым интервалом не реже раза в час. Кто и в каком документе это подтвердил, перечислено в [135, раздел 1](135.event-catalog.md).

## 2. Что заменяет события для потребителей

| Потребность | Механизм | Где описан |
| --- | --- | --- |
| Узнать актуальное значение | `Get` по имени записи | [130](130.api-contracts.md) |
| Обновить локальную копию | Периодический `List` с `show_deleted` | [US-CS-05](080.consumer-service-user-stories.md) |
| Узнать, что и когда изменилось | `ListRevisions` записи | [US-CS-06](080.consumer-service-user-stories.md) |

Формат данных при таком обмене задаёт схема записи справочника и схема ревизии в [130, раздел 4](130.api-contracts.md).

## 3. Заготовка на случай пересмотра

Если решение будет пересмотрено по условию из [135, раздел 6](135.event-catalog.md), сервис публикует одно событие на каждую операцию записи. Формат наследует поля ревизии, поэтому отдельной модели данных не требуется. Заготовка не реализуется и не входит в первую версию.

Событие `RecordChanged`, топик по правилу Infra `<env>.reference-manager.record-changed.v1`.

| Поле | Тип | Обязательность | Пример | Семантика |
| --- | --- | --- | --- | --- |
| `event_id` | строка | да | `8f14e45f-...` | Идентификатор события для устранения дублей на стороне потребителя |
| `name` | строка | да | `employees/1024` | Имя записи |
| `collection` | строка | да | `employees` | Справочник |
| `action` | перечисление | да | `UPDATED` | CREATED, UPDATED, DELETED, UNDELETED |
| `revision` | целое | да | `4` | Номер ревизии записи; порядок событий одной записи |
| `create_time` | время RFC 3339 UTC | да | `2026-10-02T09:00:00Z` | Когда выполнена операция |
| `changes` | список объектов | да | `[{"field": "employment_state", "old_value": "EMPLOYED", "new_value": "DISMISSED"}]` | Изменённые поля с прежними и новыми значениями |

Правила:

- Ключ партиции - `name`. Все события одной записи попадают в одну партицию и приходят в порядке ревизий.
- Совместимость схемы - обратная: поля только добавляются и только необязательные, существующие не меняют тип и не удаляются. Несовместимое изменение - новый топик с суффиксом `v2`.
- Справочники `salaries` и `absences` в событиях не публикуются: их данные ограниченного доступа.
- Доставка at-least-once по правилам Infra. Потребитель устраняет дубли по `event_id` и пропускает ревизию не старше уже применённой.
