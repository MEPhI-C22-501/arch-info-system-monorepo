# 115 - Live-прототип

> Формат - см. [состав документов](documents-composition.md), документ 115.
> См. также [110 - UI/UX прототип](110.ui-ux.md).

Live-прототип - админ-панель из [110](110.ui-ux.md): отдельный компонент интерфейса в [`frontend/admin/`](../frontend/admin/README.md) с экранами S-01..S-05 и переходами между ними. Шаг 1 (2026-10-13) работал на имитации сервиса в памяти страницы. Шаг 2 (2026-10-31, issue #148) подключил панель к API сервиса по контракту [130](130.api-contracts.md) (ADR-022) и к Keycloak: вход Authorization Code с PKCE, роли из токена, имитации и переключателя роли больше нет. Данные приходят из сервиса, на локальном стенде - набор `deployments/seed/demo.sql`.

## Экраны и связки между ними

| Экран | Что есть в панели |
| --- | --- |
| S-01 | Справочники по группам G-2, G-3, G-1 с поиском по названию и числом записей первой страницы. Оклады и отсутствия видны только ролям кадрового контура |
| S-02 | Фильтр AIP-160 передаётся сервису как есть, сортировка `order_by`, флаг `allowDeleted`, размер страницы, переход по `pageToken`. Неверный фильтр - ответ 400 с причиной сервиса и подсветкой строки. Выгрузка - `POST /v1/{коллекция}/export`, файл сохраняется из ответа. "Создать запись" по уровню create |
| S-03 | Форма по схеме справочника: ссылочные поля с подсказкой из целевого справочника, перечисления, даты, числа. Ошибки у полей из `details` ответа 400, прочие ошибки баннером с `X-Trace-Id`, сохранение только изменённых полей в `updateMask`, ответ 409 с предложением перечитать, черновик в окне браузера. Справа сведения (`id`, `is_deleted`, `revision`, `last_changer`, время) и история: ревизии из `GET .../revisions` с операциями JSON Patch, состояние на ревизию собирается из операций |
| S-04 | Без токена - перенаправление в Keycloak и возврат на прежний экран; учётная запись без ролей сервиса - экран отказа с выходом; 403 по отдельному справочнику - баннер |
| S-05 | Карточка сотрудника: состояния, действующие подразделение, должность и оклад, вкладки назначений, окладов и отсутствий, закрытие действующей записи датой, добавление новой, "Уволить" с датой и подтверждением, "Повторить операцию с учётной записью" при PENDING |

## Что делает сервис, а что панель

| Поведение | Где |
| --- | --- |
| Проверка полей, уникальность, ссылки, периоды, иерархия подразделений | Сервис; панель показывает ошибки у полей |
| Права по ролям | Сервис (401, 403); панель только скрывает действия |
| Приём, увольнение, учётная запись Keycloak (FR-RM-53..58) | Сервис; панель вызывает `Create`, `dismiss`, `syncAccount` и показывает `account_state` |
| Фильтр и сортировка | Сервис; панель передаёт `filter` и `order_by` |
| Файл `.xlsx` | Сервис (`export`); панель сохраняет ответ |
| История | Сервис хранит ревизии; панель применяет операции JSON Patch для состояния на ревизию |
| Наименования ссылок | Панель читает первую сотню записей целевого справочника и кэширует их на время страницы |

Панель покрыта тестами (`task tests:frontend`): клиент API (параметры, ошибки, повтор при 429, выгрузка), вход (PKCE по примеру RFC 7636, обмен кода, обновление токена, выход), схемы (роли, тело запроса, маска обновления), JSON Patch.

## Упрощения и условие их снятия

Упрощения шага 1 сняты шагом 2. Осталось одно.

| Упрощение | Когда снимается | Как проверяется |
| --- | --- | --- |
| Временный пароль новой учётной записи не показывается, сотрудник входит после сброса пароля администратором Keycloak | Решение вопроса 18 требований (Infra, #163) | По принятому способу выдачи |
| Наименования ссылок берутся из первой сотни записей целевого справочника | Когда справочник превысит сотню записей: поиск по вводу через `filter` | Подсказка находит запись за пределами первой страницы |

## Критерий готовности

Шаг 2 принят, когда сценарии P-01..P-10 проходят на локальном стенде на реальном сервисе, тесты панели проходят в CI и в интерфейсе нет имитаций. Проверка 2026-10-31 выполнена в браузере на стенде из `task up` с набором `demo.sql`: пройдены P-01..P-06, P-08..P-10 и P-07 без остановки Keycloak.
