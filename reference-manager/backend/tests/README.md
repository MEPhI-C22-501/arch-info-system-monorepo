# Интеграционные тесты

Сценарии описаны на Gherkin в `features/`, шаги реализованы в `steps/http` и `steps/sql`.

Запуск из `reference-manager/` (нужен запущенный Docker):

```sh
task tests:integration
```

или из `backend/`:

```sh
go test -v -tags integration -count=1 ./tests
```

Чтобы видеть ход проверки в реальном времени, запускайте один пакет `./tests` с `-v`.
Без `-v` или со списком пакетов (`./tests/...`) `go test` выводит всё только после завершения пакета.

## Окружение

Окружение описано в `docker-compose.test.yaml`: сервис (собирается из Dockerfile), миграции, Postgres без volume
Keycloak с realm из `deployments/configs/keycloak/arch-info-system-realm.json` и OpenTelemetry Collector, который только печатает полученную телеметрию (Elasticsearch и Kibana в тестах не поднимаются).
Его поднимает и останавливает сам тест через testcontainers (`infra/`), вручную ничего запускать не нужно.

- Состав окружения задаётся только compose-файлом. Тест знает лишь имена сервисов и их внутренние порты.
- Порты на хосте случайные, тест берёт их из запущенных контейнеров. Несколько прогонов не мешают друг другу.
- Логин, пароль и имя БД читаются из переменных окружения контейнера Postgres.
- Каждый прогон получает свой compose-проект. Если процесс упадёт, контейнеры удалит Ryuk.

Сценарии с тегом `@skip` не запускаются.

## Изоляция

Перед каждым сценарием все таблицы схемы, кроме `schema_migrations`, очищаются
(`TRUNCATE ... RESTART IDENTITY CASCADE`), поэтому сценарий начинается с пустой БД,
а идентификаторы генерируются с 1. Данные, нужные сценарию, создаются в нём самом.

## Сравнение тел ответов

JSON-тела сравниваются семантически: порядок полей и форматирование не важны.
Значение `"{{any}}"` в ожидаемом теле совпадает с любым значением, но поле должно
присутствовать. Это нужно для полей, которые генерирует сервис, например `created_at`.

## Значения в ответе

Шаг `the HTTP response contains a value at "<pointer>"` сравнивает не всё тело, а значение
по JSON Pointer (RFC 6901). Токен `*` выбирает все элементы массива, поэтому
`/currencies/*/code` — это массив кодов всех валют в порядке ответа.

## Excel-файлы в ответе

Шаг `the HTTP response contains an Excel sheet "<sheet>" with rows` разбирает тело ответа как xlsx
и сравнивает лист с таблицей. Первая строка листа считается заголовком: колонки таблицы сопоставляются
с колонками листа по нему, поэтому в таблице можно перечислить только нужные колонки в любом порядке.
Строки данных сравниваются по порядку, значения ячеек — в том виде, в каком их показывает Excel
(например, дата `2026-10-01 10:00:00`). Таблица из одного заголовка означает, что строк данных в листе нет.

## Несколько запросов в сценарии

Шаг `a <METHOD> HTTP request` начинает новый запрос: параметры, заголовки и тело предыдущего
сбрасываются. Ответ на предыдущий запрос остаётся доступным до отправки нового, поэтому
шаг `the HTTP request contains URL parameter "<name>" from the HTTP response value at "<pointer>"`
может подставить из него значение, например `nextPageToken` для следующей страницы.

## Пользователь

Сервис принимает только токены Keycloak. Шаг `the HTTP request is authorized as "<user>"` получает токен
пользователя realm по password grant через клиент `reference-manager-ui` и добавляет заголовок `Authorization`.
Шаг `the HTTP request is authorized as "<user>" through the client "<client>"` получает токен через другой клиент,
например `foreign-app`, чьи токены выданы не для аудитории сервиса. Токены кэшируются до истечения срока.

Пароль тестового пользователя совпадает с логином. Идентификаторы пользователей заданы в realm, поэтому
в ожидаемых данных (`changed_by`, `last_changer`) они постоянны.

| Пользователь   | Роль                  | ID                                     |
| -------------- | --------------------- | -------------------------------------- |
| `admin`        | `reference-admin`     | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| `second-admin` | `reference-admin`     | `9b2e4c1a-7d3f-4e8a-b5c6-1f0a2d3e4b5c` |
| `reader`       | `reference-reader`    | `c5a7e2d0-3b4f-4a19-8e6d-2f1b0c9d8e7a` |
| `hr-admin`     | `reference-hr-admin`  | `d81f4b6c-2e9a-4c35-b7d0-6a5e4f3c2b1d` |
| `hr-reader`    | `reference-hr-reader` | `e2b9c8a7-6d5f-4e3a-9b1c-0f8e7d6c5b4a` |
| `outsider`     | нет ролей сервиса     | `f7a6b5c4-d3e2-4f1a-8b9c-1d2e3f4a5b6c` |

Издатель токенов зафиксирован через `KC_HOSTNAME` (`http://localhost:8180`), поэтому он совпадает с `issuer_url`
локальной конфигурации, с какого бы порта хоста тест ни получал токен.

## Ограничение частоты запросов

Сервис ограничивает частоту запросов. Если он отвечает `429 Too Many Requests`, шаг
`the HTTP request is sent to "<path>"` ждёт время из заголовка `Retry-After` и отправляет запрос повторно
(не более 5 попыток), поэтому число сценариев не упирается в лимит.
