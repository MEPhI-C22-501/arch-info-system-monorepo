# 080 — User Stories: администратор модуля

**Этап 2, блок C.** Редакция 1.0 от 24.09.2026. Статус: к ревью команды.

Актор [H-06](030.actors.md), роль [R-06](070.role-matrix.md).
Формат: «Как <актор>, я хочу <функция>, чтобы <ценность>».
Given / When / Then означают «Дано / Когда / Тогда». Все сценарии — спецификации
приёмки, а не результаты выполненных тестов. Общие условия: проверены роль,
область, редакция и состояние объекта. Приоритеты — в [090](090.features-epics.md),
трассировка и тесты — в [095](095.requirements-check.md).

## US-AD-01 — Настроить доступ и зависимости

Как администратор модуля, я хочу проверять OIDC, привязки областей и соединения с сервисами, чтобы подготовить безопасную работу модуля.

**Связи:** UC-12 ([060](060.use-cases.md)); R-06; NFR-02, NFR-03, NFR-04.

- **AC-1. Given** Infra предоставила конфигурацию и решение владельца о правах зарегистрировано; **When** применяю привязку и проверяю вход; **Then** используются Keycloak и проверенные claims, изменение аудируется без секретов.
- **AC-2. Given** токен просрочен, имеет неверные подпись, issuer или audience; **When** обращаюсь к защищённому API; **Then** доступ отклоняется без изменения данных.
- **AC-3. Given** есть только MODULE_ADMIN; **When** пытаюсь назначить себе право утверждения или изменить baseline; **Then** получаю отказ, диагностика не раскрывает секреты.

<a id="us-ad-02"></a>

## US-AD-02 — Восстановить обмен

Как администратор модуля, я хочу диагностировать и повторять неуспешные операции, чтобы восстановить синхронизацию без дублей.

**Связи:** UC-07, UC-10, UC-12 ([060](060.use-cases.md)); R-06; FR-11, FR-14.

- **AC-1. Given** публикация FAILED и её версия ещё актуальна; **When** после сверки с получателем повторяю отправку; **Then** сохраняется тот же ключ, SUCCEEDED ставится только после подтверждения.
- **AC-2. Given** версия замещена до отправки; **When** запрашиваю повтор старой публикации; **Then** отправка запрещена с SUPERSEDED_BEFORE_DELIVERY, новая версия не затирается.
- **AC-3. Given** пришло позднее подтверждение доставки прежней попытки; **When** система сопоставляет ID; **Then** существующий Notification становится DELIVERED без нового запроса.

<a id="us-ad-03"></a>

## US-AD-03 — Проверить выдачу Reports и НСИ

Как администратор модуля, я хочу видеть состояние согласованных обменов, чтобы обнаруживать устаревшие данные и ошибки прав.

**Связи:** UC-11, UC-12 ([060](060.use-cases.md)); R-06; FR-15.

- **AC-1. Given** Reports запрашивает разрешённую проекцию, а НСИ доступны по REST; **When** выполняются диагностические проверки; **Then** фиксируется успешный обмен и даты срезов без копирования бизнес-данных в технический журнал.
- **AC-2. Given** нет согласованного контракта Reports или источника календарей; **When** запускаю диагностику; **Then** вижу D-05 или D-03, успешный ответ заглушки не считается готовой интеграцией.
