# 160 — План интеграции

Редакция 1.0, 05.10.2026. Этапы: **проектирование → планирование разработки →
разработка → тестирование**. Сроки заданы контрольными выходами этапов;
календарные даты назначает руководитель проекта, они не выдумываются в документации.
Полная матрица данных/протоколов — [020 §3](020.system-context.md#3-единая-матрица-обмена).

## Порядок стыковки и приёмка

Для каждой строки: на проектировании согласовать [130](130.api-contracts.md),
[135](135.event-catalog.md)/[140](140.event-schema.md); при планировании разработки
назначить исполнителей, доступы и фикстуры; на разработке выполнить adapter +
контрактную заглушку, затем реальный сервис; на тестировании — соответствующий
T-INT из [095](095.requirements-check.md). Заглушка имеет отдельный verdict.

| Очередь / ID | Способ / протокол | Владелец Planning System | Смежный владелец | Срок реализации | Критерий приёмки на тестировании |
| --- | --- | --- | --- | --- | --- |
| 1 / INT-01 | OIDC, HTTPS/JWKS | Ответственный за API/доступ | Infra / Keycloak | До первого защищённого CRUD на разработке | Реальный вход, отрицательные токены и 070; T-INT-01 |

Название команды — ответственность, а не утверждение о согласии конкретного человека.

## Условия допуска, а не автоматическое закрытие вопросов

| Вопрос | Что должно появиться до приёмки | Зависимые проверки |
| --- | --- | --- |
| D-01 | Подписанный обеими командами mapping project/epic/iteration ID, API TT, внешний producer факта, sourceRevision, tombstone и сверка | T-INT-03, T-NFR-06/10 |
| D-02 | Подтверждённые REST-схемы НСИ и их версии; обязательная Kafka НСИ исключена | T-INT-02 |
| D-03 | Работающий HR API, уникальный account_user_id; утверждённые нормы календаря, TZ и процедура актуализации | T-FR-05, T-INT-02 |
| D-04 | Назначенный поставщик, каналы, receipt, timeout и доступы | T-INT-04 |
| D-05 | Согласованные поля Reports, состав batch, срок хранения и расписание загрузки | T-INT-05/08 |
| D-06/D-08 | Решение владельца продукта о делегировании, составе review и блокировках | T-FR-09, T-NFR-14 |
| D-07 | Принятая методика ADR-011, источник ETC, датированные ставки/нормы и порог отклонения | T-FR-10, T-NFR-15 |
| D-09 | QA/TT/PS согласовали источник итераций, связь с RELEASE, исторические ссылки и API-проекцию | T-INT-07 |

На проектировании каждый вопрос получает решение/проект контракта. Он снимается
из открытого реестра 020 только после подтверждения владельцев со ссылкой на PR
или протокол; результат реального теста фиксируется отдельно.

## Переход к эксплуатации

До тестирования Infra выдаёт endpoint/JWKS/ACL/bucket без секретов в Git;
Planning System предоставляет image digest, health/readiness и миграции.
Перед приёмкой выполнить потерю связи, повтор, DLQ replay, восстановление БД/S3,
security checklist и minikube smoke из [165](165.deployment-diagram.md).
Протокол: commit, версии схем, среда, входы, ожидаемое/фактическое, логи,
passed/failed/blocked и ответственные. Отсутствующий сервис = blocked.
