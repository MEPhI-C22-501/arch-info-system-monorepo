# 130 — Контракты API

Редакция 1.0, 05.10.2026. **Предлагаемые** контракты 1.0.0; endpoint сервера
ещё не реализован. [OpenAPI 3.1](contracts/openapi.json),
[примеры успешного и ошибочного запроса/ответа каждой операции](contracts/http-examples.json),
[предложение приёмника Task Tracker](contracts/task-tracker-receiver.openapi.json).

## Общие правила

HTTPS, JSON UTF-8, UUID, RFC3339 UTC; money/hours decimal до двух знаков.
Bearer JWT проверяется по 070; service scopes отдельно от пользовательских ролей.
Пути /api/v1; semver: optional поле/новый endpoint — minor, несовместимое изменение
сигнатуры/смысла/обязательности — major с согласованием TT, Reports и QA.
Все схемы и примеры доступны локально, адреса example.invalid — placeholder.

Изменения имеют Idempotency-Key; ключ связан с subject, operation и хешем тела,
повтор возвращает исходный результат; другой body с тем же ключом даёт 409.
If-Match содержит ETag revision; нет заголовка — 400, устаревшая revision — 412.
Права проверяются заново и при повторе. Путь/тело/receipt должны ссылаться на один
проект и версию. Submit требует непустого валидного маршрута; RETURN — комментария.
Утверждённые объекты не редактируются. Partial update карточки задаёт только name/goal;
изменение приоритета, назначений и согласований требует отдельных доменных прав.

200/201 — локальный результат, 202 — принятая операция, опрос getOperation.
Ошибки: 400 синтаксис/нет заголовка, 401 токен, 403 права, 404 скрытый/отсутствующий
объект, 409 состояние/идемпотентность, 412 revision, 422 бизнес-валидация, 429 лимит,
503 зависимость. Ошибка содержит code/message/correlationId/details; rollback
не оставляет частичного изменения. Binary/multipart исключения явно заданы в OAS.

Пагинация pageSize 1..200 (50 по умолчанию), cursor непрозрачен и подписан, связан
с фильтрами/областью/срезом. nextCursor=null завершает список. Сортировка проектов
(priority,id), строк batch — ordinal; изменение фильтра требует нового cursor.
У batch читаются только READY; PENDING — 409, EXPIRED — 409 BATCH_EXPIRED.
Scope/token проверяется на каждой странице. Денежные поля без cost.read
**отсутствуют**, а не равны нулю; null означает неизвестное при наличии права.

## Межмодульные контракты и ограничения

Task Tracker читает publication и подтверждает receipt; Planning System также
может отправить тот же payload через предложенный PUT приёмника TT. Это один
Idempotency-Key, не независимые публикации. Выбор push/pull согласуется D-01;
основной сценарий 155 — push. Версии сравниваются по versionNumber, старый retry
не заменяет новую. Kafka Task* сообщает абсолютные срезы по [140](140.event-schema.md);
этот документ не объявляет внутренний API TT уже совместимым.

QA читает getReleaseContext: APPROVED/ACTIVE или историческую ранее утверждённую
версию, никогда черновик. Items содержит RELEASE/MILESTONE/EPIC/FEATURE; итерации
хранят внешний ID/sourceRevision, null при отсутствии подтверждённого входа.
Reports читает getReportProjection, либо запускает createExport и читает manifest
до READY, затем все страницы. Export содержит планы (структуру и baseline),
потребность, доступность, назначения, прогноз/бюджетные корректировки.
Дата и состав фиксируются до READY; counts проверяются перед merge потребителя.
Устаревший forecast остаётся с собственной dataAsOf и PARTIAL проекции.

Входные НСИ/HR используют API владельца: [Reference Manager 130](../../reference-manager/documents/130.api-contracts.md),
его resource names и page_token/etag не переименовываются на проволоке.
Keycloak — OIDC/JWKS, Object Storage — S3; их API не копируются в собственный OAS.
Notification Service обменивается событиями 140. Матрица владельцев — [020](020.system-context.md).

Покрытие этой версии OAS: сквозной цикл и интеграционные контракты. Отдельные
CRUD портфеля/программы, нормы календаря, управление ресурсами/ставками и настройки
администратора ещё требуют детализации API перед реализацией; NFR-10 остаётся partial.
Спецификация модели 120 и права 070 обязательны для этих будущих операций.
