# 010 — Глоссарий Planning System

**Блок A.** Редакция 1.1 от 24.09.2026, к ревью команды.
Основания: [Vision](vision.md), [ТЗ, разделы 2–4](technical-specification.md),
[доменная модель](architecture.md#5-доменная-модель).

## 1. Термины предметной области

| Термин | Определение | Контекст / модуль ERP | Синонимы |
| --- | --- | --- | --- |
| Портфель проектов | Совокупность проектов, конкурирующих за общие ресурсы и рассматриваемых совместно при выборе приоритетов и сроков. | Planning System, портфель | Портфель |
| Программа | Группа связанных проектов внутри портфеля, объединённых общей целью. Проект может не входить в программу. | Planning System, FR-01 | Программа проектов |
| Проект | Единица управления результатом, сроками и плановыми ресурсами. Создаётся в Planning System; в Task Tracker передаётся его внешний идентификатор. | Planning System — мастер | Project |
| Приоритет проекта | Относительная важность проекта для распределения ограниченных ресурсов; не совпадает с приоритетом отдельной задачи. | Planning System | Портфельный приоритет |
| Горизонт планирования | Интервал дат, в пределах которого составляются календарь и распределение ресурсов. | Planning System | Плановый период |
| Годовой план | Согласованный набор плановых версий проектов на год с общим представлением сроков и загрузки. | Planning System, FR-02 | Годовой портфельный план |
| Скользящее планирование | Регулярное уточнение будущей части плана по новым данным об исполнении и доступности, с сохранением истории версий. | Planning System, FR-02 | Перепланирование, rolling planning |
| Версия плана | Идентифицируемый вариант декомпозиции, оценок, дат, зависимостей и назначений одного проекта. | Planning System, PlanVersion | Плановая версия |
| Базовая линия | Неизменяемое содержимое утверждённой версии, относительно которого рассчитывают отклонения. | Planning System, FR-09 | Baseline |
| Активная версия | Единственная введённая в действие версия проекта; её плановые рамки подлежат публикации в Task Tracker. | Planning System | Действующий план |
| Сценарий «что если» | Изолированный вариант плана для оценки изменения объёма, дат или ресурсов. До утверждения и активации не заменяет действующий план. | Planning System, PlanVersion с kind=SCENARIO | Сценарий |
| Элемент плана | Узел декомпозиции проекта: этап, веха, эпик или фича. Это плановый объект, который может быть связан с несколькими задачами. | Planning System, PlanItem | Плановая работа |
| Этап | Крупная часть проекта с определённым результатом и временными границами. | Planning System | Фаза |
| Веха | Контрольная точка достижения результата. В модели имеет одну дату и нулевую собственную трудоёмкость. | Planning System | Milestone |
| Эпик | Крупный функциональный результат, который можно декомпозировать на фичи. | Planning System; связь с Task Tracker | Epic |
| Фича | Планируемая функциональная возможность с оценкой и сроками; задачи её реализации ведутся в Task Tracker. | Planning System; связь с Task Tracker | Feature |
| Зависимость | Ограничение взаимного положения элементов плана во времени. Для первой модели принято «окончание–начало» без отрицательного лага. | Planning System, проектное уточнение | Предшествование, FS |
| Плановая трудоёмкость | Оценка объёма работы в человеко-часах. У родителей агрегируется по дочерним элементам без повторного учёта. | Planning System; Task Tracker на уровне задачи | Оценка, plannedHours |
| Фактическая трудоёмкость | Уже зарегистрированные трудозатраты по задачам; первоисточник — Task Tracker. | Task Tracker — мастер; Planning System — проекция | Факт, actualHours |
| Оставшаяся трудоёмкость | Оценка человеко-часов, ещё необходимых для завершения работ. Может пересматриваться и превышать первоначальную оценку; не равна арифметической разности плана и факта Task Tracker. | Planning System, прогноз | Остаток в часах, remainingHours |
| Оставшаяся длительность | Прогноз календарного времени до завершения с учётом зависимостей и доступности; не тождественна оставшимся человеко-часам. | Planning System | remainingDuration |
| Ресурсная потребность | Необходимый объём часов для конкретного элемента плана, периода, проектной роли и грейда. | Planning System, ResourceDemand | Потребность в людях |
| Проектная роль | Функция сотрудника при выполнении работы, например аналитик или разработчик. Не является ролью доступа к приложению. | Reference Manager — классификатор; Planning System — применение | Специализация |
| Грейд | Уровень квалификации, используемый в оценке потребности и подборе исполнителя. | Reference Manager — классификатор | Уровень |
| Рабочий календарь | Набор рабочих и нерабочих дней, часовой пояс и нормы времени. Источник календарей требует согласования D-03. | Planning System / Reference Manager | Производственный календарь |
| Доступная мощность | Число часов, которое сотрудник может выделить в периоде после учёта календаря и отсутствий, до вычитания назначений. | Planning System, EmployeeAvailability | Доступность, capacity |
| Назначение | Выделение конкретного сотрудника и количества часов на ресурсную потребность в заданном периоде. | Planning System, Allocation | Allocation |
| Загрузка | Сумма назначений сотрудника за период по рассматриваемым версиям проектов. Для сценария заменяется версия его проекта, остальные берутся из активного портфеля. | Planning System | Плановая занятость |
| Перегрузка | Превышение загрузки над доступной мощностью в одном и том же периоде. | Planning System | Overallocation |
| Дефицит ресурсов | Непокрытая подтверждёнными назначениями часть ресурсной потребности по роли и грейду. | Planning System | Нехватка ресурса |
| Простой | Положительная разница между доступной мощностью и назначенными часами в выбранном периоде. | Planning System | Свободная мощность |
| Ресурсный конфликт | Выявленное несоответствие плана ограничениям ресурсов: перегрузка, дефицит или несовместимое назначение. | Planning System | Конфликт загрузки |
| Диаграмма Ганта | Календарное представление элементов плана, зависимостей и назначений по проектам или людям. | Planning System | Гант |
| План-факт | Сопоставление одной явно указанной базовой линии с фактическими данными на известный момент времени. | Planning System, Reports | Отклонение от плана |
| Срез факта | Локальная проекция сведений задачи с внешним идентификатором, версией источника и временем актуальности. | Planning System, TaskSnapshot | Снимок задачи |
| Единый прогноз | Согласованный результат расчёта остатка трудоёмкости, календарного завершения и бюджетной корректировки на одной версии и одном срезе данных. | Planning System, ForecastSnapshot | Прогноз остатка |
| Бюджетная корректировка | Предлагаемое изменение плановой стоимости по прогнозу завершения. Не является платёжным документом или бухгалтерской проводкой. | Planning System; Reports — чтение | budgetAdjustment |
| Актуальность данных | Момент и полнота входных данных расчёта. Старый или неполный факт должен быть видим пользователю. | Planning System, dataAsOf | Дата среза |
| Согласование версии | Получение решений по содержимому конкретной редакции: ресурсного подтверждения и решения уполномоченного руководителя. | Planning System | Review |
| Активация плана | Введение утверждённой версии в действие с замещением прежней активной версии того же проекта. | Planning System | PlanActivated |
| Публикация плана | Передача активной версии, её структуры, сроков и назначений в Task Tracker с фиксацией подтверждения приёма. | Planning System → Task Tracker | Синхронизация плановых рамок |
| Вложение | Файл, связанный с проектом, версией или сценарием. Метаданные и права принадлежат Planning System, содержимое — Object Storage. | Planning System / Object Storage | Attachment |
| Оповещение | Сообщение пользователю о связанном изменении, конфликте или решении; запрос и подтверждение доставки — разные факты. | Planning System / Notification Service | Уведомление |

Правила для горизонта, сценария, вехи, зависимости и расчётных величин — проектные
уточнения исходного ТЗ; конкретные ограничения приведены в [050](050.entities.md).

## 2. Соответствие терминам соседних модулей

У Task Tracker появился выделенный глоссарий; для остальных модулей ниже даны
ссылки на существующие разделы терминов. Это предложенное соответствие;
подтверждение командами ещё не зафиксировано. Совпадение названия не означает
совпадение семантики или согласование владельца данных.

| Термин Planning System | Термин и источник смежного модуля | Правило соответствия |
| --- | --- | --- |
| Элемент плана | [Рабочий элемент, Task Tracker](../../task-tracker/docs/block-a-context-and-scope/010.glossary.md) | Не синонимы: один элемент плана может объединять несколько задач; у Task Tracker также есть типы «Проект» и «Эпик», их связь с мастер-объектами Planning System ещё согласуется. |
| Фактическая трудоёмкость | [Фактическая трудоёмкость, Task Tracker](../../task-tracker/docs/block-a-context-and-scope/010.glossary.md) | Часы источника сохраняются; агрегирование не создаёт новых трудозатрат. |
| Оставшаяся трудоёмкость | [Оставшееся время, Task Tracker](../../task-tracker/docs/block-a-context-and-scope/010.glossary.md) | У Task Tracker это «актуальный план − факт», допускающий отрицательный результат. В Planning System это неотрицательная оценка будущей работы; автоматическое отождествление запрещено, D-07. |
| Этап / веха | [Итерация, Task Tracker](../../task-tracker/docs/block-a-context-and-scope/010.glossary.md) | Не устанавливаем автоматическое соответствие: состав и идентификаторы согласуются отдельно. |
| Проектная роль / грейд | [Справочник, запись, код, Reference Manager §2](../../reference-manager/docs/system-requirements.md#2-термины) | Ссылки по стабильным кодам; удалённое значение сохраняется в истории, но не выбирается для нового назначения. |
| План-факт | [План-факт, Reports §1.4](../../reports/docs/vision.md#14-термины) | Передаётся ID сравниваемой базовой линии и дата среза факта. |
| Актуальность данных | [Лаг витрины, Reports §1.4](../../reports/docs/vision.md#14-термины) | Возраст входных данных Planning System и лаг витрины Reports измеряются раздельно. |

Неподтверждённые соответствия связаны с D-01–D-05 и D-07 в
[реестре договорённостей](020.system-context.md#6-открытые-договорённости).
