## 1. Значение статусов и границы проверки

- **covered**: требование связано с документами, историей и спецификацией теста;
  для указанного объёма достаточно требований, чтобы начать реализацию.
- **partial**: связи есть, но остаётся предметное решение, контракт или непринятый
  измеримый порог, влияющий на приёмку. Причина указана в строке.
- **missing**: отсутствует требование, история или сценарий проверки.

Это статусы полноты документации, не состояния реализации. Все тесты ниже имеют
статус **planned**, ни один не объявлен passed. В папке Planning System на базе
анализа есть документация; исполняемого приложения и результатов его испытаний нет.
Проектные уточнения блока B сохраняют статус «к ревью» даже при covered.

ID FR-01–FR-15 сохранены из ТЗ. INT-01–INT-06 разложены из §4.5, не являются
дополнительными интеграциями. NFR-01–NFR-16 уточняют §4.4 и предложенные атрибуты
качества. Новые функциональные требования вместо существующих не вводятся.

## 5. Каталог тестовых спецификаций

**Общие условия:** тестовые пользователи всех шести ролей, два непересекающихся
портфеля, проекты, сотрудники и календари, явно заданные ставки/валюта для
денежных позитивных сценариев. Для отрицательных сценариев нужные входы удаляются
из тестовой копии. Все операции выполняются только на тестовых данных.

Для T-FR-01–T-FR-15 исходное состояние, действие и ожидаемый результат — все AC
историй из §2; каждый AC получает отдельный результат. Тест проходит только если
пройдены все применимые сценарии; недоступный внешний сервис означает blocked,
а не исключение сценария из знаменателя. Проверки прав/состояний выполняются
как через UI, так и прямым запросом к API. Контрактные заглушки допустимы в M4,
но T-INT-* принимаются только с согласованными реальными сервисами на стенде.
