## INT-01 — Единый вход

**Назначение:** Единая личность и серверные права.

**Схема:** браузер → Keycloak → JWT → API → JWKS + RBAC.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| OIDC + локальная JWKS-проверка | Стандартные токены; без сетевого вызова на каждый запрос | Отзыв ограничен exp; нужен кэш и ротация ключей | Выбран |
| Introspection | Быстрая проверка отзыва | Задержка и зависимость каждого запроса от Keycloak | Отклонён для первой версии |
| Локальные пароли | Автономность | Второй реестр и нарушение требования единого входа | Отклонён для первой версии |

**Обоснование:** Готовый Keycloak соответствует ТЗ; локальная проверка уменьшает связность. ADR-001.

**Ожидаемый результат:** Каждый запрос имеет проверенный subject и область.

**Критерии проверки:** Реальный вход; неверные issuer/audience/exp/подпись отклонены, чужой проект недоступен, ротация ключа работает. T-INT-01, статус planned до реального прогона.

## INT-02 — НСИ и кадровые входы

**Назначение:** Чтение HR и кодов без второго мастера.

**Схема:** adapter → REST Reference Manager → кэш name/etag → плановый snapshot.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| REST владельца | Поддерживается поставщиком; явные страницы и состояния | Нужна периодическая сверка | Выбран |
| Kafka НСИ | Малая задержка | У поставщика нет этого контракта | Отклонён для первой версии |
| XLSX | Удобный ручной импорт | Устаревает, нет автоматической сверки и etag | Отклонён для первой версии |

**Обоснование:** Использовать существующий контракт чтения. employeeId = resource name, subject = account_user_id. Оклад не равен часовой ставке; календарные нормы принадлежат PS. При переименовании обновляются ФИО и etag кэша, ID и назначения сохраняются; baseline хранит прежний snapshot. ADR-008/010.

**Ожидаемый результат:** Воспроизводимые кадровые входы.

**Критерии проверки:** Все страницы прочитаны; повтор не создаёт дублей; переименование сохраняет назначения; удаление не разрушает baseline; отсутствие норм даёт PARTIAL. T-INT-02, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).

## INT-03 — План и факт Task Tracker

**Назначение:** Публикация рамок и получение факта.

**Схема:** ACTIVE → Publication → HTTP adapter TT → receipt; TT → Kafka → inbox → TaskSnapshot → Forecast; REST-сверка.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| REST + Kafka + REST-сверка | Подтверждение применения, быстрая реакция и восстановление | Mapping, producer, DLQ и сверка требуют согласования | Выбран |
| Только polling | Простой старт, есть facts API | Задержка; страницы не дают общий snapshot, нужны удаления | Отклонён для первой версии |
| Только Kafka | Буфер и независимые потребители | Ack брокера не подтверждает применение, нет адресного чтения | Отклонён для первой версии |
| Общая БД | Простые join | Нарушает владение и независимость выпуска | Отклонён для первой версии |

**Обоснование:** Публикации нужен receipt, факту — sourceRevision и дедупликация. У TT уже есть PUT /api/v1/planning/projects/{externalId} и GET .../facts; наш /versions/{planVersionId} — прежнее отдельное предложение. Сверка и нерешённый mapping в [реестре](integration-agreements.md#task-tracker-d-01). ADR-004/008/011. Без D-01 реальная интеграция blocked.

**Ожидаемый результат:** Одна применённая версия и один учёт изменения факта.

**Критерии проверки:** Десять повторов не удваивают часы; старая версия не откатывает проекцию; конфликт payload обнаружен; удаление запускает сверку; remainingHours TT не принимается за ETC без D-07. T-INT-03, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).

## INT-04 — Оповещения

**Назначение:** Доставка без блокировки активации.

**Схема:** причина → NotificationRequested → Kafka → поставщик → NotificationDelivered → inbox.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| Kafka + receipt | Буфер при сбое, активация не ждёт канала | Нужны дедупликация и DLQ | Выбран |
| HTTP | Адресный ack запроса | Сетевая зависимость; ack тоже не означает доставку | Отклонён для первой версии |
| Прямой SMTP | Нет отдельного API | Дублирует Infra, связывает модуль с каналом и секретами | Отклонён для первой версии |

**Обоснование:** Доставка асинхронна: broker ack = SENT, не DELIVERED. Поставщик ещё D-04. ADR-004/008.

**Ожидаемый результат:** Причинное уведомление с достоверным статусом.

**Критерии проверки:** Timeout сохраняет ошибку; поздний receipt и ручной retry не создают второго сообщения. T-INT-04, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).

## INT-05 — Оперативная проекция Reports

**Назначение:** Текущий разрешённый срез.

**Схема:** Reports → REST projection → область/cost.read → срез.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| REST projection | Адресное чтение и проверка прав | Зависимость от API; данные могут устареть | Выбран |
| Kafka-копия | Автономное чтение | Задержка и риск устаревших прав; нужна сверка | Отклонён для первой версии |
| Чтение БД PS | Прямой доступ | Обход прав, зависимость от внутренней схемы | Отклонён для первой версии |

**Обоснование:** Отдельная проекция ограничивает поля и показывает dataAsOf/quality вместо ложных нулей. ADR-009/012.

**Ожидаемый результат:** Дашборд разрешённого проекта с качеством и датой.

**Критерии проверки:** Чужая область отклонена; без cost.read денежные поля отсутствуют; устаревший прогноз помечен PARTIAL. T-INT-05, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).

## INT-06 — Вложения

**Назначение:** Файлы с правами владельца.

**Схема:** API → UPLOADING → S3 upload → проверка → AVAILABLE.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| S3 / MinIO | Потоковая передача и независимое хранение | Согласование БД и жизненного цикла объекта | Выбран |
| PostgreSQL blobs | Одна транзакция | Рост БД и резервных копий | Отклонён для первой версии |
| Диск API | Простой старт | Нет общего файла у реплик; потеря при замене контейнера | Отклонён для первой версии |

**Обоснование:** Общий S3 Infra соответствует нескольким экземплярам API. Доступ проверяет PS. ADR-007.

**Ожидаемый результат:** Доступен только полностью проверенный файл.

**Критерии проверки:** Проверены размер/тип/хеш; чужой objectKey недоступен; timeout не открывает неполный файл; повтор удаления безопасен. T-INT-06, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).

## INT-07 — Релизные рамки QA System

**Назначение:** Устойчивая привязка тест-плана к релизу.

**Схема:** QA → GET release-context(projectId, planVersionId) → релизы/вехи и ссылки на итерации TT.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| REST выбранной версии | Исторический адресный срез; qa.read | Нужен доступный API и качество итераций | Выбран |
| Только PlanActivated | Быстрая инвалидация кэша | Нет произвольного чтения старой версии | Отклонён для первой версии |
| Общая таблица | Простой join | Нарушение владения и независимости схем | Отклонён для первой версии |

**Обоснование:** QA нужна определённая версия. Итерации остаются у TT; при недоступной проекции iterations=null, quality=PARTIAL с причиной. QA уже описала release-context в своих 130/160; двустороннее принятие версии и выбор источника итераций остаются D-09. ADR-012.

**Ожидаемый результат:** Привязка сохраняется после перепланирования.

**Критерии проверки:** Устойчивый релизный ID; чужой проект и черновик отклонены; PARTIAL и недоступность обработаны. T-INT-07, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).

## INT-08 — Пакетный ETL в Reports

**Назначение:** Целостная выгрузка планов, ресурсов и прогноза.

**Схема:** Reports → создать batch → неизменяемые страницы → staging → manifest/уникальность → merge → checkpoint.

| Вариант | Плюсы | Минусы | Решение |
| --- | --- | --- | --- |
| Материализованный batch REST | Фиксированный snapshot, повтор страницы, manifest | Хранение партии, TTL, количество запросов | Выбран |
| Живые страницы | Не нужно хранить snapshot | Смешение версий между страницами | Отклонён для первой версии |
| Только Kafka | Инкрементальные сигналы | Нет начальной загрузки и надёжного watermark | Отклонён для первой версии |
| S3-файлы | Мало запросов на больших объёмах | Нужны lifecycle, ACL, формат; отложен до замера объёма | Отклонён для первой версии |

**Обоснование:** Полный snapshot выбран до согласования watermark. ARCHIVED/tombstone явны; EXPIRED запускает новую партию, частичный staging не публикуется. ADR-009/012.

**Ожидаемый результат:** Одна целостная версия витрины без повторных часов.

**Критерии проверки:** Сбой второй страницы и повтор не создают дублей; counts и уникальность совпадают; версии не смешаны; без cost.read нет денег; EXPIRED обработан. T-INT-08, статус planned до реального прогона.

**Связи:** [130](130.api-contracts.md), [135](135.event-catalog.md), [140](140.event-schema.md), [145](145.architecture-decisions.md), [160](160.integration-plan.md), [165](165.deployment-diagram.md).
