## Основания и правила чтения

Приоритет для функционального объёма Planning System имеют существующие
[Vision](vision.md), [ТЗ](technical-specification.md),
[архитектура](architecture.md) и [ландшафт](system-landscape.md).
Исходная [модель состояний плана](diagrams/08-uml-plan-state.mmd) сохранена.
Ветка `codex/planning-system-docs` проверена: её материалы уже включены и уточнены
в `main`; устаревшие редакции не используются как новая база.

Для границ интеграций дополнительно изучены
[Reference Manager](../../reference-manager/docs/system-requirements.md),
[Task Tracker](../../task-tracker/docs/vision.md),
[Reports](../../reports/docs/vision.md) и [Infra](../../infra/vision.md).
Имена событий из архитектуры сохраняются, но не означают наличия согласованных
топиков и схем. События Event Storming также включают внутренние бизнес-факты.

При актуализации 24.09.2026 учтены новый глоссарий Task Tracker, его внутренний
каталог событий и различие между арифметическим остатком задачи и прогнозом
необходимой трудоёмкости. Открытые вопросы владения проектами, внешнего обмена
и удаления задач отражены в D-01/D-07; согласование с командой Task Tracker
этим документом не подменяется.

Требования к составу взяты из предоставленного `documents-composition.md`, только
из блоков A и B. Файлы размещены в `planning-system/docs` по запросу команды.
Документы блоков C–I этим комплектом не создаются.

Атрибуты, дополнительные состояния, правила согласования и расчёта, которых нет
в исходном ТЗ, помечены как **проектное уточнение**. Они делают модель проверяемой,
но не выдаются за решения, уже утверждённые всеми командами. Общий реестр
расхождений и ответственных находится в [020, раздел 6](020.system-context.md#6-открытые-договорённости).

## Проверка полноты

В глоссарии приведены предметные термины; у интеграций указаны направления,
протоколы и степень согласованности. Карты Event Storming связаны с агрегатами и
Use Cases. У сущностей определены типы, ограничения, локальные FK и внешние ссылки;
у жизненных циклов — статусы и триггеры. В Use Cases есть include/extend,
предусловия, постусловия, основной и альтернативные потоки; таблица покрытия
связывает все 15 функциональных требований ТЗ со сценариями.
