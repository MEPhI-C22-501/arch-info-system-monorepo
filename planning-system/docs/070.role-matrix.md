# 070 — Роли и права Planning System

**Этап 2, блок C.** Редакция 1.0 от 24.09.2026. Статус: к ревью команды.

Основания: [акторы](030.actors.md), [UC-01–UC-12](060.use-cases.md),
[состояния и инварианты](050.entities.md), [ТЗ §4.3–4.5](technical-specification.md).
Матрица — проектное уточнение; соответствие claims Keycloak и делегирование
утверждаются по D-03/D-06/D-08 из [реестра договорённостей](020.system-context.md#6-открытые-договорённости).

## 1. Роли и области

| Роль доступа | Актор | Область |
| --- | --- | --- |
| R-01 PORTFOLIO_OWNER | H-01 Руководитель портфеля | Явно назначенные портфели и их проекты |
| R-02 PLANNER | H-02 Планировщик / PMO | Назначенные портфели/проекты |
| R-03 PROJECT_MANAGER | H-03 Руководитель проекта | Только закреплённые проекты |
| R-04 RESOURCE_MANAGER | H-04 Ресурсный руководитель | Свои сотрудники и связанные назначения; минимум сведений о работах для согласования |
| R-05 TEAM_MEMBER | H-05 Участник команды | Собственные назначения и разрешённые связанные объекты |
| R-06 MODULE_ADMIN | H-06 Администратор | Настройки и технические журналы своего модуля |

Это логические роли, а не уже созданные realm/client roles. Роль/грейд ресурса
из Reference Manager не предоставляет права доступа. Связь Keycloak `sub` с
`employeeId` должна быть подтверждена; при отсутствии связи личный календарь
нельзя получать по имени или email.

`C` = create, `R` = read, `U` = update, `D` = delete, `X` = execute.
В таблицах **Да** разрешает операцию только в своей области и допустимом состоянии,
**Нет** запрещает. **Дел.** означает «нет по умолчанию; да при явном делегировании».
Все отсутствующие права запрещены. Проверки выполняются сервером, включая API,
списки, поиск, выгрузки, расчёты и ссылки на файлы.

Подтверждение/отмена назначений допустимы только в DRAFT; изменение подтверждённого
назначения возвращает его в PROPOSED. Согласование относится к зафиксированным
`contentRevision` и `reviewRound`. R-04 не утверждает портфель целиком.
Делегирование R-03 задаёт проект, операции, срок, выдавшего полномочие и аудит;
право проверяется при каждом решении и активации. Назначить себе делегирование
нельзя. Совмещение ролей объединяет только явно выданные права и области;
ограничения состояния, актуальности и неизменяемости действуют всегда.

Чтение карточки не расширяет область: R-03 видит свои проекты и минимальные
сведения об их программе/портфеле, R-04 — необходимые для ресурсного решения
поля связанных проектов. Удаление содержимого черновика проверяет зависимости
и не затрагивает историю утверждённых версий. Ручная оценка до завершения хранится
отдельно от baseline с автором и временем по 050; она не меняет факт Task Tracker.
Параметры денежного расчёта доступны только при отдельно выданном `cost.write`,
а его результат — при `cost.read`; роль сама эти права не выдаёт.
Пересчёт по событию выполняется внутренней политикой, не правами внешнего сервиса.
При создании проекта R-02/R-03 начальный приоритет задаётся принятой настройкой
портфеля; изменять его может R-01. Приостановка/завершение не эквивалентны D.

## 3. Чтение, файлы и администрирование

| Роль | Календарь/план-факт R | Деньги R | Вложение C/D | Вложение R | Оповещения R | Настройки U/X | Повтор обмена X | Аудит R |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| R-01 | Да | Да* | Нет | Да | Да | Нет | Нет | Да |
| R-02 | Да | Да* | Да | Да | Да | Нет | Нет | Да |
| R-03 | Да | Да* | Да | Да | Да | Нет | Нет | Да |
| R-04 | Да | Нет | Нет | Да | Да | Нет | Нет | Да |
| R-05 | Да | Нет | Нет | Да | Да | Нет | Нет | Нет |
| R-06 | Нет | Нет | Нет | Нет | Нет | Да | Да | Да |

`Да*` требует дополнительного права `cost.read` в той же области; сама роль
его не выдаёт. Без него денежные поля исключаются из ответа, экспорта и расчётной
детализации. Оповещения доступны только адресату. Аудит R-01–R-04 ограничен своими
бизнес-объектами, R-06 — техническими действиями и метаданными без файлов, секретов
и стоимостного содержимого. Файл наследует область владельца и собственное
ограничение видимости; R-05 не получает все вложения проекта автоматически.

D для вложения — управляемое удаление по UC-09 с DELETE_PENDING → DELETED.
Для версии/сценария C/D вложений разрешены только в DRAFT. Физическое удаление
портфелей, проектов, baseline, решений, факта и аудита запрещено всем ролям;
архивация/отмена — отдельные X-операции с сохранением истории. Завершение,
приостановка и архивирование проекта — R-01 либо R-03 в своей области по UC-01.
Администратор не редактирует бизнес-план, не меняет общие НСИ и не выдаёт себе
бизнес-права; привязки полномочий применяются только по зарегистрированному решению
уполномоченного владельца, с аудитом прежнего и нового значения.

## 4. Сервисные права

| Актор | Разрешено | Запрещено |
| --- | --- | --- |
| S-01 Keycloak | Выдать идентичность/claims по OIDC; Planning System проверяет их | Изменять план от имени сервиса входа |
| S-02 Reference Manager | Отвечать на REST-чтение НСИ | Записывать планы; требовать обязательную Kafka-подписку |
| S-03 Task Tracker | Передать согласованный факт и подтверждение публикации для известных projectId | Создавать мастер-проект в Planning System; менять baseline |
| S-04 Notification Service | Подтвердить доставку по известному ID запроса | Читать произвольные планы; создавать получателей по своему усмотрению |
| S-05 Object Storage | Принять/выдать/удалить объект по операции компонента вложений | Публично раскрывать бакет или выдавать иной objectKey |
| S-06 Reports | Читать согласованную проекцию с разрешённой областью и отдельным правом денежных данных | Изменять план, факт или обходить фильтрацию персональных данных |

Вызовы наружу выполняют отдельные сервисные идентичности компонентов; им выданы
минимальные права на API/топик/бакет. Пользовательские и сервисные токены не
взаимозаменяемы. Объекты из запроса проверяются по принадлежности проекту,
а не только по наличию валидного токена.

## 5. Проверка

Связанные истории: US-PO-02/03, US-PM-04, US-RM-01/02, US-TM-01/02,
US-AD-01/02 из [бэклога](090.features-epics.md).
T-NFR-03 проверяет все разрешённые и запрещённые ячейки, чужую область,
прямой API-вызов, изменение роли и попытку самоназначения; T-FR-09 проверяет
неизменяемость и переходы. Определения тестов — в [095](095.requirements-check.md).
