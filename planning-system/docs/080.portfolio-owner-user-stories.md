# 080 — User Stories: руководитель портфеля

**Этап 2, блок C.** Редакция 1.0 от 24.09.2026. Статус: к ревью команды.

Актор [H-01](030.actors.md), роль [R-01](070.role-matrix.md).
Формат: «Как <актор>, я хочу <функция>, чтобы <ценность>».
Given / When / Then означают «Дано / Когда / Тогда». Все сценарии — спецификации
приёмки, а не результаты выполненных тестов. Общие условия: проверены роль,
область, редакция и состояние объекта. Приоритеты — в [090](090.features-epics.md),
трассировка и тесты — в [095](095.requirements-check.md).

<a id="us-po-01"></a>

## US-PO-01 — Выбрать состав портфеля

Как руководитель портфеля, я хочу управлять программами и приоритетами проектов, чтобы направлять доступные ресурсы на наиболее важные цели.

**Связи:** UC-01 ([060](060.use-cases.md)); R-01; FR-01.

- **AC-1. Given** есть доступный портфель и уникальный код проекта; **When** создаю проект с программой этого портфеля; **Then** проект и первый DRAFT сохраняются вместе, проект появляется в списке.
- **AC-2. Given** код уже занят либо программа принадлежит другому портфелю; **When** сохраняю карточку; **Then** получаю ошибку поля, ни проект, ни черновик частично не создаются.
- **AC-3. Given** существует ACTIVE-версия; **When** меняю приоритет проекта; **Then** приоритет обновляется с аудитом, baseline сохраняется и предлагается пересчёт.

<a id="us-po-02"></a>

## US-PO-02 — Принять решение по версии

Как руководитель портфеля, я хочу утвердить или вернуть проверенный вариант, чтобы зафиксировать выполнимую базовую линию.

**Связи:** UC-05, UC-06 ([060](060.use-cases.md)); R-01; FR-08, FR-09.

- **AC-1. Given** версия ON_REVIEW имеет актуальную проверку и все обязательные ресурсные решения; **When** утверждаю её; **Then** записываются APPROVED, автор, время и неизменяемая baseline, активация ещё не выполнена.
- **AC-2. Given** версия находится на согласовании; **When** возвращаю её с причиной; **Then** она становится DRAFT, причина сохранена, прежний цикл решений не применяется повторно.
- **AC-3. Given** входные данные проверки изменились или остался конфликт; **When** пытаюсь утвердить; **Then** утверждение блокируется с причиной и предложением повторной проверки.

<a id="us-po-03"></a>

## US-PO-03 — Активировать утверждённый план

Как руководитель портфеля, я хочу ввести утверждённую версию в действие и видеть результат публикации, чтобы дать исполнителям актуальные плановые рамки.

**Связи:** UC-07 ([060](060.use-cases.md)); R-01; FR-09, FR-11.

- **AC-1. Given** есть APPROVED и прежняя ACTIVE; **When** активирую новую версию; **Then** новая становится единственной ACTIVE, прежняя SUPERSEDED, создаётся одна Publication.
- **AC-2. Given** Task Tracker не ответил после отправки; **When** открываю статус публикации; **Then** вижу FAILED и неизвестный результат, baseline остаётся целой и SUCCEEDED не заявляется.
- **AC-3. Given** повторно отправляю ту же команду активации; **When** система обрабатывает повтор; **Then** возвращается существующий результат без второй активной версии и публикации.

<a id="us-po-04"></a>

## US-PO-04 — Оценить портфель по данным

Как руководитель портфеля, я хочу просматривать сроки, загрузку и отклонения с датой среза, чтобы принимать решения по сопоставимым данным.

**Связи:** UC-11 ([060](060.use-cases.md)); R-01; FR-15.

- **AC-1. Given** есть план, факт и прогноз выбранной версии; **When** открываю представление портфеля; **Then** вижу версию, дату среза, отклонения и переход к работе-источнику.
- **AC-2. Given** прогноз PARTIAL либо отсутствует cost.read; **When** открываю отчёт; **Then** неполнота обозначена, денежные поля без права не выдаются, пропуск не заменяется нулём.
