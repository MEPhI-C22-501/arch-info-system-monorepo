# 090 — Эпики и план реализации

**Этап 2, блок C.** Редакция 1.0 от 24.09.2026. Статус: к ревью команды.

Основания: [Vision](vision.md), [ТЗ](technical-specification.md),
[UC](060.use-cases.md), [NFR](075.nfr.md). Это предлагаемый бэклог команды,
а не уже заведённые задачи Jira и не утверждённые календарные даты.

План использует этапы проекта: проектирование → планирование разработки →
разработка → тестирование. На проектировании утверждается комплект 010–165;
на планировании разработки эпики дробятся на задачи/оценки и назначаются владельцы;
на разработке поставляются функции, на тестировании проверяются AC и интеграции.
Календарный график ведёт руководитель проекта; ниже указан обязательный выход этапа.

## 2. Этапы и критерии выхода

| Этап | Эпики и результат |
| --- | --- |
| Проектирование | EP-01…08: модель 120, интерфейсы 110/115, контракты 130/140, ADR/архитектура 145–165; открытые зависимости имеют владельцев |
| Планирование разработки | EP-01…08: задачи, оценки, исполнители, seed и тестовые фикстуры; порядок стыковки 160 |
| Разработка | Сначала EP-07 (доступ/аудит), EP-01 → EP-02 → EP-03; затем EP-04, EP-05/06/08 и выпуск Compose/CI. Заглушки помечены |
| Тестирование | Все Must-истории: реальные интеграции, NFR, unit/E2E, security-отчёт, восстановление и minikube; доказательства в 095/165 |

EP-06 дополнен пакетным ETL INT-08 и историей US-AD-04; EP-07 — техническими
поставками TECH-01…06 из 165. EP-08 ведут Planning System + QA + Task Tracker.

Владелец EP-01/02/03 — команда Planning System совместно с PMO и ресурсным
руководителем как предметными согласующими; EP-04 — Planning System + Task Tracker;
EP-05 — Planning System + Infra + назначенный поставщик уведомлений;
EP-06 — Planning System + Reports; EP-07 — Planning System + Infra.
Имена исполнителей не назначены и не выдумываются.

## 3. Риски и ограничения объёма

- D-01: внешний контракт Task Tracker ещё не подтверждён; согласование начинать
  до этапа разработки, иначе этап тестирования не демонстрирует сквозной цикл.
- D-03/D-07: источник календаря, идентичности сотрудника и оценок до завершения
  определяет достоверность расчёта; отсутствие данных даёт PARTIAL.
- D-04/D-05: нужны поставщик внешних оповещений и контракт проекций Reports.
- D-06/D-08: маршрут, делегирование и блокировки утверждения требуют ревью владельца.
- Профиль нагрузки, RPO/RTO и доступность из 075 согласуются до этапа тестирования.

Платежи, зарплата, кадровый учёт, отдельный сервис входа, редактирование задач
в Planning System и файловый обмен задачами — вне объёма по 020/ТЗ.
Нет переноса обязательных вложений, Keycloak, НСИ или оповещений за первую версию.

## 4. Definition of Done истории

Все AC истории проверены, права и область соблюдены, контракт/данные документированы,
есть результаты положительных и отрицательных тестов, review команды завершён.
Измеримые NFR применимого эпика подтверждены протоколом. Для интеграции дополнительно
нужен тест с реальным согласованным сервисом; результат заглушки отражается отдельно.
Трассировка обновляется в [095](095.requirements-check.md); covered в документации
не заменяет готовность к выпуску.
