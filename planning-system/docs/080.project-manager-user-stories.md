# 080 — User Stories: руководитель проекта

**Этап 2, блок C.** Редакция 1.0 от 24.09.2026. Статус: к ревью команды.

Актор [H-03](030.actors.md), роль [R-03](070.role-matrix.md).
Формат: «Как <актор>, я хочу <функция>, чтобы <ценность>».
Given / When / Then означают «Дано / Когда / Тогда». Все сценарии — спецификации
приёмки, а не результаты выполненных тестов. Общие условия: проверены роль,
область, редакция и состояние объекта. Приоритеты — в [090](090.features-epics.md),
трассировка и тесты — в [095](095.requirements-check.md).

<a id="us-pm-01"></a>

## US-PM-01 — Вести собственный проект

Как руководитель проекта, я хочу актуализировать карточку, структуру и оценки проекта, чтобы сохранять согласованный объём планирования.

**Связи:** UC-01, UC-02 ([060](060.use-cases.md)); R-03; FR-01, FR-03, FR-04.

- **AC-1. Given** я закреплён за проектом с DRAFT; **When** изменяю цель и листовые оценки; **Then** сохраняется новая редакция в моей области, потребности родителей пересчитываются без двойного учёта.
- **AC-2. Given** другой пользователь уже изменил редакцию; **When** сохраняю устаревшую копию; **Then** получаю конфликт и предложение перечитать, его изменения не перезаписываются.

<a id="us-pm-02"></a>

## US-PM-02 — Получить факт и объяснимый прогноз

Как руководитель проекта, я хочу видеть задачи, историю и фактические часы с прогнозом до завершения, чтобы вовремя инициировать перепланирование.

**Связи:** UC-08, UC-05 ([060](060.use-cases.md)); R-03; FR-02, FR-10, FR-12.

- **AC-1. Given** согласованный контракт передаёт новую редакцию задачи с абсолютным фактом и отдельной оценкой до завершения; **When** система принимает событие; **Then** проекция обновляется один раз, прогноз содержит planVersionId, dataAsOf и входные редакции.
- **AC-2. Given** пришёл повтор eventId или более старая sourceRevision; **When** система принимает сообщение; **Then** фактические часы не удваиваются и новая проекция не затирается.
- **AC-3. Given** Task Tracker передал остаток −4 как план минус факт, но оценки будущих часов нет; **When** открываю прогноз; **Then** −4 остаётся sourceRemainingHours, remainingHours не подменяется им, результат PARTIAL с причиной.
- **AC-4. Given** полная авторизованная сверка ещё не выполнена и задача отсутствует лишь на одной странице; **When** обновляю факт; **Then** история и часы не удаляются, показывается необходимость сверки.

- **AC-5. Given** есть авторизованный согласованный источник истории и комментариев задачи; **When** открываю историю связанной работы; **Then** вижу статусы, изменения и комментарии с внешними ID, автором и временем, редактирование первичного факта в Planning System недоступно.
- **AC-6. Given** согласована методика из 050, фактическая стоимость 1000, остаток 4 часа по ставке 200 в одной валюте и baselineBudget 1500; **When** пересчитываю прогноз с полными календарными входами; **Then** итоговая стоимость 1800, budgetAdjustment +300, валюта и входные редакции сохранены, результат передаётся отдельным согласованным обновлением без изменения baseline.

<a id="us-pm-03"></a>

## US-PM-03 — Работать с обоснованиями

Как руководитель проекта, я хочу прикреплять, скачивать и удалять разрешённые файлы, чтобы сохранять основания плановых решений.

**Связи:** UC-09 ([060](060.use-cases.md)); R-03; FR-13.

- **AC-1. Given** есть доступный проект, DRAFT-версия или DRAFT-сценарий и допустимый файл; **When** загружаю файл к одному из этих владельцев; **Then** после подтверждения хранилища и контрольной суммы вижу AVAILABLE, автора и время, скачивание возвращает исходные байты.
- **AC-2. Given** файл превышает лимит, запрещённого типа либо владелец-версия APPROVED; **When** загружаю или меняю состав вложений baseline; **Then** операция отклоняется и содержимое baseline не меняется.
- **AC-3. Given** вложение разрешено удалить; **When** удаляю его, а хранилище временно недоступно; **Then** остаётся DELETE_PENDING без скачивания, после успешного повтора становится DELETED.

<a id="us-pm-04"></a>

## US-PM-04 — Перепланировать в границах полномочий

Как руководитель проекта, я хочу подготовить новый вариант и при делегировании принять решение, чтобы устранить отклонение с соблюдением ответственности.

**Связи:** UC-05, UC-06, UC-07 ([060](060.use-cases.md)); R-03; FR-08, FR-09.

- **AC-1. Given** есть отклонение и право подготовки; **When** создаю сценарий; **Then** получаю отдельный DRAFT, активный план и его baseline сохраняются.
- **AC-2. Given** нет действующего делегирования финального решения; **When** вызываю утверждение через API; **Then** получаю отказ даже если сам создал проект.
- **AC-3. Given** делегированы утверждение и активация этого проекта, проверки и согласования завершены; **When** утверждаю и отдельно активирую; **Then** решения аудируются, другое projectId теми же правами не разрешается.
