## Проверки GitHub

Workflow Planning System checks запускается на push/PR при изменении модуля.
Он проверяет синтаксис, документы/трассировку, воспроизводимость генераторов,
PostgreSQL-тесты, чистый Compose, browser E2E, restore и Mermaid.
Публикация образа в GHCR запускается только после успешного verify на main.
Ручной workflow_dispatch с параметром minikube=true добавляет проверку кластера,
Ingress и сохранности PVC; локальное доказательство хранится в artifacts.

Администратор репозитория определяет обязательность check и права GHCR.
Настройки защиты main не меняются самим наличием workflow. Секреты общего
стенда не передаются в GitHub-артефакты; используются только тестовые credentials.

## Внешние зависимости

Пять запросов к Infra, Reference Manager, Task Tracker, QA и Reports подготовлены
в [реестре](docs/integration-agreements.md). После публикации Issues в нём
фиксируются номера и даты. Отправленный запрос не считается согласием второй
стороны. Нужны точная версия/hash, решения по открытым полям, дата и представитель.

Логины участников для назначения задач из [рабочего плана](work-plan.md) и дата
защиты ещё ожидаются. Исполнители/reviewers не назначаются вымышленными именами.
Приёмка общего стенда включает реальные T-INT, image digest, логи/скриншоты,
security/restore и общий сценарий с соседями по 095/160/165.
