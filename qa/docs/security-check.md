# Проверка безопасности QA System

> Требование — технические требования к модулю (проверка по чек-листу: XSS, CSRF, инъекции) и [NFR-06](075.nfr.md#4-безопасность). Образцы — отчёты [Reference Manager](../../reference-manager/documents/security-check.md) и [Reports](../../reports/docs/security-check.md). Задача в техническом бэклоге — TECH-08 в [165](165.deployment-diagram.md#7-технический-бэклог).

QA System проверяет чужие подсистемы, поэтому сама должна проходить ту же проверку. У модуля повышенные риски: он хранит пользовательский текст (кейсы, фактические результаты, комментарии разработчиков из Task Tracker), принимает файлы и журналы автотестов, а исполнитель держит служебный токен с правами записи в тестируемые подсистемы.

**Статус на 2026-10-12:** чек-лист составлен, проверка не проводилась — кода QA System в репозитории ещё нет. Пункты, которые проверяются по документам, проверены и отмечены. Остальные заполняются после реализации по каждой строке: результат, способ, дата, версия образа.

## 1. Чек-лист

| № | Угроза | Мера в проекте | Как проверить | Результат |
| --- | --- | --- | --- | --- |
| S-01 | Хранимый XSS через текст кейса, шага, фактического результата, комментария | Интерфейс выводит пользовательский текст только как текст; HTML-вставки запрещены линтером; Markdown не рендерится | Кейс с названием `<img src=x onerror=alert(1)>` и шагом `<script>`: открыть список, карточку, прогон, дефект | Не проверено |
| S-02 | XSS через комментарий, пришедший из Task Tracker | Комментарии с источником `TRACKER` выводятся так же, как свои — текстом | Комментарий с HTML в «Ошибке» → цикл опроса → карточка дефекта | Не проверено |
| S-03 | XSS через вложение и журнал автотеста | SVG и HTML запрещены (NFR-19), тип проверяется по содержимому; скачивание с `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`; журнал показывается как текст | Загрузить HTML с расширением `.png` → `422`; журнал с `<script>` → отображается текстом | Не проверено |
| S-04 | CSRF | API принимает только `Authorization: Bearer`, cookie-сессий нет; CORS разрешает только адрес интерфейса QA System | Запрос с чужого origin без токена → `401`; preflight с чужого origin → отказ | Не проверено |
| S-05 | SQL-инъекции в фильтрах списков и наборов | Только связанные параметры; фильтр набора хранится как структура JSON с перечнем разрешённых полей и операторов, а не как строка SQL | `q = "x' OR 1=1 --"`, фильтр набора с неизвестным полем → `422` | Не проверено |
| S-06 | Формулы в экспорте (CSV injection) | Значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются в `.csv` и `.xlsx` | Кейс с названием `=HYPERLINK("http://evil")` → экспорт → открыть в Excel | Не проверено |
| S-07 | Вредоносный файл импорта | Предел размера файла импорта 5 МиБ и 5 000 строк; проверка до записи; формулы не вычисляются | `.xlsx` с внешними ссылками и макросами → отчёт с отказом | Не проверено |
| S-08 | Обход прав по ролям и чужим данным | Права проверяются на сервере на каждом запросе ([070](070.role-matrix.md)); чужой назначенный кейс — `403`; результат завершённого прогона — `409` | Матричный тест ролей T-NFR-06 | Не проверено |
| S-09 | Подделка токена | Проверка подписи по JWKS, `iss`, `aud = qa-system`, срока | Токен другого клиента, истёкший, с изменённой подписью → `401` | Не проверено |
| S-10 | Утечка служебного токена исполнителя | Секрет `qa-executor` — только в окружении `qa-worker`; маскирование `Authorization` и секретов в журналах автотестов и приложения; журнал проходит фильтр перед сохранением | Поиск токенов и секретов по журналам автотестов прогона «Smoke» на стенде — фактически, а не по требованию | Не проверено |
| S-11 | Секреты в репозитории | `.env.example` без значений; сканер секретов в workflow `qa-checks` | Сканер на всей истории ветки; тестовый секрет в pull request → workflow красный | Выполнено по документам: в `qa/` на 2026-10-12 нет файлов конфигурации с секретами; сканер появится с TECH-03 |
| S-12 | Избыточные права служебных записей | `qa-executor` — минимальные права в каждой подсистеме; `qa-ci` — только запуск наборов и чтение своих прогонов; `qa-tracker-reader` — только чтение | Попытка `qa-ci` изменить кейс → `403`; попытка `qa-tracker-reader` вызвать `POST /bugs` → `403` | Не проверено |
| S-13 | Доступ к чужому вложению | Скачивание через API с проверкой прав на владельца; бакет не публичный; подписанная ссылка живёт 5 минут | Чужой `attachmentId` без прав → `404`; ссылка через 6 минут → отказ | Не проверено |
| S-14 | Персональные данные в событиях и выгрузках | События [140](140.event-schema.md) несут идентификаторы, не ФИО и не текст дефекта; `/reports/*` — только под ролью R-07 | Проверка схем событий | Выполнено по документам 2026-10-12: в схемах нет ФИО, почты и текстов |
