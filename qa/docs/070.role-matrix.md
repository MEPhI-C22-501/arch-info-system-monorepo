# 070 — RBAC (Role-Based Access Control)

> Формат — см. [состав документов](documents-composition.md), документ 070.
> Источник — [vision, разделы 3 и 5.5](vision.md#3-пользователи). Акторы — [030](030.actors.md), use cases — [060](060.use-cases.md).

Матрица — проектное предложение команды QA. Имена ролей в Keycloak заявляются в Infra (Q-06 в [020](020.system-context.md#5-открытые-договорённости)).

## 1. Роли

| Роль | Имя в Keycloak | Актор | Область |
| --- | --- | --- | --- |
| R-01 | `qa-viewer` | H-04 разработчик, H-05 руководитель проекта | Чтение всех данных модуля, комментарии к дефектам |
| R-02 | `qa-tester` | H-02 тестировщик | Кейсы, выполнение прогонов, дефекты |
| R-03 | `qa-automation` | H-03 автоматизатор | Кейсы и связь с автотестами, автопрогоны |
| R-04 | `qa-lead` | H-01 QA-лид | Всё, что R-02, плюс планы, наборы, назначение, управление прогонами |
| R-05 | `qa-admin` | H-06 администратор | Шаблоны, классификаторы, окружения, расписания, состояние интеграций |
| R-06 | `qa-ci` | S-06 GitHub Actions (служебный клиент) | Запуск прогона набора и чтение его итога |
| R-07 | `qa-reports-reader` | S-05 Reports (служебный клиент) | Чтение `/api/v1/reports/*` |

Роли — клиентские роли клиента `qa-system` в realm `arch-info-system`. Исполнитель автотестов — внутренний процесс: в API QA System он не ходит, а наружу обращается под служебной записью `qa-executor` с минимальными правами в тестируемых подсистемах (FR-SEC-02).

Обозначения: **C** create, **R** read, **U** update, **D** delete, **X** execute. «Да» разрешает операцию в допустимом состоянии объекта, «—» запрещает. Всё, что не перечислено, запрещено. Права проверяет сервер на каждом запросе (FR-SEC-01).
