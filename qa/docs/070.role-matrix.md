Матрица — проектное предложение команды QA. Имена ролей в Keycloak заявляются в Infra (Q-06 в [020](020.system-context.md#5-открытые-договорённости)).

## 1. Роли

| Роль | Имя в Keycloak | Актор | Область |
| --- | --- | --- | --- |
| R-01 | `qa-viewer` | H-04 разработчик, H-05 руководитель проекта | Чтение всех данных модуля, комментарии к дефектам |
| R-02 | `qa-tester` | H-02 тестировщик | Кейсы, выполнение прогонов, дефекты |
| R-03 | `qa-automation` | H-03 автоматизатор | Кейсы и связь с автотестами, автопрогоны |
| R-04 | `qa-lead` | H-01 QA-лид | Всё, что R-02, плюс планы, наборы, назначение, управление прогонами |
| R-05 | `qa-admin` | H-06 администратор | Шаблоны, классификаторы, окружения, расписания, состояние интеграций |
| R-06 | `qa-ci` | S-06 сервис пайплайна (служебный клиент) | Запуск наборов «Smoke» и «Приёмка стенда» по имени и чтение итога и вердикта |
| R-07 | `qa-reports-reader` | S-05 Reports (служебный клиент) | Чтение `/api/v1/reports/*` |

Роли — клиентские роли клиента `qa-system` в realm `arch-info-system`. Исполнитель автотестов — внутренний процесс: в API QA System он не ходит, а наружу обращается под служебной записью `qa-executor` с минимальными правами в тестируемых подсистемах (FR-SEC-02).

Обозначения: **C** create, **R** read, **U** update, **D** delete, **X** execute. «Да» разрешает операцию в допустимом состоянии объекта, «—» запрещает. Всё, что не перечислено, запрещено. Права проверяет сервер на каждом запросе (FR-SEC-01).

## 5а. Справочники значений и статусы: кто что меняет

Владельцы справочников — [050, раздел 1а](050.entities.md#1а-справочники-значений-и-их-владельцы). Здесь — кто и где меняет каждое значение, чтобы один статус не правили в трёх системах.

| Что меняется | Где | Кто | Что не может |
| --- | --- | --- | --- |
| Набор значений серьёзности (коды) | Код QA System | Никто без новой версии контракта событий | Администратор не добавляет и не удаляет коды |
| Названия и порядок значений серьёзности, приоритета кейса, типов кейса; окружения | QA System, «Администрирование» | R-05 | Удалить значение нельзя. Отключить можно только неиспользуемое: значение текущей версии неархивного кейса, активного шаблона или незакрытого дефекта, окружение незавершённого прогона или включённого расписания — `409 VALUE_IN_USE`. Код окружения не меняется |
| Серьёзность конкретного дефекта или кейса | QA System | R-02, R-03, R-04 | Task Tracker не меняет серьёзность: она приходит к нему один раз при создании «Ошибки» |
| Статусы тестирования дефекта `NEW`, `READY_FOR_TEST`, `CLOSED`, `REOPENED` | QA System | R-02, R-04; система по итогу перепроверки | Task Tracker и Reference Manager |
| Статусы разработки `OPEN`, `IN_PROGRESS`, `FIXED` | Task Tracker, в QA System приходят опросом | Разработчик и тимлид в Task Tracker; R-04 в QA System только при выключенном опросе | R-02, R-05 |
| Набор статусов задачи в Task Tracker | Task Tracker | Администратор Task Tracker | QA System их не создаёт |
| Таблица маппинга статусов «Ошибки» | QA System | R-05 | Сопоставить статус Task Tracker со статусом тестирования |
| Приоритет исправления «Ошибки» | Task Tracker | Тимлид и разработчик в Task Tracker | QA System показывает только для чтения |

Reference Manager ни одно из этих значений не ведёт и не меняет (его решение от 2026-10-02).

## 5б. Доступ к чужим прогонам и данным

| Объект | Правило |
| --- | --- |
| Кейс, план, набор, прогон, дефект | Видны всем ролям R-01…R-05: данные тестирования проекта общие |
| Результат кейса, назначенного другому тестировщику | R-02 видит, но не меняет; R-04 меняет |
| Прогон, запущенный пайплайном | R-06 видит только свои прогоны; люди видят все |
| Журнал автотеста и вложения | Права наследуются от владельца: кто видит результат, тот скачивает журнал |
| `/api/v1/reports/*` | Только R-07; люди этот путь не используют |

## 6. Проверка

Матрицу проверяет сценарий T-NFR-06 из [095](095.requirements-check.md): каждая разрешённая и запрещённая ячейка, запрос без токена, токен с чужой ролью, попытка изменить результат завершённого прогона и чужой назначенный кейс, попытка R-05 сопоставить статус Task Tracker со статусом тестирования. Результаты проверки — в [отчёте о безопасности](security-check.md).
