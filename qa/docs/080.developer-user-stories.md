# 080 — User Stories: разработчик

> Формат — см. [состав документов](documents-composition.md), документ 080.
> Источник — [vision, разделы 2 и 4.4](vision.md#44-жизненный-цикл-дефекта). Актор H-04, роль R-01 `qa-viewer` из [070](070.role-matrix.md), use cases — [060](060.use-cases.md).

**US-DV-01.** As a разработчик, I want получать дефект как задачу «Ошибка» в Task Tracker so that работать с ним в привычном бэклоге.
- GWT-1: Given в QA System создан дефект, When синхронизация завершена, Then в Task Tracker есть «Ошибка» с заголовком, шагами воспроизведения, ожидаемым и фактическим результатом, окружением и ссылкой на прогон.
- GWT-2: Given запрос создания повторён из-за тайм-аута, When Task Tracker получает его второй раз, Then второй «Ошибки» нет: возвращена ссылка на существующую.
- GWT-3: Given Task Tracker недоступен, When дефект создан, Then он сохранён в QA System с состоянием синхронизации `PENDING` и будет отправлен позже.

*(→ UC-18; FR-DEF-06, NFR-11)*

**US-DV-02.** As a разработчик, I want открыть дефект в QA System по ссылке из «Ошибки» so that увидеть кейс, шаг, журнал автотеста и историю провалов.
- GWT-1: Given у меня роль `qa-viewer`, When перехожу по ссылке, Then вижу дефект, версию кейса, упавший шаг, журнал и все прогоны, где дефект проявился.
- GWT-2: Given я хочу уточнить условия воспроизведения, When оставляю комментарий, Then он виден тестировщику с моим именем и временем.
- GWT-3: Given у меня только роль `qa-viewer`, When пытаюсь изменить статус дефекта вызовом API, Then получаю `403`.

*(→ UC-19; FR-DEF-04, FR-SEC-01)*
