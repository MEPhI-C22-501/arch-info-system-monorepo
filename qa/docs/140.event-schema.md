# 140 — Event Schema

> Формат — см. [состав документов](documents-composition.md), документ 140.
> Каталог событий — [135](135.event-catalog.md). Формат — JSON, схемы — JSON Schema 2020-12.

## 1. Общая оболочка

Все события имеют одну оболочку; различается только `payload`. Состав служебных полей совпадает с требованиями Infra (`event_id` для дедупликации) и с оболочкой событий [Planning System](../../planning-system/docs/architecture.md).

```json
{
  "$id": "QaSystemEvent.v1",
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["eventId", "eventType", "schemaVersion", "occurredAt", "producer", "correlationId", "payload"],
  "properties": {
    "eventId": { "type": "string", "format": "uuid" },
    "eventType": { "type": "string", "enum": ["TestRunStarted", "TestResultRecorded", "TestRunCompleted", "DefectChanged"] },
    "schemaVersion": { "type": "integer", "const": 1 },
    "occurredAt": { "type": "string", "format": "date-time" },
    "producer": { "type": "string", "const": "qa-system" },
    "correlationId": { "type": "string" },
    "payload": { "type": "object" }
  },
  "additionalProperties": false
}
```

| Поле | Тип | Обяз. | Пример | Семантика |
| --- | --- | --- | --- | --- |
| `eventId` | string, UUID | да | `3f0e6c1a-…` | Уникален для события; потребитель устраняет дубли по нему |
| `eventType` | string | да | `TestRunCompleted` | Вид события |
| `schemaVersion` | integer | да | `1` | Мажорная версия схемы `payload` |
| `occurredAt` | string, RFC 3339 UTC | да | `2026-10-05T17:40:12Z` | Момент изменения в QA System, а не публикации |
| `producer` | string | да | `qa-system` | Издатель |
| `correlationId` | string | да | `5f1c2a…` | Идентификатор запроса, вызвавшего изменение |
| `payload` | object | да | — | Данные события |

## 2. `TestRunStarted`

```json
{
  "$id": "TestRunStarted.v1",
  "type": "object",
  "required": ["runId", "runKey", "environment", "trigger", "caseCount", "startedAt"],
  "properties": {
    "runId": { "type": "string", "format": "uuid" },
    "runKey": { "type": "string" },
    "planId": { "type": ["string", "null"], "format": "uuid" },
    "suiteId": { "type": ["string", "null"], "format": "uuid" },
    "parentRunId": { "type": ["string", "null"], "format": "uuid" },
    "environment": { "type": "string" },
    "trigger": { "type": "string", "enum": ["MANUAL", "SCHEDULE", "CI"] },
    "caseCount": { "type": "integer", "minimum": 1 },
    "trackerIterationId": { "type": ["string", "null"] },
    "planningMilestoneId": { "type": ["string", "null"] },
    "startedAt": { "type": "string", "format": "date-time" }
  },
  "additionalProperties": false
}
```

| Поле | Тип | Обяз. | Пример | Семантика |
| --- | --- | --- | --- | --- |
| `runId`, `runKey` | UUID, string | да | `7d2e…`, `RUN-87` | Прогон |
| `planId`, `suiteId` | UUID или null | нет | `c41a…` | Источник прогона: задано ровно одно |
| `parentRunId` | UUID или null | нет | `null` | Исходный прогон, если этот — повторный |
| `environment` | string | да | `dev` | Код окружения |
| `trigger` | enum | да | `CI` | Источник запуска |
| `caseCount` | integer | да | `25` | Число кейсов в прогоне |
| `trackerIterationId`, `planningMilestoneId` | string или null | нет | `null` | Привязка плана; для набора — null |
| `startedAt` | date-time | да | `2026-10-05T17:35:00Z` | Время запуска |

## 3. `TestResultRecorded`

```json
{
  "$id": "TestResultRecorded.v1",
  "type": "object",
  "required": ["runId", "resultId", "testCaseId", "testCaseKey", "caseVersion", "status", "automated"],
  "properties": {
    "runId": { "type": "string", "format": "uuid" },
    "resultId": { "type": "string", "format": "uuid" },
    "testCaseId": { "type": "string", "format": "uuid" },
    "testCaseKey": { "type": "string" },
    "caseVersion": { "type": "integer", "minimum": 1 },
    "module": { "type": "string" },
    "status": { "type": "string", "enum": ["PASSED", "FAILED", "BLOCKED", "SKIPPED", "NOT_RUN"] },
    "previousStatus": { "type": ["string", "null"] },
    "automated": { "type": "boolean" },
    "executedBy": { "type": ["string", "null"] },
    "durationMs": { "type": ["integer", "null"], "minimum": 0 },
    "defectId": { "type": ["string", "null"], "format": "uuid" }
  },
  "additionalProperties": false
}
```

| Поле | Тип | Обяз. | Пример | Семантика |
| --- | --- | --- | --- | --- |
| `runId`, `resultId` | UUID | да | — | Прогон и результат в нём |
| `testCaseId`, `testCaseKey` | UUID, string | да | `TC-RM-03` | Кейс |

| `durationMs` | integer или null | нет | `412` | Длительность выполнения кейса |
| `defectId` | UUID или null | нет | `e9c0…` | Дефект, созданный или связанный по провалу |

## 5. `DefectChanged`

```json
{
  "$id": "DefectChanged.v1",
  "type": "object",
  "required": ["defectId", "defectKey", "change", "status", "severity", "priority", "reopenCount"],
  "properties": {
    "defectId": { "type": "string", "format": "uuid" },
    "defectKey": { "type": "string" },
    "change": { "type": "string", "enum": ["CREATED", "STATUS_CHANGED", "FIELDS_CHANGED", "TRACKER_LINKED"] },
    "origin": { "type": "string", "enum": ["AUTO", "MANUAL"] },
    "status": { "type": "string", "enum": ["NEW", "OPEN", "IN_PROGRESS", "FIXED", "READY_FOR_TEST", "CLOSED", "REOPENED"] },
    "previousStatus": { "type": ["string", "null"] },
    "severity": { "type": "string", "enum": ["BLOCKER", "CRITICAL", "MAJOR", "MINOR", "TRIVIAL"] },
    "priority": { "type": "string" },
    "reopenCount": { "type": "integer", "minimum": 0 },
    "trackerWorkItemId": { "type": ["string", "null"] },
    "testCaseId": { "type": ["string", "null"], "format": "uuid" },
    "runId": { "type": ["string", "null"], "format": "uuid" },
    "planId": { "type": ["string", "null"], "format": "uuid" },
    "trackerIterationId": { "type": ["string", "null"] },
    "epicRef": { "type": ["string", "null"] },
    "environment": { "type": ["string", "null"] }
  },
  "additionalProperties": false
}
```

| Поле | Тип | Обяз. | Пример | Семантика |
| --- | --- | --- | --- | --- |
| `defectId`, `defectKey` | UUID, string | да | `DEF-45` | Дефект |
| `change` | enum | да | `STATUS_CHANGED` | Что произошло |
| `origin` | enum | нет | `AUTO` | Создан системой или вручную |
| `status`, `previousStatus` | enum, string или null | да / нет | `REOPENED`, `READY_FOR_TEST` | Текущий и прежний статус; переход в `REOPENED` — признак повторного открытия |
| `severity`, `priority` | enum, string | да | `MAJOR`, `HIGH` | Серьёзность ведёт QA System |
| `reopenCount` | integer | да | `1` | Сколько раз дефект переоткрывался |
| `trackerWorkItemId` | string или null | нет | `b3b9b1b0-…` | Задача «Ошибка» в Task Tracker; null до синхронизации |
| `testCaseId`, `runId`, `planId` | UUID или null | нет | — | Связи; `runId` — прогон, вызвавший изменение |
| `trackerIterationId`, `epicRef`, `environment` | string или null | нет | — | Разрезы отчётов R-05, R-08, R-09 |

Событие несёт полное текущее состояние QA-полей дефекта, поэтому потребителю достаточно последнего события по `defectId`.

## 6. Партиционирование

| Топик | Ключ | Обоснование |
| --- | --- | --- |
| `dev.qa.test-run.v1` | `runId` | Все события одного прогона идут в одну партицию: `TestRunStarted` раньше результатов, `TestRunCompleted` — последним |
| `dev.qa.defect.v1` | `defectId` | Сохраняется порядок изменений статуса одного дефекта, без чего нельзя считать переоткрытия |

## 7. Версионирование и совместимость

- Версия — в суффиксе топика (`.v1`), в `$id` схемы и в `schemaVersion`.
- **Обратная совместимость (backward):** в пределах `v1` добавляются только необязательные поля и новые значения `change`. Потребитель на новой схеме читает старые события.
- **Прямая совместимость (forward):** издатель не удаляет и не переименовывает поля, не меняет их тип. `additionalProperties: false` — правило для издателя; потребителю рекомендуется игнорировать неизвестные поля, чтобы пережить добавление.
- Удаление, переименование поля или смена смысла статуса — новая мажорная версия: топик `.v2`, параллельная публикация в оба топика на время перехода потребителя.
- Изменение схемы согласуется с Reports до выпуска.
