# 090 — Epics / Features

> Формат — см. [состав документов](documents-composition.md), документ 090.
> Источник — [vision, разделы 5, 7 и 9](vision.md#5-функциональные-требования). Истории — файлы 080: [тестировщик](080.tester-user-stories.md), [QA-лид](080.qa-lead-user-stories.md), [автоматизатор](080.automation-engineer-user-stories.md), [разработчик](080.developer-user-stories.md), [руководитель проекта](080.project-manager-user-stories.md), [администратор](080.admin-user-stories.md), [внешние сервисы](080.external-services-user-stories.md).

Приоритет по MoSCoW. Веха задаёт порядок разработки: **M4** — первая работающая версия, которой можно проверить стенд; **M5** — интеграции с соседями, остальной объём и приёмка.

## 1. Вехи

| Веха | Что должно работать | Вехи интеграций из [160](160.integration-plan.md) |
| --- | --- | --- |
| M4 | Вход через Keycloak; тест-кейсы с версиями; планы и наборы; ручной прогон; исполнитель и автопрогон; дефекты с жизненным циклом и автосозданием; автотест TC-RM-01 | И-M1, И-M2 |
| M5 | Создание «Ошибки» в Task Tracker; события и API для Reports; вложения в S3; импорт и экспорт; шаблоны и администрирование; запуск из CI; справочные данные соседей; остальные автотесты стартового набора по мере появления API | И-M3, И-M4, И-M5 |

## 3. Вне первой версии

| Возможность | Почему отложена |
| --- | --- |
| Проверки через браузер и нагрузочное тестирование | Исключены vision, раздел 1.4 |
| Настраиваемые пользовательские поля кейса и дефекта | Упомянуты в роли администратора, но требования FR на них нет; набор полей фиксирован |
| Двусторонняя синхронизация комментариев с Task Tracker | У Task Tracker нет контракта — Q-01 |
| Интеграция с TFS / Azure DevOps | Роль TFS выполняет Task Tracker — Q-09 |
| Параллельное исполнение кейсов внутри одного задания | Не нужно для набора из 25 кейсов и NFR-01 |
