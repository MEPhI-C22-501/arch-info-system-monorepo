# 010 — Глоссарий (Ubiquitous Language)

> Формат — см. [состав документов](documents-composition.md), документ 010.
> Источник — [vision, раздел 1.5](vision.md#15-термины). Сверено с глоссариями
> [Task Tracker](../../task-tracker/docs/block-a-context-and-scope/010.glossary.md),
> [Planning System](../../planning-system/docs/010.glossary.md) и
> [Reference Manager](../../reference-manager/documents/010.glossary.md).

Общепрограммные термины («пользователь», «роль», «CRUD») не включены. В скобках после термина — имя, которым он называется в API, событиях и модели данных.

## 1. Термины QA System

| Термин | Определение | Контекст / модуль | Синонимы |
| --- | --- | --- | --- |
| Тест-кейс (`TestCase`) | Описание проверки: предусловия, шаги, ожидаемый результат. Постоянный актив: копируется, версионируется и архивируется, но не удаляется после участия в прогоне | Тест-кейсы | Кейс, test case |
| Ключ кейса | Читаемый неизменяемый идентификатор вида `TC-RM-03`: префикс модуля и порядковый номер | Тест-кейсы | ID кейса |
| Шаг (`TestStep`) | Отдельное действие кейса со своим ожидаемым результатом. Провал фиксируется с точностью до шага | Тест-кейсы | Step |
| Версия кейса (`TestCaseVersion`) | Неизменяемый снимок полей и шагов кейса, созданный при сохранении. Прогон ссылается на конкретную версию | Тест-кейсы | Ревизия кейса |
| Шаблон (`TestCaseTemplate`) | Заготовка кейса с предзаполненными полями и шагами, например «Проверка CRUD справочника» | Тест-кейсы, администрирование | Template |
| Тип кейса | Классификатор назначения проверки: функциональный, регрессионный, smoke, интеграционный, негативный | Тест-кейсы | — |
| Автоматизированный кейс | Кейс с признаком автоматизации и ключом автотеста; его результат записывает исполнитель | Тест-кейсы, исполнитель | Авто-кейс |
| Автотест | Исполняемый сценарий в каталоге `qa/autotests`, связанный с кейсом по ключу | Исполнитель | Autotest |
| Ключ автотеста | Строка, по которой исполнитель находит автотест кейса, например `rm/test_health.py::test_readyz` | Тест-кейсы, исполнитель | Autotest key |
| Несвязанный ключ | Ключ автотеста, указанный в кейсе, которого нет среди автотестов зафиксированного коммита | Исполнитель | — |
| Набор (`TestSuite`) | Сохранённая выборка кейсов: по фильтру или вручную, например «Smoke Reference Manager» | Планы и наборы | Suite, сьют |
| Тест-план (`TestPlan`) | Перечень кейсов, которые нужно пройти к итерации, релизу, проекту или модулю, с ответственным и сроками | Планы и наборы | План |
| Прогон (`TestRun`) | Одно выполнение плана или набора на выбранном окружении. Хранит результат каждого кейса в версии на момент создания | Прогоны | Run, тест-ран |
| Заморозка версий | Фиксация в прогоне текущих версий кейсов; последующая правка кейса не меняет прогон | Прогоны | Snapshot |
| Результат (`RunResult`) | Статус кейса в прогоне: «Пройден», «Провален», «Заблокирован», «Не выполнен», «Пропущен» | Прогоны | Result |
| Результат шага (`StepResult`) | Статус и фактический результат отдельного шага в прогоне | Прогоны | — |
| Фактический результат | То, что система сделала на самом деле. Принадлежит результату в прогоне, а не кейсу | Прогоны, дефекты | Actual |
| Повторный прогон | Новый прогон, созданный из завершённого только по кейсам «Провален» и «Заблокирован» | Прогоны | Rerun |
| Окружение (`Environment`) | Именованный стенд с адресами тестируемых подсистем, на котором выполняется прогон | Прогоны, администрирование | Стенд |
| Исполнитель автотестов | Фоновый процесс QA System, который берёт задания из очереди, запускает автотесты и записывает результаты | Исполнитель | Executor, runner |
| Задание на запуск (`ExecutionJob`) | Запись очереди: какой прогон исполнить, с каким тайм-аутом и на каком окружении | Исполнитель | Job |
| Журнал автотеста | Текстовый вывод автотеста, прикладываемый к результату как вложение | Исполнитель | Лог |
| Дефект (`Defect`) | Зафиксированное расхождение фактического результата с ожидаемым. Связан с кейсом, шагом и прогоном | Дефекты | Баг |
| Автодефект | Дефект, созданный системой при провале кейса или шага без участия тестировщика | Дефекты | — |
| Серьёзность (`severity`) | Влияние дефекта на систему: Blocker, Critical, Major, Minor, Trivial. Ведёт QA System | Дефекты, тест-кейсы | Severity |
| Приоритет (`priority`) | Очерёдность исправления. Не равен серьёзности | Дефекты, тест-кейсы | Priority |
| Перепроверка | Повторное выполнение кейса после исправления; по её итогу дефект закрывается или открывается заново | Дефекты | Retest |
| Повторное открытие | Переход дефекта в «Reopened» из «Ready for Test» или «Closed». Основа показателя reopened rate | Дефекты, отчётность | Reopen |
| Синхронизация дефекта | Создание задачи вида «Ошибка» в Task Tracker и обмен статусами и комментариями с ней | Интеграции | — |
| Внешняя ссылка | Идентификатор чужого объекта (итерация, веха, эпик, сотрудник), хранимый без копии данных владельца | Интеграции | External ref |
| Вложение (`Attachment`) | Файл в объектном хранилище, прикреплённый к кейсу, шагу, результату или дефекту | Вложения | — |
| Сводка | Счётчики результатов плана или прогона по статусам. Межмодульные показатели считает Reports | Прогоны, планы | Summary |

## 2. Смежные термины других модулей

| Термин у нас | Термин соседа | Модуль-владелец | Соответствие |
| --- | --- | --- | --- |
| Дефект | Ошибка (рабочий элемент типа «Ошибка») | [Task Tracker](../../task-tracker/docs/block-a-context-and-scope/010.glossary.md) | Каждому дефекту соответствует не более одной «Ошибки»; мастер QA-полей — QA System |
| Идентификатор дефекта `DEF-n` | Внешний идентификатор дефекта | Task Tracker | Передаётся как `externalDefectId` с `externalSource = qa-system` |
| QA System | Сервис тестирования | Task Tracker | Одна и та же система |
| QA System | Система управления тестированием | [Reports](../../reports/docs/vision.md) | Одна и та же система |
| Итерация (внешняя ссылка) | Итерация | Task Tracker | QA System хранит только идентификатор |
| Веха, эпик, фича, проект (внешние ссылки) | Веха, эпик, фича, проект | [Planning System](../../planning-system/docs/010.glossary.md) | QA System хранит только идентификаторы |
| Сотрудник, подразделение (внешние ссылки) | `employees`, `org_units` | [Reference Manager](../../reference-manager/documents/010.glossary.md) | Читаются по REST с кэшем; имя записи вида `employees/1024` |
| Pass rate, reopened rate, defect density | Те же | Reports | Считает Reports по событиям и данным QA System |

Согласование с соседями: строки про «Ошибку» и внешний идентификатор совпадают с опубликованным контрактом Task Tracker; остальные строки отражают документы соседей на 2026-10-05 и подтверждаются по реестру договорённостей в [020, раздел 5](020.system-context.md#5-открытые-договорённости).
