# 075 — NFR (Non-Functional Requirements)

> Формат — см. [состав документов](documents-composition.md), документ 075.
> Источник — [vision, раздел 6](vision.md#6-нефункциональные-требования). Решения — [145 ADR](145.architecture-decisions.md), сценарии проверки — [095](095.requirements-check.md).

NFR-01…NFR-08 взяты из vision с теми же номерами. NFR-09…NFR-14 добавлены командой QA, чтобы закрыть категории из состава документов; их пороги — предложение до первых замеров на стенде.

| ID | Категория | Требование | Метрика и порог | Проверка | ADR |
| --- | --- | --- | --- | --- | --- |
| NFR-01 | Производительность | Стартовый набор проходит быстро | 25 кейсов раздела 7 vision — не дольше 5 минут на стенде | T-NFR-01: замер длительности прогона набора | ADR-004, ADR-005 |
| NFR-02 | Надёжность / изоляция | Автотесты независимы друг от друга | Данные создаются с уникальным префиксом; набор проходит в любом порядке; 0 кейсов, упавших из-за соседнего | T-NFR-02: запуск в случайном порядке и запуск одного кейса отдельно | ADR-005 |
| NFR-03 | Надёжность / устойчивость | Недоступность подсистемы не подвешивает прогон | Результат «Провален» или «Заблокирован» с причиной не позже тайм-аута задания; 0 прогонов в статусе «Выполняется» дольше тайм-аута плюс 1 минута | T-NFR-03: остановка подсистемы во время прогона | ADR-004, ADR-010 |
| NFR-04 | Надёжность / идемпотентность | Повторная доставка входящего события не меняет дефект второй раз | 0 повторных записей истории при повторе события с тем же идентификатором | T-NFR-04: двойная доставка события | ADR-007, ADR-008 |
| NFR-05 | Целостность данных | История неизменна | 100 % попыток изменить результат завершённого прогона, версию кейса или запись истории отклоняются; правка кейса не меняет сохранённые результаты | T-NFR-05: правка кейса после прогона, прямой вызов API | ADR-003 |
| NFR-06 | Безопасность | Секреты не попадают в репозиторий и журналы; права проверяет сервер | 0 секретов в репозитории и в выборке журналов автотестов; 100 % защищённых операций отклоняют запрос без права | T-NFR-06: поиск секретов, матричный тест ролей из [070](070.role-matrix.md) | ADR-011 |
| NFR-07 | Сопровождаемость / воспроизводимость | Прогон можно повторить на том же коде | 100 % автопрогонов хранят commit SHA автотестов и версии подсистем | T-NFR-07: проверка полей прогона | ADR-005 |
| NFR-08 | Развёртывание | Подсистема и исполнитель разворачиваются средствами Infra | `docker compose up` поднимает API, исполнитель и БД; `/livez` и `/readyz` отвечают; при недоступной БД `/readyz` возвращает 503 | T-NFR-08: запуск на чистом окружении | ADR-002 |
| NFR-09 | Производительность | Интерфейс и API отвечают без заметной задержки | 95 % запросов списка до 50 записей — не дольше 500 мс; сохранение результата кейса — не дольше 300 мс; на объёме NFR-10 | T-NFR-09: замер на наполненной БД | ADR-002 |
| NFR-10 | Масштабируемость | Система выдерживает учебный объём и растёт без переделки | Ориентир: 5 000 кейсов, 50 000 версий, 2 000 прогонов, 200 000 результатов, 50 пользователей; число исполнителей увеличивается без изменения кода | T-NFR-10: наполнение генератором, запуск двух исполнителей | ADR-004 |
| NFR-11 | Надёжность / независимость от соседей | Недоступность Task Tracker, Kafka или источников справочных данных не останавливает тестирование | Создание дефекта и запись результата успешны при недоступных Task Tracker и Kafka; отложенные сообщения доставляются после восстановления, потерь 0 | T-NFR-11: отключение Task Tracker и Kafka, затем восстановление | ADR-007, ADR-010 |
| NFR-12 | Наблюдаемость | Работу можно диагностировать по журналам | 100 % ответов несут идентификатор запроса; журнал исходящих вызовов содержит результат, длительность и идентификатор корреляции; состояние очереди и отложенных сообщений видно администратору | T-NFR-12: анализ журналов успешных и ошибочных вызовов | ADR-007 |
| NFR-13 | Сопровождаемость | Контракт и переходы статусов защищены тестами | OpenAPI — источник истины, расхождение реализации со спецификацией ломает сборку; 100 % переходов из [050](050.entities.md) покрыты тестами | T-NFR-13: контрактные тесты и тесты автоматов состояний в CI | ADR-001 |
| NFR-14 | Совместимость | Файлы экспорта читаются обратно и открываются в редакторах | Неизменённый экспорт импортируется с результатом «0 создано, 0 обновлено»; файл открывается в Microsoft Excel и LibreOffice | T-NFR-14: экспорт, импорт и сравнение | — |
