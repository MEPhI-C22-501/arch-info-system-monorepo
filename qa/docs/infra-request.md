## 1. Объектное хранилище

| Параметр | Значение |
| --- | --- |
| Бакет | `arch-dev-qa` |
| Доступ | Только сервисная учётная запись QA System; публичный доступ запрещён; межкомандного чтения не требуется |
| Ключи объектов | `<вид владельца>/<идентификатор>/<uuid>`: `case/…`, `step/…`, `result/…`, `defect/…`, `autotest-log/…` |
| Квота | 20 ГБ ([NFR-10](075.nfr.md)) |
| Удаление объектов | Нужно: логически удалённые вложения удаляются через 30 суток, журналы автотестов — через 90 суток ([NFR-18](075.nfr.md)) |
| Незавершённые multipart-загрузки | Очищать через 1 сутки |
| Размер объекта | До 10 МиБ ([NFR-19](075.nfr.md)) |
| Резервное копирование | По регламенту Infra; требование QA — RPO ≤ 24 часов ([NFR-17](075.nfr.md)) |

## 2. Kafka

| Параметр | `dev.qa.test-run.v1` | `dev.qa.defect.v1` |
| --- | --- | --- |
| Владелец | Команда QA | Команда QA |
| Издатели | `qa-system` | `qa-system` |
| Потребители и группа | Reports, `reports-qa-ingest` | Reports, `reports-qa-ingest` |
| События и схема | `TestRunStarted`, `TestResultRecorded`, `TestRunCompleted` v1 — [140](140.event-schema.md) | `DefectChanged` v1 — [140](140.event-schema.md) |
| Ключ партиционирования | `runId` | `defectId` |
| Число partitions | 3 | 3 |
| Срок хранения | 7 суток | 7 суток |
| Предел сообщения | 256 КБ | 256 КБ |
| Ожидаемый объём | До 2 000 сообщений в сутки (25–100 результатов на прогон, до 20 прогонов в сутки) | До 200 сообщений в сутки |
| Политика повторов | Издатель повторяет из таблицы исходящих с нарастающей задержкой от 5 секунд до 10 минут | То же |
| Отдельный топик ошибок | Не нужен: неотправленное остаётся в таблице исходящих QA System | Не нужен |

Подписка QA System на топики других подсистем сейчас не нужна. Когда Task Tracker опубликует `task-tracker.events.v1` (их DEC-TT-02), будет подана отдельная заявка на группу `qa-tracker-ingest`.

## 3. Keycloak, realm `arch-info-system`

| Клиент | Вид | Назначение | Роли |
| --- | --- | --- | --- |
| `qa-system` | Публичный клиент SPA с PKCE и аудитория API | Вход пользователей, проверка токенов | Клиентские роли `qa-viewer`, `qa-tester`, `qa-automation`, `qa-lead`, `qa-admin`, `qa-ci`, `qa-reports-reader` ([070](070.role-matrix.md)) |
| `qa-executor` | Конфиденциальный, client credentials | Служебная запись исполнителя автотестов для вызова тестируемых подсистем | Минимальные роли чтения и записи тестовых данных в клиентах подсистем — согласуются с каждой командой |
| `qa-ci` | Конфиденциальный, client credentials | Запуск «Smoke» из пайплайна | `qa-system`: `qa-ci` |
| `qa-tracker-reader` | Конфиденциальный, client credentials | Чтение «Ошибок» и комментариев Task Tracker (Q-09) | Роль чтения в клиенте Task Tracker — выдаёт команда Task Tracker |
| Клиент Reports | Существующий, заявка Reports | Чтение `/api/v1/reports/*` | `qa-system`: `qa-reports-reader` |
| QA System как клиент справочников и Planning System | Сервисная учётная запись `qa-system` | Чтение `employees`, `org_units`, `release-context` | `reference-reader` у Reference Manager, `qa.read` у Planning System |

Секреты конфиденциальных клиентов передаются через хранилище секретов окружения, не в репозиторий.
