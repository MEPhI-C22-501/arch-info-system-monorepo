# 080 — User Stories: тестировщик

> Формат — см. [состав документов](documents-composition.md), документ 080.
> Источник — [vision, разделы 4 и 5](vision.md#4-основные-процессы). Актор H-02, роль R-02 `qa-tester` из [070](070.role-matrix.md), use cases — [060](060.use-cases.md).

**US-TS-01.** As a тестировщик, I want создать тест-кейс с шагами и ожидаемыми результатами so that проверку можно было повторять на каждом выпуске.
- GWT-1: Given я заполнил название и хотя бы один шаг, When сохраняю кейс, Then создаётся кейс с новым ключом, версией 1 и статусом «Черновик».
- GWT-2: Given название пустое, When сохраняю, Then кейс не создаётся, а ответ указывает поле и причину.
- GWT-3: Given есть активный шаблон, When создаю кейс из шаблона, Then поля и шаги подставлены, и я могу их изменить до сохранения.

*(→ UC-01; FR-TC-01, FR-TC-02, FR-TC-06)*

**US-TS-02.** As a тестировщик, I want видеть историю изменений кейса so that понимать, кто и что в нём поменял.
- GWT-1: Given кейс сохранён трижды, When открываю историю, Then вижу три версии с автором, временем и изменёнными полями.
- GWT-2: Given кейс участвовал в прогоне в версии 2, When я изменил кейс, Then результат прогона по-прежнему показывает шаги версии 2.
- GWT-3: Given я открыл форму и ничего не изменил, When сохраняю, Then новая версия не создаётся.

*(→ UC-01; FR-TC-04, NFR-05)*

**US-TS-03.** As a тестировщик, I want скопировать один или несколько кейсов so that не писать похожие проверки заново.
- GWT-1: Given выбран кейс `TC-RM-02`, When копирую, Then появляется кейс с новым ключом, статусом «Черновик» и ссылкой на `TC-RM-02`.
- GWT-2: Given выбрано десять кейсов, When копирую, Then создаются десять копий либо ни одной, если хотя бы одна не удалась.

*(→ UC-02; FR-TC-03)*

**US-TS-04.** As a тестировщик, I want менять статус кейса и архивировать ненужные so that в планы попадали только актуальные проверки.
- GWT-1: Given у черновика есть название и шаг с ожидаемым результатом, When отмечаю его готовым, Then статус «Актуален».
- GWT-2: Given у черновика нет шагов, When отмечаю его готовым, Then переход отклонён с пояснением.
- GWT-3: Given кейс в архиве, When QA-лид добавляет кейсы в план фильтром, Then архивный кейс в план не попадает, но остаётся в старых прогонах.
- GWT-4: Given кейс участвовал в прогоне, When пытаюсь удалить его, Then удаление отклонено и предложено архивирование.

*(→ UC-03; FR-TC-01, FR-TC-02)*

**US-TS-05.** As a тестировщик, I want выгружать и загружать кейсы файлом so that править их пакетно и переносить между проектами.
- GWT-1: Given задан фильтр по модулю, When экспортирую в `.xlsx`, Then файл содержит ключи, поля и шаги отобранных кейсов.
- GWT-2: Given я не менял выгруженный файл, When импортирую его, Then отчёт показывает «0 создано, 0 обновлено», данные не изменились.
- GWT-3: Given в файле строка без названия, When загружаю файл, Then ни одна строка не записана, а отчёт указывает строку и поле.

*(→ UC-04; FR-TC-08, NFR-14)*

**US-TS-06.** As a тестировщик, I want прикреплять файлы к кейсу, шагу и результату so that скриншоты и журналы были рядом с проверкой.
- GWT-1: Given кейс мне доступен, When прикрепляю скриншот к шагу, Then файл виден у шага и скачивается по ссылке.
- GWT-2: Given хранилище недоступно, When прикрепляю файл, Then вижу ошибку, а остальные поля формы сохранены.

*(→ UC-05; FR-TC-05, FR-RUN-04)*

**US-TS-07.** As a тестировщик, I want проходить назначенный кейс по шагам и отмечать результат so that провал был зафиксирован с точностью до шага.
- GWT-1: Given прогон выполняется и кейс назначен мне, When отмечаю все шаги пройденными, Then результат кейса «Пройден», сохранены время начала, окончания и длительность.
- GWT-2: Given шаг 3 дал расхождение, When отмечаю его проваленным и записываю фактический результат, Then результат кейса «Провален» с указанием шага 3.
- GWT-3: Given прогон завершён, When пытаюсь изменить результат, Then изменение отклонено.

*(→ UC-10; FR-RUN-03, FR-RUN-04, FR-RUN-06, NFR-05)*

**US-TS-08.** As a тестировщик, I want менять статус сразу у группы кейсов прогона so that не отмечать по одному всё, что блокирует недоступный сервис.
- GWT-1: Given выбраны двенадцать кейсов, When ставлю «Заблокирован» с комментарием «Keycloak недоступен», Then статус и комментарий записаны у всех двенадцати.
- GWT-2: Given среди выбранных есть кейс, назначенный другому тестировщику, When применяю изменение, Then операция отклонена целиком с указанием кейса.

*(→ UC-11; FR-RUN-05)*

**US-TS-09.** As a тестировщик, I want чтобы при провале дефект заводился сам so that не переписывать упавший кейс в баг вручную.
- GWT-1: Given по кейсу нет незакрытого дефекта, When шаг 3 провален, Then создаётся дефект `NEW` с заголовком «[ключ кейса] Шаг 3: …», шагами 1–3, ожидаемым результатом шага 3, фактическим результатом, серьёзностью и приоритетом кейса, окружением и ссылкой на прогон.
- GWT-2: Given по кейсу уже есть незакрытый автодефект, When кейс провален в новом прогоне, Then новый дефект не создаётся, а к существующему добавлены ссылка на прогон и комментарий.
- GWT-3: Given дефект создан автоматически, When открываю его, Then могу изменить серьёзность и приоритет, и изменение попадает в историю.

*(→ UC-15; FR-DEF-02, FR-DEF-03, FR-DEF-04)*

**US-TS-10.** As a тестировщик, I want завести дефект вручную из кейса, шага или прогона so that зафиксировать проблему, найденную вне шагов.
- GWT-1: Given я открыл результат кейса, When создаю дефект, Then связи с кейсом, версией, прогоном и окружением подставлены.
- GWT-2: Given заголовок или фактический результат пусты, When сохраняю, Then дефект не создан, поля указаны в ответе.

*(→ UC-16; FR-DEF-01, FR-DEF-04)*

**US-TS-11.** As a тестировщик, I want перепроверить исправление и закрыть или переоткрыть дефект so that статус отражал реальное состояние стенда.
- GWT-1: Given дефект `FIXED` и сборка на стенде, When отмечаю «Ready for Test», Then статус `READY_FOR_TEST`, запись в истории создана.
- GWT-2: Given дефект `READY_FOR_TEST`, When связанный кейс пройден в повторном прогоне, Then дефект `CLOSED`.
- GWT-3: Given дефект `READY_FOR_TEST`, When связанный кейс провален, Then дефект `REOPENED`, счётчик переоткрытий увеличен.
- GWT-4: Given дефект `NEW`, When пытаюсь перевести его в `CLOSED`, Then переход отклонён с перечнем допустимых.

*(→ UC-17, UC-14; FR-DEF-05, FR-DEF-07)*
