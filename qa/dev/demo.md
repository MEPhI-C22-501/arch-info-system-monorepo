# Демонстрация QA System за 10 минут

Для показа интерфейса на стенде Compose. Все данные — из `qa/dev/demo-seed`, в БД вручную ничего не вводится.

## Подготовка

```bash
# Чистая БД: сценарий рассчитан на первые номера версий, прогонов и дефектов. Удаляет том qa-db-data.
docker compose -f qa/compose.yaml down -v
docker compose -f qa/compose.yaml up -d --build --wait qa-api qa-frontend
```

Интерфейс — http://127.0.0.1:8091. Если показывать повторно без `down -v`, номера версии, прогона и дефекта будут другими, а прогон «Приёмки стенда» на `dev` может быть ещё незавершён: тогда завершите его кнопкой «Завершить».

## Что не входит в демо

| Что | Сейчас | Веха |
| --- | --- | --- |
| Вход через Keycloak, проверка JWT | Демо-токен `demo-<роль>@<имя>`, выбор роли на экране входа | M4, TECH-09 (И-M2) |
| Исполнитель и автопрогоны, кнопка «Запустить автотесты» | Исполнителя нет, поэтому «Smoke» пуст: запуск отвечает `RUN_EMPTY` | M4, E-04 |
| Автотесты стартового набора | Ни один не написан | M4: TC-RM-01; M5: остальные (E-07) |
| Вердикт приёмки стенда | Точки `/runs/{id}/verdict` нет, карточка показывает только готовый вердикт | M5, E-16 (И-M5) |
| Task Tracker: создание «Ошибки», опрос статусов и приоритета | Запрос остаётся в очереди, дефект в `PENDING`; статусы разработки вручную ставит QA-лид (`TRACKER_SYNC_ENABLED=false`) | M5, E-08 (И-M3) |
| Вложения | Хранилища нет | M5, E-11 (И-M3) |
| Назначение тестировщиков, повторный прогон, массовая смена статуса | Точек API нет или они отмечены `Planned` | M4, E-03 |
| Импорт и экспорт кейсов | Отмечены `Planned` в спецификации | M5, E-12 |
| Выбор релиза из Planning System и сотрудников из Reference Manager | Ссылки вводятся текстом, план помечен «не проверена» | M5, E-14 (И-M3) |
| Экран «Автотесты», расписания, состояние интеграций | Точек API нет | M4–M5, E-04, E-10, E-13 |
